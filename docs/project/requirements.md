# ТЗ и границы

Статус: исходное ТЗ от 2026-11-11 и явно согласованные дополнения пользователя.
Создание плейлистов и их выбор в ЛК добавлены 2026-11-12 (R16).
Админ-панель ошибок фоновых заданий с повтором упавших джоб добавлена
2026-11-13 (R17); реализация отложена.
Поведение YouTube используется как ориентир для них, а не как разрешение
воспроизвести весь продукт. Детали внутри объёма — в документах модулей.

Общий интерфейс повторяет YouTube для ПК и телефонов в рамках этих экранов.
Внешний вид и наблюдаемое поведение — 1 в 1 по согласованным референсам;
простота нашего бэкенда не служит основанием упрощать UI. Явные бизнес-отличия
ТЗ сохраняются. [Критерии соответствия](../frontend/youtube-parity.md).
Тёмная тема — единственная реализуемая сейчас; структура допускает расширение.

## Базовые правила в рамках ТЗ

- Все списки — cursor-пагинация по 20 элементов, подтверждено пользователем
  в [ADR-0059](../decisions/0059-list-cursors-and-channel-order.md).
- Публичность и приватность, доступ только разрешённым зрителям, фильтрация
  выдачи и ограничения комментариев — [Video](../backend/modules/video.md).
- Владелец выдаёт приватный доступ по любому корректному email. Наличие аккаунта
  по этому адресу не раскрывается. Для учебного проекта доверяем адресу из
  регистрации: подтверждение почты не требуется и для приватного просмотра.
  [Правила разрешений](../backend/modules/video.md).
- Лайк и его отмена — там же; подписка и её отмена — [Channel](../backend/modules/channel.md).
- Комментарии ограничены 2000 символами, по умолчанию новые сначала;
  дополнительно сортируются по числу лайков, при равенстве новые выше.
  Вошедший пользователь с доступом может поставить один лайк комментарию
  и снять его. [Comment](../backend/modules/comment.md).
- Главная пока без алгоритма рекомендаций, порядок — по дате добавления.
  Для видео это момент успешного завершения загрузки, даже при поздней публикации.
  Поиск по умолчанию использует тот же порядок; пользователь утвердил сортировки
  по дате создания и изменения и конкретный набор фильтров.
  Каналы ищутся по имени/тегу, плейлисты — по названию. Длительность и особенности
  фильтруют только видео. Все заданные применимые фильтры выполняются одновременно,
  включая сочетания особенностей, например 4K + HDR.
  [Полная спецификация](search.md), [ADR-0013](../decisions/0013-search-filters.md).
- Дата изменения отражает правки владельца, а не просмотры, лайки или фоновую
  обработку. Субтитры поддерживаются только из дорожек загруженного видео;
  [правила подготовки](../backend/video-pipeline.md).
- Пользователь создаёт плейлисты. В настройках видео в ЛК можно выбрать любое
  число своих плейлистов через галочки в выпадающем списке, включая все.
  У плейлиста обязательное название, необязательное описание и один из режимов:
  публичный, по ссылке или приватный (только владельцу). Списка разрешённых
  email у плейлиста нет. [Актуальная видимость](../decisions/0011-playlist-visibility.md).
  Доступ к плейлисту не открывает приватные видео: разрешения на них отдельные.
  Новые видео добавляются в конец, ручная перестановка не предусмотрена.
  [Дополнение R16](../decisions/0010-playlist-creation.md).
- Низкое качество может стать доступно раньше высокого — [конвейер](../backend/video-pipeline.md).
- Дополнение пользователя 2026-11-13 к R08: прямая загрузка в RustFS и глобальная
  физическая дедупликация контента всех аккаунтов по доверенной серверной проверке,
  включая слепки исходников, совместимые готовые результаты и превью.
  Общие готовые результаты хранятся, пока на них ссылается хотя бы один
  пользователь; хешу клиента не доверяем.
  У каждой публикации отдельная медиассылка с проверкой её прав. Слепок содержимого
  дорожек без описательных тегов проверяется до конвертации; подтверждённый дубль
  повторно не кодируется. Выбраны сжатые дорожки без полного декодирования,
  с учётом точного тайминга и значимых параметров. Описательные теги файла
  в постоянных медиа не сохраняются, технические метаданные сохраняются;
  [ADR-0033](../decisions/0033-compressed-content-fingerprints.md).
- Готовые видеоварианты хранятся только в AV1 —
  [ADR-0039](../decisions/0039-av1-encoding.md). Оригинал нужен временно для
  слепка и перекодирования, постоянного архива нет —
  [ADR-0040](../decisions/0040-temporary-originals.md). Он сохраняется до
  завершения всех зависимых работ, включая повторы после ошибок, затем удаляется.
- Каждое качество обрабатывается и хранится отдельно; для низких качеств
  снижается также качество аудио. Очередь заданий постоянная, в PostgreSQL;
  её потеря недопустима. [Согласованные правила](../backend/video-pipeline.md).
- Для 360p аудио сильно сжимается, для 480p — умеренно, с 720p используется
  обычное качественное аудио. Загрузка и просмотр видео без звука разрешены.
- Исходный файл — не более 5 ГБ и 60 минут. Видео ниже 360p принимаются
  без увеличения разрешения и сильно сжимаются с сохранением разборчивости.
  [Правила загрузки](../backend/video-pipeline.md).
- Входные форматы не ограничиваются списком расширений: принимаются файлы
  с видеодорожкой, которые удаётся корректно обработать. При частичном сбое
  готовые качества доступны, при полном — автор видит ошибку, просмотр закрыт.
  [Уточнение от 2026-11-12](../decisions/0008-input-formats-and-failures.md).
- Жалоба запускает рассмотрение, но не скрывает видео автоматически — [Moderation](../backend/modules/moderation.md).
  Причина выбирается из согласованного списка; повторная жалоба того же
  пользователя на видео обновляет существующую запись. Рассмотренная жалоба
  после обновления снова ожидает модерации.

HTTP-контроллеры находятся снаружи бизнес-модулей и обращаются к ним только
через `public`; модули не знают маршрутов эндпоинтов. Техническое исключение:
только явный реестр DI подключает классы провайдеров инфраструктуры по
[ADR-0027](../decisions/0027-explicit-module-providers.md).

## Граница объёма

Не входят: доступ «по ссылке» для самих видео, дизлайки, уведомления, отдельная лента подписок,
история просмотров, персональные рекомендации, Shorts, трансляции, реклама,
монетизация, переписки, Google OAuth, восстановление пароля и другие экраны
или действия сверх таблицы. ЛК пока включает согласованные настройки видео
и работу с плейлистами; остальные разделы студии автора не заданы.
Расположение формы создания и другие детали UI уточняются в ходе разработки;
бизнес-часть Q06 и вопрос независимости разрешений Q14 закрыты.
Ответы на комментарии, реакции кроме лайков, редактирование и удаление также не заданы.

Техническая надёжность, проверка доступа и восстановление фоновой обработки —
часть реализации перечисленных требований, а не новые продуктовые функции.
Расширения добавляются только после прямого запроса пользователя.
