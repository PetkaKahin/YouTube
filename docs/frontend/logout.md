# Подтверждённый выход из аккаунта

F08 — `done` по функциональному профилю Chromium/Firefox. Вход и восстановление
личности описаны в [F06](login.md) и [F07](session.md). Смена доступа
существующих экранов проверена в [F33](access-lifecycle.md).
Внешний вид проверяет пользователь, снимки не выполнялись.

## Подтверждение и неизвестный результат

[useSession.signOut](../../frontend/src/entities/session/model/session.ts)
выполняет POST auth/logout с cookie/CSRF без тела с ID/ролью/паролем.
До окончания запроса changing скрывает личные данные и останавливает private-
плеер. Это ожидание проверки, а не подтверждение успешного выхода.
Повторная команда во время смены сессии не создаёт второго POST.

Нормальный подтверждённый ответ — 204. После него личные запросы отменяются,
данные старой области удаляются, Query личности получает null. Прежний
auth/me или ответ личного списка не возвращает аккаунт. Секрет cookie не
читается JavaScript и не сохраняется в Pinia/localStorage.

При ошибке, разрыве или неожиданном HTTP-статусе дополнительно запрашивается
свежий auth/me, с отменой прежнего запроса личности. Если сервер отвечает 401,
выход подтверждён независимо от потерянного ответа POST. Если сессия действует,
восстанавливается проверенный аккаунт и показана ошибка с явным повтором.
HTTP 200 без завершения серверной сессии не считается успешным выходом.
Если повторная проверка личности тоже не удалась, показана ошибка определения
аккаунта: прежняя роль скрыта, подтверждённый гостевой успех не выдумывается.
Ручной повтор проверки разрешает неизвестное состояние по F07.

## Меню, фокус и просмотр

[AppShell](../../frontend/src/widgets/app-shell/ui/AppShell.vue) и
[StudioShell](../../frontend/src/widgets/studio-shell/ui/StudioShell.vue)
возвращают фокус на доступный гостевой вход после подтверждения. При сохранённой
сессии ошибка выхода видна в повторно открытом меню, фокус — на «Выйти».
Исправлена потеря сообщения в Studio, где смена области закрывала меню.
Поколение маршрута/жизненный цикл оболочки проверяются после await:
поздний успех/отказ не открывает меню и не перемещает фокус другого экрана.

Private-видео при выходе останавливается, старый элемент освобождает источник
и удаляется. После подтверждения обычный API такого видео отвечает гостю 404;
метаданные/старый кэш не показываются. Уже полученные байты не обещаются к отзыву.
Публичное видео остаётся доступным через новый гостевой запрос. Back/Forward
и reload не восстанавливают закрытые списки без нового входа.

## Проверки и повтор

В Docker прошли vue-tsc/Vite build, ESLint/Prettier модели сессии и обеих оболочек,
синтаксис/форматирование [logout.mjs](../../docker/browser/logout.mjs).
Регрессия F07 на итоговом коде также прошла: session.mjs — по **37 проверок**
в Chromium и Firefox.
Chromium и Firefox выполнили по **30 функциональных проверок**:

- Настоящий 204 и гостевой 401 после него; ожидание до API при ещё действующей
  серверной сессии, один POST при повторных командах, очистка прежней области.
- Фокус гостевого входа в обычной оболочке и Studio, видимая ошибка Studio
  после 503 и успешный повтор без закрытых каталога/навигации.
- Обрыв до commit, настоящий CSRF 403, ложный HTTP 200 без обращения к logout
  сервера: сессия проверяется заново, ошибка не выдаётся за выход.
- Обрыв ответа после настоящего завершения сессии: auth/me подтверждает гостя;
  отказ logout вместе с отказом auth/me даёт ошибку личности и ручное восстановление.
- Реально воспроизводимое private-видео запускается клавиатурой, при начале
  выхода останавливается/освобождает src; после выхода API 404 и старый кэш пуст.
- Публичное видео остаётся доступным, Back/Forward/reload закрытого каталога
  требуют входа; задержанные auth/me и личные данные не возвращают сессию/cookie.
- Поздний успех сохраняет фокус нового экрана, отказ старой оболочки не открывает
  меню Studio; телефон, Enter, ошибка с фокусом повтора и подтверждённый выход.
- Команды содержат CSRF без credential/ID/role-тела, неожиданных runtime-ошибок нет.

Профиль использует настоящие API/PostgreSQL/Valkey/Nginx/RustFS и отдельную БД.
Прокси вводит задержки, 503, разрывы до/после настоящего commit и ложный HTTP 200;
успешный logout, проверка личности, CSRF и отказы private проверяются API.
Пароли/подписанные URL не печатаются в диагностике. SQL/серверные транзакции
и гонки cookie покрыты B03/B04, все медиамаршруты — B22/F33; новых парсеров,
серверных команд или правил доступа в реализации нет.

Запуск — как [общий браузерный runtime](upload.md#проверки), fixture
`--media --links --moderation --session` без `--upload`, браузер
`/checks/logout.mjs`, Firefox — `--firefox`. Нужны `/checks`, `/work` с manifest
и `/media`; браузеры идут последовательно. Используются скачанные материалы,
новых медиа нет. SIGINT fixture удаляет её объекты/сессии/БД, рабочие данные
не затрагиваются. Изменений бэкенда приложения, контракта и библиотек нет.
Safari/WebKit и физический телефон не квалифицированы; полный make check
остаётся до завершения плана.
