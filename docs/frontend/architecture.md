# FSD и интеграция

Статус: требование FSD и начальная схема размещения. Приложение пока не создано.

## Структура

Планируемые пути от корня репозитория:

```text
frontend/src/
  app/                    # bootstrap, router, providers, глобальные стили
  pages/                  # home, watch, channel, search, upload, login, register, moderation, video-settings
  widgets/                # составные переиспользуемые блоки, когда действительно нужны
  features/               # sign-in, sign-up, upload-video, like-video, subscribe-channel, ...
  entities/               # переиспользуемые модели/представления video, user, channel, comment
  shared/
    api/                  # генерируемый Hey API клиент и общий транспорт
    ui/                   # базовые элементы интерфейса
    config/               # настройки
    lib/                  # конкретные независимые библиотеки
```

Не требуется создавать пустые папки под все элементы схемы.
Сегменты внутри слайса: `ui`, `model`, `api`, `lib` по реальной необходимости.

Зависимости направлены `app → pages → widgets → features → entities → shared`.
Слайсы одного слоя не импортируют друг друга; композиция находится выше.
Внешний импорт идёт через публичный `index.ts`, без deep imports внутрь слайса.
`app` и `shared` организуются по сегментам, без бизнес-слайсов.
Основание — [официальная документация FSD](https://fsd.how/docs/reference/layers/),
проверена 2026-11-11. Исключения к межслайсовым зависимостям не вводятся заранее.

## Состояние и данные

- TanStack Query хранит серверные списки, карточки, комментарии и состояния мутаций.
- Pinia хранит клиентское состояние интерфейса, которое нужно нескольким частям
  приложения. Локальное состояние формы остаётся рядом с формой.
- Поисковая строка и идентификатор текущего видео принадлежат URL. Pinia не
  дублирует данные Query; формы могут иметь отдельный редактируемый черновик.
- Генерация Hey API находится в `shared/api`; специфические query keys и мутации
  размещаются у сценария/сущности, которая ими владеет. Бизнес-правила не прячутся
  в общем транспортном клиенте.
- Серверный контракт — OpenAPI FastAPI. Генерируемые файлы не правятся вручную.
  Ошибки и поля, которых в контракте нет, сначала согласуются с бэкендом.

## Сессия и приватность

Транспорт передаёт cookie по согласованной схеме; секрет сессии не хранится в
Pinia или localStorage. Данные текущего пользователя загружаются с сервера.
Route guard управляет навигацией, API отдельно проверяет каждую операцию.

При выходе, смене пользователя или 401 очищаются персональные запросы и
приостанавливается приватное воспроизведение. При 403/404 убираются недоступные
данные и ссылки. Ключи персонального кэша изолируются по пользователю;
UI не продолжает показывать чужой ранее загруженный приватный контент.

## Видео и интерфейс

Плеер использует HLS и показывает только готовые качества; конкретная библиотека
и её поведение на целевых браузерах — [Q07](../tasks/open-questions.md).
Повторное переключение качества не теряет позицию без необходимости.
Раздача подчиняется [правилам конвейера](../backend/video-pipeline.md).

Цвета, типографика, отступы и размеры задаются токенами тёмной темы.
Добавление другой темы должно менять значения токенов, а не переписывать экраны.
Сам переключатель темы сейчас не нужен. ПК и телефон используют одну бизнес-логику,
адаптация меняет композицию и размеры. Библиотека UI и CSS-подход не утверждены.

Визуальный ориентир «1 в 1» ограничен [ТЗ](../project/requirements.md).
До вёрстки нужны согласованные референсы, размеры и язык интерфейса (Q07).
Наличие элемента на YouTube само по себе не добавляет его функции в проект.
