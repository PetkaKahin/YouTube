# FSD и интеграция

Статус: FSD применяется в первой реализации: `app`, страницы home/search/login/register/
not-found/watch/channel/playlist-link/library/studio-playlists/studio-videos/video-settings/upload/moderation/job-administration, `widgets/app-shell`, `widgets/studio-shell`, `widgets/video-player`, `widgets/discussion`,
`widgets/playlist-contents`, `widgets/video-list`, `widgets/video-upload`, features watch-progress/video-like/subscribe-channel/create-playlist/video-thumbnail/video-playlists/video-permissions/report-video,
сущности session/video/playlist и сегменты shared. Цвет хедера координируется
app через типизированный shared-контракт provide/inject; серверные данные в нём не хранятся.
Реализованные маршруты, состояние и транспорт — [текущая реализация](implementation.md).
Ниже — целевая схема; отсутствующие слайсы создаются по необходимости.

## Структура

Целевые пути от корня репозитория:

```text
frontend/src/
  app/                    # bootstrap, router, providers, глобальные стили
  pages/                  # home, watch, channel, search, upload, login, register, moderation, video-settings
  widgets/                # составные переиспользуемые блоки, когда действительно нужны
  features/               # sign-in, sign-up, upload-video, like-video, subscribe-channel, ...
  entities/               # переиспользуемые модели/представления video, user, channel, comment
  shared/
    api/                  # генерируемый Hey API клиент и общий транспорт
    ui/                   # базовые элементы интерфейса
    config/               # настройки
    lib/                  # конкретные независимые библиотеки
```

Не требуется создавать пустые папки под все элементы схемы.
Сегменты внутри слайса: `ui`, `model`, `api`, `lib` по реальной необходимости.

Зависимости направлены `app → pages → widgets → features → entities → shared`.
Слайсы одного слоя не импортируют друг друга; композиция находится выше.
Внешний импорт идёт через публичный `index.ts`, без deep imports внутрь слайса.
`app` и `shared` организуются по сегментам, без бизнес-слайсов.
Основание — [официальная документация FSD](https://fsd.how/docs/reference/layers/),
проверена 2026-11-11. Исключения к межслайсовым зависимостям не вводятся заранее.

## Состояние и данные

- TanStack Query хранит серверные списки, карточки, комментарии и состояния мутаций.
- Pinia хранит клиентское состояние интерфейса, которое нужно нескольким частям
  приложения. Локальное состояние формы остаётся рядом с формой.
- Поисковая строка и идентификатор текущего видео принадлежат URL. Pinia не
  дублирует данные Query; формы могут иметь отдельный редактируемый черновик.
- Генерация Hey API находится в `shared/api`; специфические query keys и мутации
  размещаются у сценария/сущности, которая ими владеет. Бизнес-правила не прячутся
  в общем транспортном клиенте.
- Серверный контракт — OpenAPI FastAPI. Генерируемые файлы не правятся вручную.
  Ошибки и поля, которых в контракте нет, сначала согласуются с бэкендом.
- Числовые ID в публичных DTO представлены точными строками `Identifier`.
  JSON проходит через адаптер над Hey API; страницы не используют сырой SDK
  или преобразование ID в `number` — [ADR-0064](../decisions/0064-exact-client-identifiers.md).

## Сессия и приватность

Транспорт передаёт cookie по согласованной схеме; секрет сессии не хранится в
Pinia или localStorage. Данные текущего пользователя загружаются с сервера.
Route guard управляет навигацией, API отдельно проверяет каждую операцию.

При выходе, смене пользователя или 401 очищаются персональные запросы и
приостанавливается приватное воспроизведение. При 403/404 убираются недоступные
данные и ссылки. Ключи персонального кэша изолируются по пользователю;
UI не продолжает показывать чужой ранее загруженный приватный контент.
Транспорт ограничивает отправку и обработку 401 областью сессии;
[механизм и проверки F33](access-lifecycle.md).

Страницы Studio владеют персональными выдачами и формой метаданных;
общие блоки превью/плейлистов/email находятся в features и используются
в загрузке и настройках. Навигация по контенту — widget; обычная шапка
использует тот же feature «Создать», передавая открытие формы странице Studio.
Ключи и жизненный цикл — [настройки видео](video-settings.md#код-и-приватность).

Публичные карточки сообщают ошибку превью родительской выдаче, которая
перепроверяет доступ через API. Лента, поиск и списки канала не сохраняют
неактивные снимки; поведение и проверки — [F09](feed.md).

Личные выдачи и каналы sidebar принадлежат Query; ключи, сброс после действий
и защита при смене личности — [R19](library.md).

Дополнения watch: выдача feed и сохранённые плейлисты принадлежат Query;
средний RGB кадра — локальное состояние страницы, без сохранения медиа.
[Жизненный цикл R20](watch-enhancements.md); цвет хедера передаётся через
контракт shared и владельца в app по [R21](watch-refinements.md).

Гостевая позиция просмотра — клиентское состояние Pinia/localStorage.
Серверная позиция аккаунта принадлежит Query; feature watch-progress ограничивает
частоту и сериализует записи через Hey API, без локального кэша в Pinia. Плеер получает подтверждённую начальную позицию
один раз на экземпляр; [восстановление](resume.md) отделено от записи прогресса.
Экземпляры HLS координируются единым владельцем активного предпросмотра и не
попадают в сериализуемое состояние; [R18](hover-preview.md).

## Видео и интерфейс

Плеер использует HLS и показывает только готовые качества. Выбран `hls.js` 1.7.4
с собственными Vue/SCSS-контролами — [ADR-0065](../decisions/0065-hls-client.md);
первая интеграция — [просмотр](watch.md), полная приёмка на целевых браузерах впереди.
Повторное переключение качества не теряет позицию без необходимости.
Раздача подчиняется [правилам конвейера](../backend/video-pipeline.md).

Цвета, типографика, отступы и размеры задаются токенами тёмной темы.
Добавление другой темы должно менять значения токенов, а не переписывать экраны.
Сам переключатель темы сейчас не нужен. ПК и телефон используют одну бизнес-логику,
адаптация меняет композицию и размеры. Приняты собственные Vue-компоненты
без UI-библиотеки и SCSS; [решения и референсы](references.md).

Для Studio достаточно общего сходства по ADR-0068; публичный интерфейс
сохраняет прежние критерии. Внешний вид и наблюдаемое поведение «1 в 1» ограничены [ТЗ](../project/requirements.md).
Критерии — [соответствие YouTube](youtube-parity.md), работы —
[F01–F33](../tasks/frontend/README.md). Простая реализация нашего бэкенда
не отменяет это требование и не разрешает фиктивные действия.
Для публичных экранов до вёрстки нужны согласованные референсы, размеры
и язык интерфейса (Q07); компоновку Studio можно выбирать по ADR-0068.
Наличие элемента на YouTube само по себе не добавляет его функции в проект.
