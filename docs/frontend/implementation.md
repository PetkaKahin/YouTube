## Реализовано

- `widgets/app-shell`: шапка, боковая навигация, поиск, гостевой вход,
  меню аккаунта/выход, «Создать» перед аватаром, мобильная строка поиска
  и нижняя навигация.
  Пункты личных разделов и раскрытие каналов подключены — [R19](library.md).
  Пунктами несуществующих разделов YouTube оболочка не заполняется.
- `pages/login` и `pages/register`: настоящие запросы, состояния отправки,
  ошибки полей, повтор пароля и возврат после входа только внутрь приложения.
  Регистрация не выполняет автоматический вход. Пароль не обрезается,
  не сохраняется в браузерные хранилища и очищается при завершении формы.
- `pages/home`: запрос публичной ленты, карточки, загрузка, пустой результат,
  ошибка и продолжение по cursor. `pages/search`: три типа результатов,
  фильтры и сортировка в URL; сервер остаётся источником результата.
  Заполненная лента и переходы проверены — [профиль F09](feed.md);
  поиск трёх типов, пагинация, история и сбои — [профиль F10](search.md);
  фильтры/сортировки и модалка телефона — [профиль F11](search-filters.md).
- Прокрутка до следующей порции запускает запрос через IntersectionObserver;
  доступна и кнопка продолжения/повтора. Размер порции и cursor определяет API
  по ADR-0059. Пагинация и повтор после ошибки проверены в профильных сценариях
  выдач, поиска, личных разделов и Studio.
- SCSS компилируется Dart Sass `1.108.2`; цвета и основные размеры заданы
  CSS-токенами в `app/styles.scss`. Светлая тема и переключатель не добавлены.
- `make frontend-dev` собирает и запускает Node/Nginx с зависимостями API;
  `make frontend-build` проверяет типы и собирает `frontend/dist` в одноразовом
  контейнере. Полное окружение с worker по-прежнему запускает `make up`.

## API и состояние

Hey API генерируется командой `./docker/run dev exec -T node npm run api:generate`
из OpenAPI работающего бэкенда. Файлы `shared/api/generated` не редактируются
вручную; общий транспорт находится рядом, публичный API — `shared/api/index.ts`.
Браузер обращается к `/api` того же origin, передаёт cookie и берёт CSRF из
`csrftoken` для заголовка `X-CSRFToken`. При первом изменяющем запросе без
CSRF-cookie транспорт сначала получает её безопасным GET текущего аккаунта.
Переменные браузерного окружения и ключи сервисов для этого не нужны.
Формы авторизации вызывают SDK напрямую: локальный pending блокирует форму,
а пароль не попадает в переменные MutationCache. Аккаунтом владеет Query.

TanStack Query хранит текущий аккаунт и результаты запросов. Pinia в
`entities/session` координирует состояние смены сессии и её ревизию, отдельную
копию аккаунта/списков не хранит. Выход подтверждается сервером; отказ сети
оставляет аккаунт и показывает ошибку. Смена личности/выход/401 отменяют старые
запросы и убирают их кэш; ключи выдач включают ревизию сессии.

Исправлена гонка очистки: перед повышением ревизии запоминаются хеши старых
запросов. После отмены удаляются только они; новый запрос текущего экрана не
удаляется асинхронным окончанием старой очистки. Браузерная проверка поиска
после восстановления сессии покрывает этот случай.

Установлен `lossless-json` 4.3.3: JSON-адаптер над сгенерированным SDK получает
ответ как текст и сохраняет числовые ID точными строками до любого преобразования
в `number`. Обратная сериализация ID сохраняет JSON-числа серверного контракта.
UUID, обычный текст и поддерживаемые числовые поля не меняют представление —
[ADR-0064](../decisions/0064-exact-client-identifiers.md). Сессия и выдачи используют
адаптированные DTO, без прежнего отказа от корректных больших int64.

## Первичная проверка основы (историческая)

Ниже сохранены команды и результаты первого этапа. Текущая функциональная
проверка без снимков — [итоговая приёмка](final-acceptance.md).

Требуется запущенный dev. Проверки выполняются в Docker, Chromium управляется
через CDP, Firefox — через WebDriver BiDi. Дополнительный тестовый фреймворк
в приложение не установлен.

Собрать контейнер браузеров и запустить отдельный API в первом терминале:

```bash
docker build --target dev -t youtube-browser-check -f docker/browser/Dockerfile .
docker cp docker/browser/fixture.py youtube-python-1:/tmp/frontend_browser_fixture.py
docker cp docker/browser/stop.py youtube-python-1:/tmp/frontend_browser_stop.py
./docker/run dev exec python python /tmp/frontend_browser_fixture.py
```

Fixture создаёт отдельную БД с миграциями и слушает внутренний порт 8181.
Аккаунты, каналы и плейлисты получают ID больше 2^53 для проверки точности
и смены личности на настоящем API.
Рабочая БД не меняется. Сессии используют отдельный случайный префикс в Valkey.
Остановка Ctrl+C удаляет тестовые сессии и БД; тесты не загружают медиа в RustFS.
При запуске с перенаправлением вывода вместо Ctrl+C используйте
`./docker/run dev exec -T python python /tmp/frontend_browser_stop.py`.
Команда проверяет PID fixture, отправляет SIGINT и ожидает удаления её данных.

Во втором терминале:

```bash
mkdir -p /tmp/youtube-frontend-checks
docker run --rm --network youtube_default --user "$(id -u):$(id -g)" \
  --volume "$PWD/docker/browser:/checks:ro" \
  --volume /tmp/youtube-frontend-checks:/work --workdir /checks \
  youtube-browser-check /checks/check.mjs
docker run --rm --network youtube_default --user "$(id -u):$(id -g)" \
  --volume "$PWD/docker/browser:/checks:ro" \
  --volume /tmp/youtube-frontend-checks:/work --workdir /checks \
  youtube-browser-check /checks/firefox.mjs
```

Chromium через временный HTTP-прокси обращается к отдельному API и dev-фронтенду.
Firefox проверяет гостевые страницы работающего dev через Nginx, без записей
в рабочую БД. Старые check.mjs/firefox.mjs сохраняли снимки во временной папке;
они приведены как историческая проверка первого этапа. Для текущей приёмки
используется shell.mjs по [инструкции](final-acceptance.md), без скриншотов.

Проверены ПК 1920×935 и телефон 390×844. Safari/WebKit, реальный телефон с
экранной клавиатурой ещё не проверены; заполненная лента проверена в [профиле F09](feed.md). Проверки
приватного просмотра добавлены в [этап плеера](watch.md), смены доступа —
в [F33](access-lifecycle.md). Пиксельную приёмку выполняет пользователь.
Открытие мобильного поиска хранится в `#searching`; Back/Forward и обновление
страницы восстанавливают состояние, а закрытие возвращает фокус кнопке поиска.

## Результаты проверок

На текущем этапе в Docker прошли генерация Hey API, vue-tsc/Vite build,
ESLint и Prettier; установка Sass и lossless-json проверила npm-зависимости
без известных уязвимостей. Команды `make frontend-dev` и `make frontend-build`
выполнены успешно. Для вспомогательного Python fixture прошли Ruff и форматирование.
`./docker/run dev exec -T node npm test` проверяет типы тестов и запускает
три сценария JSON-адаптера: границы int64/соседние ID, обратную сериализацию,
отказ от некорректных чисел, сохранение текста/UUID и защиту от prototype pollution.
Все три сценария прошли.
Команда `npm test` также включена в общий `make check`.
В Chromium прошли 42 проверки: реальная регистрация/вход/выход, границы форм,
смена аккаунта, CSRF, безопасный вывод названия плейлиста/поискового текста,
отказ сети, восстановление поиска после загрузки сессии и возврат фокуса.
Реальный API с ID больше 2^53 подтверждает точность личности и ссылки плейлиста;
мобильный поиск проверен с Back/Forward и обновлением страницы.
Firefox выполнил 6 проверок гостевой шапки, переполнения и формы на ПК/телефоне.
При реализации экранов применялись профильные проверки по проектному скиллу;
результат текущего итогового `make check` хранится в
[общей приёмке](final-acceptance.md).
