# Ошибки и повтор фоновых заданий

Статус: T12 реализована. Интерфейс по [контракту бэкенда](../backend/job-administration.md).
Пользователь согласовал таблицу с выбором, три режима повтора, подтверждение
и показ результатов в стиле Studio. Это проектная панель, без референса
внутреннего интерфейса YouTube. Новые бизнес-правила не вводятся.

## История и выбор

`/admin/jobs` доступен из меню аккаунта и навигации Studio только admin.
Гость получает вход с возвратом; user/moderator — отказ до запроса истории.
Сервер отдельно проверяет действующую роль на каждом чтении и записи.

История показывает время, точный ID задания, попытку, этап, причину, состояние
native-задания и безопасную диагностику API. Стек раскрывается через details;
текст не становится HTML, ссылкой или командой. Аргументы, сообщения исключений,
секреты и ключи хранилищ не запрашиваются. Записи остаются в истории после повтора.
Порядок — новые сверху, cursor по 20; фильтров нет. Следующая порция доступна
при прокрутке и по кнопке, ошибки первой/следующей порции различаются.

Галочки выбирают задания по job_id, а не записи ошибок: повторяющиеся записи
одного задания отмечаются вместе и дают один ID. Выбор сохраняется между
порциями, до принятия команды или смены аккаунта/роли. Пустой selected не отправляется.
Есть «Повторить» в строке, «Повторить выбранные» и «Повторить все упавшие».
Последний режим относится ко всем целям сервера, включая незагруженные страницы.
Подтверждение фиксирует выбранный набор. Запрос содержит только ID/режим;
произвольные функции, аргументы, приоритеты и параметры порций UI не задаёт.

## Запрос и результат

На время POST подтверждение и повторная отправка заблокированы. Ошибка сохраняет
выбор и не создаёт фиктивный результат. Только 202 от API закрывает подтверждение,
очищает принятый выбор и сохраняет точный ID намерения в URL `?retry=<id>`.
Его состояние читается GET; reload и прямая ссылка восстанавливают результат.
Ошибка чтения после принятия позволяет повторить GET, без автоматического нового POST.

`pending` означает незавершённую обработку намерения, `submitted` — завершённую
постановку, `cancelled` — отменённый остаток после утраты полномочий.
Счётчики и записи queued/skipped/unavailable берутся из ответа. Постановка не
выдаётся за успешное выполнение джобы. Для queued показан новый ID;
для остальных — причина. Результаты также читаются cursor-порциями по 20.
«Обновить состояние» читает актуальный результат; фиксированный таймер не добавлен.
Историю можно обновить отдельно. Размер порции фоновой подачи остаётся настройкой
бэкенда по Q46, а не элементом формы.

## Код и приватность

[JobAdministrationPage](../../frontend/src/pages/job-administration/ui/JobAdministrationPage.vue)
владеет Query истории и результата. Ключи `job-admin / session.scope / role / resource`
изолируют персональные данные и ID намерения, `gcTime: 0` убирает неактивный кэш.
Локальные Set/команда хранят только незавершённый выбор; MutationCache не получает
ID или поля команды в переменных вызова. Адаптер Hey API сохраняет int64 точно
в URL и числовом JSON, записи используют cookie/CSRF.

401/403/404 очищают служебный интерфейс, выбор, подтверждение и кэш, обновляют
сессию. Смена аккаунта/роли, URL результата или уход отменяют незавершённую запись;
поздний ответ не возвращает прежнюю панель. Прерывание HTTP не обещает отмены
уже принятого намерения — сервер владеет его дальнейшей обработкой.
Роль повторно проверяется и при фоновой подаче; её отмену UI читает с сервера.
На телефоне широкие таблицы прокручиваются внутри контейнеров, кнопки переносятся,
подтверждение помещается в экран и доступно с клавиатуры.

## Проверки и ограничения

В Docker прошли vue-tsc/Vite build, ESLint, Prettier фронтенда и Ruff/Formatter
тестовой fixture. Chromium и Firefox выполнили по **38 профильных проверок**:
все роли, история 20/20/2 и результаты 20/20, точные int64 в URL/JSON,
дедупликация выбора, три режима, ошибка/повтор/двойное нажатие, настоящий dispatcher,
пересечение запросов, отзыв роли/отмена остатка, CSRF, безопасный текст, reload,
прямая ссылка, поздний ответ, потеря сессии, клавиатура и размеры 1920×935, 390×844, 320×568.

Профиль [jobs.mjs](../../docker/browser/jobs.mjs) работает с реальными API,
PostgreSQL, очередью и dispatcher из отдельной fixture. [jobs_seed.py](../../docker/browser/jobs_seed.py)
создаёт в тестовой БД синтетические failed/succeeded/неподдерживаемые native-задания
и 42 записи безопасной истории. Команды POST/проверки роли/dispatcher настоящие;
worker не исполняет тестовые задания. Проверки реального выполнения и восстановления
медиа остаются в серверной приёмке T12. Ошибки HTTP и задержка вводятся прокси.

Запуск — как [профиль загрузки](upload.md#проверки): fixture `--media --jobs`,
в браузере `jobs.mjs`, для Firefox добавить `--firefox`. Запуски последовательные:
они меняют те же намерения и роль. Тестовые команды управления доступны только
отдельному API fixture с `--jobs`; рабочее приложение их не получает.
SIGINT удаляет тестовую БД, медиа и сессии. Safari/WebKit и реальная экранная
клавиатура не проверены. Итоговая приёмка публичного интерфейса остаётся отдельной
работой; полный `make check` здесь не запускается.
