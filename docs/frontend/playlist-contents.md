# Состав плейлиста и прямые ссылки

F20 — `done` по функциональному профилю Chromium/Firefox, с готовым [B28](../backend/playlists.md).
Композиция остаётся на [канале](channel-playlists.md): отдельный экран списка
видео не добавляется. Внешний вид проверяет пользователь; скриншоты не снимаются.

## Данные и жизненный цикл

[PlaylistContents](../../frontend/src/widgets/playlist-contents/ui/PlaylistContents.vue)
читает состав через Query. Ключ включает область сессии, точный ID плейлиста,
ID канала и тег. Запрос берёт контекст из ключа; ответ проверяется на совпадение
плейлиста и канала с открытой шапкой. Карточки сохраняют серверный порядок
включения и дедуплицируются по ID. Порция — 20, есть прокрутка и кнопка продолжения.
Ошибка следующей страницы сохраняет подтверждённый состав и позволяет повторить
cursor. Фоновая ошибка чтения скрывает прежние метаданные/строки и предлагает повтор.

Состав ждёт подтверждённой личности. При каждом новом экземпляре данные
появляются только после свежего ответа (`isFetchedAfterMount`); gcTime 0
удаляет неактивный снимок. Отмена незавершённого чтения и удаление после ухода
выполняются Query. Отдельная отложенная очистка по ключу больше не нужна:
она могла затронуть быстро открытый новый экземпляр по тому же адресу.
Поздний ответ не меняет другой плейлист, закрытый состав или новую личность.

При отказе доступа скрываются название, описание, карточки и прежний заголовок
вкладки. Удаляется именно экземпляр недоступного запроса; наблюдатель может
создать пустой отключённый Query без прежних данных. Родитель не отправляет
запрос отключённого каталога с пустым контекстом после отказа состава.
Повторное открытие снова обращается к API. Закрытие состава возвращает
каталог и заголовок канала.

[PlaylistLinkPage](../../frontend/src/pages/playlist-link/ui/PlaylistLinkPage.vue)
разрешает `/playlist?list=<id>` по серверному `channel`, включая пустой плейлист.
Она ждёт проверки сессии, а её ошибку показывает отдельным состоянием с повтором,
без попытки считать пользователя гостем. ID запроса берётся из ключа.
Успешный свежий ответ проверяется на совпадение ID/канала и допустимый тег,
затем `router.replace` открывает состав на канале с сохранением hash. Back
не проходит лишнюю промежуточную страницу. Ошибка разрешения не раскрывает автора;
поздний ответ после ухода не перенаправляет. Неверный/повторный ID отклоняется
до API; допустимый отсутствующий int64 получает обычный отказ.

## Права и порядок

Public/unlisted доступны гостю, private — только владельцу. Приглашение
к видео не разрешает private-плейлист. Права каждого видео независимы:
в public/unlisted не появляются недоступные private, hidden, draft или
неготовые объекты, их названия, превью, placeholders и скрытые счётчики.
Владелец/приглашённый могут видеть разрешённое private-видео в доступном составе;
hidden закрыт и владельцу. При выходе или отзыве email-разрешения карточка
убирается после свежей проверки, сам public/unlisted-плейлист остаётся доступным.

Ошибка превью инициирует чтение актуального состава. Обычный переход ведёт
к `/watch?v=<id>`, где доступ проверяется заново. Знание плейлиста не обходит
отказ JSON/HLS или отозванное приглашение. Пустой доступный состав отличается
от ошибки и отсутствия прав. Название/описание выводятся текстом Vue.

Повторное включение видео даёт новую позицию в конце по серверному правилу,
курсоры не являются снимком истории. Уже загруженная запись может встретиться
повторно при продолжении; UI не дублирует её. Свежая загрузка получает новый
полный порядок. Ручная перестановка не добавляется.

## Проверки и повтор

В Docker прошли vue-tsc/Vite build, ESLint и Prettier затронутых компонентов.
Chromium и Firefox выполнили по **55 функциональных проверок** F20.
Затронутая интеграция канала F18 повторно прошла по **49 проверок** в обоих
браузерах: вкладки, переходы и отказ private-состава сохранили поведение.
[playlist-contents.mjs](../../docker/browser/playlist-contents.mjs) использует
fixture `--media --channel --links`: реальные API/PostgreSQL/Valkey/Nginx/RustFS,
скачанные AV1/AAC/WebVTT-материалы, 41 публичное видео и дополнительное разрешённое
private для владельца/приглашённого. Все три режима и пустые плейлисты существуют
на сервере. Изменение состава/прав выполняется обычным API владельца с Cookie/CSRF.

Профиль проверяет начальную проверку личности, точные int64, авторство и текст,
20/20/конец, ошибку продолжения и повтор, прокрутку, фильтрацию закрытых элементов
и отсутствие запросов их превью/HLS от гостя. Реальное удаление/повторное включение
между страницами проверяет дедупликацию и новый серверный порядок. Проверены
public/unlisted/private и пустые варианты, прямые ссылки, hash/Back/Forward,
гостевой вход с исходным returnTo, владелец/приглашённый, отказ private-плейлиста
приглашённому к видео, выход и отдельный отзыв/возврат email-разрешения.

После отзыва сервер возвращает 404 для private master и превью: ошибка настоящего
изображения заставляет UI убрать карточку из разрешённого плейлиста. Проверены
недоступный private без названия/строк/заголовка, отсутствие прежних данных в Query,
сбой личности и повтор, ошибки разрешения/обновления и повтор, поздние ответы
другого плейлиста, быстрое закрытие/повторное открытие, уход до ответа resolver,
чужой контекст канала, ошибочный DTO, неверные/повторные/отсутствующие ID.
Переход к обычному просмотру после отзыва не открывает private. На ширине телефона
клавиатурой доступны возврат к каталогу и переход к видео.

Прокси вводит задержки, 503 и ошибочный channel_id для проверки клиента;
успешные права/страницы/медиа не подменяются. Искусственные ошибки имеют no-store.
Пароли/cookie и содержимое закрытых объектов в отчёт не записываются.

Запуск — как [профиль загрузки](upload.md#проверки), fixture
`--media --channel --links` вместо `--upload`; браузер playlist-contents.mjs,
для Firefox добавить `--firefox`. Прогоны идут последовательно: оба меняют
только изолированный состав/разрешения, повтор допустим без ручной очистки БД.
SIGINT fixture удаляет её БД, сессии и объекты; рабочие данные не затрагиваются.

Новых библиотек, API-контрактов и изменений бэкенда нет. SQL/транзакции и сбои
постоянного хранилища покрывает B28; здесь проверяется браузерный результат
после отказа HTTP и свежего изменения прав. Новых форм, файловых путей
или внешних назначений нет. Safari/WebKit и физический телефон не проверены;
общий `make check` остаётся до завершения текущего плана.
