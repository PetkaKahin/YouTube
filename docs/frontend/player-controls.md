## Исправление ошибки и повтора

[VideoPlayer](../../frontend/src/widgets/video-player/ui/VideoPlayer.vue) хранит
последнюю подтверждённую позицию и состояние воспроизведения локально в экземпляре.
После ошибки сегмента HLS может уже очистить медиаэлемент, поэтому читать
только currentTime в обработчике отказа недостаточно: оно уже равно нулю.
Кнопка повтора передаёт сохранённую позицию в startPosition hls.js, после новой
загрузки metadata восстанавливает её и паузу/воспроизведение. Это восстановление того же сеанса
плеера. Продолжение нового просмотра из сохранённой позиции дополнительно
подключено по запросу пользователя — [исправление](resume.md).

Очистка источника снимает ready до pause/load. События отказа и размонтированного
плеера не сообщают прогресс, поэтому служебный сброс времени не записывается
как новая позиция. Нормальный финальный прогресс отправляется до остановки.
Служебный просмотр также имеет локальное восстановление, но не создаёт
записи гостя или аккаунта. Готовые качества, HLS и права API этим не меняются.

В регрессии R20 исправлена гонка быстрых команд громкости: после изменения
volume/muted локальное представление синхронизируется сразу, без ожидания
асинхронного volumechange. Последующие ↑/↓ используют текущее значение.
[Проверки интеграции](watch-enhancements.md).

Меню плеера поднято над controls/seek в [дополнении R21](video-reactions.md);
проверяется получение указателя в области их пересечения.

## Профиль проверки

В Docker прошли vue-tsc/Vite build, ESLint и Prettier изменённого плеера.
В Chromium и Firefox прошли по **38 функциональных проверок**.
Непосредственно затронутая интеграция записи прогресса R18 повторно прошла
по **33 проверки** в каждом браузере, включая финальную запись при уходе и
очистку при смене аккаунта.

[player.mjs](../../docker/browser/player.mjs) работает в Docker через реальный
изолированный API/PostgreSQL/Nginx/RustFS, fixture `--media`, готовые скачанные
AV1/AAC-дорожки. Ошибка 410 сегмента и задержка доставки вводятся только
тестовым HTTP-прокси с no-store; успешные metadata/master/варианты/сегменты настоящие.
410 выбран для исчерпания восстановления hls.js без добавления новых таймаутов
или политики повторов в приложение. Запуск — как [профиль загрузки](upload.md#проверки),
браузер `player.mjs`, Firefox — `--firefox`.

Начальная проверка воспроизвела потерю выбранной позиции после отказа.
Регрессия требует освобождённый источник, сохранение позиции гостя и повтор
на том же времени/паузе. Контролы проверяются по фактическому media state:
K/Space, J/L/стрелки/Home/End, громкость/mute, конец и повтор, фокус меню,
fullscreen с настоящим пользовательским событием, buffering и очистка при уходе.
На телефонном размере проверяются запуск/пауза/seek/mute портретного видео
без аудио. Chromium отправляет события touchStart/touchEnd, Firefox использует
настоящую клавиатурную активацию кнопок; физическое касание устройства не проверяется. Проверка не снимает скриншоты
и не сравнивает геометрию.

Также проверен настоящий HLS-отказ после смены public → private отдельной
сессией владельца: старый источник освобождается и метаданные убираются.
Native HLS/Safari и настоящий сенсорный экран этим профилем не подтверждаются.
Файлы/сырой XML/пользовательские шаблоны этим управлением не загружаются;
инъекции медиассылок/права и смена сессии — соседние профили F12/R18 и серверная
раздача. Функции вне ТЗ, зависимости и фоновые задачи не добавляются.
SIGINT fixture удаляет тестовые БД, медиа и сессии, рабочие данные не меняются.
Общие проверки приложения не запускаются для этой отдельной задачи.
