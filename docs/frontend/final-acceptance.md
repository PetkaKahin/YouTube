# Итоговая функциональная приёмка фронтенда

Статус: проверки завершены, функциональная приёмка пройдена. Общий прогон
неуспешен: открыты ошибки бэкенда и замечание аудита npm, перечисленные ниже.
Запрос пользователя от 2026-11-18.
Объём — [F01–F04](../tasks/frontend/foundation.md), связанные сценарии
реализованных F05–F33 и дополнений R18–R21. Внешний вид проверяет пользователь;
снимки и сравнение оформления браузеров не выполняются.

## Порядок

1. Сверить ранее пройденные профильные проверки экранов и ограничений.
2. Выполнить общий [профиль оболочки](../../docker/browser/shell.mjs) в Docker:
   Chromium/CDP и Firefox/BiDi, ПК и телефон. Проверить прямые/SPA-переходы,
   reload/Back/Forward, клавиатуру, мобильный поиск/навигацию, реальные
   загрузку/ошибку/пустую выдачу, вход/выход и авторские/личные разделы.
3. На итоговом коде один раз запустить `make check`; после найденного сбоя
   повторять только затронутый этап. Сохранить фактический результат.
4. Обновить статусы и устаревшие описания первой реализации, проверить ссылки.

## Окружение

Профиль shell.mjs использует dev, `youtube-browser-check` и отдельную fixture
`--media --links --jobs --session` по [инструкции](upload.md#проверки),
`/work/watch-fixture.json`. Успешные ответы идут через настоящий API/PostgreSQL/
Valkey/RustFS/HLS; тестовый прокси добавляет только 503 и задержку ответа ленты.
Пустой результат получается настоящим поиском отсутствующей строки. Рабочая БД
не меняется; после завершения fixture удаляет тестовые сессии/БД/медиа.

После запуска fixture/gateway с `/tmp/frontend-preview-results:/work`:

```bash
docker run --rm --network youtube_default --user "$(id -u):$(id -g)" \
  --volume "$PWD/docker/browser:/checks:ro" \
  --volume /tmp/frontend-preview-results:/work \
  --volume /tmp/frontend-media:/media:ro --workdir /checks \
  youtube-browser-check /checks/shell.mjs
```

Для Firefox добавить `--firefox`. Chromium использует реальные touch-события,
Firefox — клавиатуру/клики при мобильном viewport. Это не тест физического
устройства. Остановка fixture и удаление gateway — по той же инструкции.

## Ограничения

Ранее пройденные профильные проверки не заменяют общую приёмку связей, но не
повторяются без новой причины. Safari/native HLS и физический телефон с экранной
клавиатурой не квалифицированы. Эмуляция viewport/касаний не подтверждает их.
Публикация и отдельный этап деплоя T11 не входят в текущую работу фронтенда.

переходы и direct/reload/Back/Forward, поиск с клавиатуры, реальные пустой
результат и 503/задержка/повтор, точные ID плейлиста, просмотр/освобождение

## Открытое замечание зависимостей

Аудит npm получен 2026-11-18: GHSA-fc5q-39xc-vjpf/CVE-2026-112366,
ReDoS при обработке повторяющихся extglob. Это одна прямая уязвимость
picomatch и её влияние на дерево из 17 пакетов, а не 17 независимых CVE.
Установлена 4.0.7; npm registry подтверждает latest=4.0.7, а
[первичный advisory](https://github.com/advisories/GHSA-fc5q-39xc-vjpf)
указывает affected <=4.0.7 и отсутствие исправленной версии. Обновление
advisory датировано 2026-11-17, поэтому прежние чистые аудиты этому не противоречат.

Автоисправление npm предлагает major-откаты Vite/vue-router/vue-tsc и других
инструментов; они не применялись. Свой патч/fork, исключение advisory или
подавление проверки не добавлялись. Исходники приложения не принимают glob
от пользователя и не вызывают picomatch; это ограничивает найденную поверхность
использования, но не означает устранение уязвимости всей цепочки инструментов.
Нужен исправленный совместимый релиз и повторный аудит/затронутые проверки.
До этого npm audit и полный `make check` остаются неуспешными.
Поэтому F01–F33 закрыты по функциональным профилям, а T09/T10 в общем плане
сохраняют `in_progress` до устранения перечисленных замечаний качества.
Нереализованных согласованных экранов за этим статусом нет.
