# Свои видео и настройки Studio

F26–F28 реализованы: [задачи и приёмка](../tasks/frontend/creator.md).
Стиль Studio — общее сходство по [ADR-0068](../decisions/0068-studio-visual-scope-and-video-options.md).
Публичный собственный канал сохраняет тот же интерфейс, что чужой.

## Вход и списки

Меню аккаунта → «YouTube Studio», `/studio` и пункт «Контент» открывают
`/studio/content/videos`. Вкладки контента переключают видео и плейлисты.
Внутри видео «Опубликованные» использует GET `/api/v1/videos/mine`,
«Черновики» — тот же метод с `publication=draft`; выбор хранится в URL.
Контракт, права и порядок — [свои видео владельца](../backend/own-videos.md).

Обе выдачи включают свои private, скрытые и неготовые видео; таблица показывает
название/описание, доступ, состояние, даты создания/изменения и переход к настройкам.
Превью запрашивается у API текущего видео; до готовности или при отказе остаётся
нейтральная иконка. Счётчики просмотров и другие отсутствующие поля не имитируются.
«Смотреть» доступно для опубликованного, принятого, готового/частично готового
видео без модерационного скрытия; право просмотра повторно проверяет сервер.

Новые идут первыми по `created_at DESC, id DESC`. Изменение настроек не меняет
порядок. Для каждого раздела свой cursor по 20, ID дедуплицируются; есть
автопродолжение и кнопка. Широкая таблица на телефоне прокручивается внутри
контейнера. Загрузка, пустой результат и отказ API имеют отдельные состояния.
Гость получает вход с возвратом; личная выдача до авторизации не запрашивается.

## Редактирование

Название в таблице ведёт на `/studio/video/<id>/edit`. Страница получает
GET settings только для текущего владельца; корректный ID в URL не даёт права
доступа. Чужие сведения не подставляются до ответа. Доступны название,
описание, public/private и существующие блоки [превью, плейлистов и email](video-options.md).
У этих блоков собственное подтверждение сохранения; «Сохранить» относится
к общим метаданным. Выбор public сохраняет ранее выданные email-разрешения.

PUT settings отправляется лишь при изменении нормализованного названия,
описания или видимости. Название — 1–100 Unicode-символов после trim,
описание — до 5000; NUL и одиночные суррогаты отклоняются. Превышение длины
не обрезается, ошибка возвращает фокус к полю. На время записи форма заблокирована,
повторная отправка не создаёт второй запрос. Ошибка сохраняет черновик;
только успешный ответ обновляет Query и показывает подтверждение.
«Отменить изменения» возвращает последние подтверждённые метаданные.

Редактирование не публикует черновик, не меняет `added_at` и не снимает
модерационное скрытие. Для черновика есть переход к существующей загрузке
и публикации; из окна загрузки — ссылка на настройки. Закрытие загрузки
возвращает к своим видео, для созданного черновика — в раздел черновиков.

## «Создать» в шапке

У авторизованного пользователя обычная шапка содержит «Создать» непосредственно
перед аватаром. То же меню доступно в Studio: «Добавить видео» открывает модалку
загрузки, «Создать плейлист» — существующую форму в Studio. Переход передаёт
одноразовый query `create=playlist`, удаляемый после открытия, поэтому reload
не открывает форму повторно. Гость кнопку не видит. На телефоне остаются иконка
и доступное имя «Создать». Escape закрывает меню и возвращает фокус.

## Код и приватность

- [Список](../../frontend/src/pages/studio-videos/ui/StudioVideosPage.vue) владеет
  InfiniteQuery с ключом `studio-videos / session.scope / publication`.
- [Настройки](../../frontend/src/pages/video-settings/ui/VideoSettingsPage.vue)
  используют `video-settings / session.scope / id`; подтверждённые данные
  принадлежат Query, незавершённая правка — локальной форме.
- Внешние импорты проходят публичные API FSD; Hey API сгенерирован из актуального
  OpenAPI. ID остаются точными строками и после 2^53. Записи используют cookie/CSRF.
- При уходе/смене видео/аккаунта запросы отменяются, прежние приватные Query
  удаляются. 401/403/404 убирают недоступные сведения. Поздний ответ не возвращает
  старый UI. MutationCache не получает поля формы. Метаданные выводятся текстом.

## Проверки

В Docker прошли vue-tsc/Vite build, ESLint и Prettier затронутых файлов.
[settings.mjs](../../docker/browser/settings.mjs) выполнил **46 проверок Chromium
и 45 Firefox** с реальными изолированными API/PostgreSQL/Nginx/RustFS/worker:
20/20/1 в обоих разделах, URL/reload, точные int64, public/private/hidden/draft,
границы Unicode, пустая правка, ошибка/повтор/двойное сохранение, безопасный текст,
сохранность дат/порядка/модерации, чужой аккаунт, потеря сессии, очистка кэша,
поздний ответ, CSRF, меню и модалки, клавиатура и размеры 1920×935, 390×844, 320×568.


Запуск — как [профиль загрузки](upload.md#проверки), заменив `upload.mjs`
на `settings.mjs`; Firefox запускается с `--firefox`. Эти два запуска идут
последовательно: они редактируют одни и те же видео fixture. Профиль использует
`--media --upload --links`; подписи хранилища не попадают в результаты.
Рабочие данные не меняются, завершение fixture по SIGINT удаляет её БД/медиа/сессии.
Safari/WebKit и реальная экранная клавиатура не проверены. Общая приёмка
приложения и `make check` остаются после завершения остальных задач фронтенда.
