# Смена пользователя и утрата доступа

F33 — `done` для существующих экранов по функциональным профилям Chromium/Firefox.
Личные выдачи [R19](library.md) дополнительно прошли свою приёмку смены
аккаунта, поздних ответов и отзыва доступа. Внешний вид проверяет пользователь; снимки не выполнялись.

## Область запросов

[Транспорт](../../frontend/src/shared/api/transport.ts) запоминает текущую область
сессии в WeakMap для каждого Request. Это локальная ревизия, не credential;
новых заголовков или API-параметров нет. После асинхронного получения CSRF и
непосредственно перед fetch повторно проверяются область и AbortSignal.
Старая операция не отправляет команду с cookie нового аккаунта, даже если
смена произошла в следующем асинхронном перехватчике.

Поздний 401 старой области или отменённого запроса не завершает новую сессию.
Настоящий 401 текущей области по-прежнему запускает expire; auth/login и
проверка auth/me сохраняют собственную обработку. Страницы и операции отдельно
проверяют актуальность результатов; транспорт не объявляет любой поздний 200
ошибкой. Сгенерированный SDK вручную не менялся.

В [модели сессии](../../frontend/src/entities/session/model/session.ts) changing
объединяет вход/выход и синхронно выставляемое ожидание expire. Личные блоки
скрываются сразу после обнаружения потери сессии, пока Query отменяет старые
запросы и удаляет их кэш. Повторные expire объединяются. Прежняя личность не
попадает в интерфейс следующего аккаунта.

## Доступ к содержимому

Сервер остаётся источником прав. После обнаружения 403/404 старые метаданные,
карточки и источники плеера убираются. Приватный просмотр останавливается при
отзыве разрешения, смене аккаунта и потере сессии; скрытое модерацией видео
недоступно в обычном просмотре также владельцу/администратору. Доступ к личному
плейлисту не предоставляет доступ к каждому его видео.

Очистка, отмена, ключи Query и проверки поздних результатов в отдельных экранах
проверены также в профилях [F12](watch-access.md), [F13](player-controls.md),
[F20](playlist-contents.md), [F21](studio.md), [F22–F25](upload.md),
[F26–F28](video-options.md), [F30–F32](moderation.md).
Новый профиль дополняет эти проверки, а не повторяет все медиамаршруты.

## Проверки и повтор

В Docker прошли vue-tsc/Vite build, ESLint/Prettier изменённых файлов приложения,
синтаксис/формат браузерного профиля и Ruff/формат тестового seed.
[access-lifecycle.mjs](../../docker/browser/access-lifecycle.mjs) выполнил
по **25 проверок** в Chromium и Firefox:

- Старый запрос без AbortSignal получает настоящий 401 после ротации сессии;
  новый аккаунт сохраняется. Текущий 401 после удаления сессии действительно
  очищает личность и персональный интерфейс.
- Смена аккаунта во время CSRF-bootstrap и после обычного перехватчика перед
  fetch не отправляет старый PUT лайка от имени нового зрителя.
- Реальный отзыв private-разрешения останавливает играющий плеер, освобождает
  src и убирает название/кэш. Возврат через историю браузера не показывает
  прежний снимок до свежего отказа; повторное разрешение восстанавливает просмотр.
- Смена владельца на другого пользователя закрывает private-плейлист и прямой
  редактор. Утрата доступа к ресурсу не завершает действующую сессию.
- Перевод public-видео в private удаляет карточку после ошибки свежего превью;
  прямой URL закрыт, восстановление public требует нового чтения.
- Настоящее решение модератора hide прекращает обычный просмотр; служебная
  роль не обходит отказ обычного API. Телефон проверяет отзыв и смену аккаунта.
- Нет неожиданных ошибок выполнения или восстановления старой области Query.

Регрессия на итоговом транспорте прошла в обоих браузерах: [вход](login.md) —
по **37**, [сессия](session.md) — по **37**, [выход](logout.md) — по **30** проверок.

Запуск — как [общий runtime](upload.md#проверки), fixture
`--media --links --moderation --session` без `--upload`, браузер
`/checks/access-lifecycle.mjs`, Firefox — `--firefox`. Нужны `/checks`, `/work`
с manifest и `/media`; браузеры идут последовательно. Используются настоящие
API/PostgreSQL/Valkey/Nginx/RustFS, отдельная БД и скачанные материалы.
Прокси задерживает запрос перед API с исходной cookie; успешные ответы,
401 и права доступа не подменяются. Диагностика не печатает cookie/пароли/URL медиа.

Тестовый restore_silent восстанавливает ровно одно видео fixture между прогонами;
это не команда снятия модерации в приложении. SIGINT fixture удаляет тестовые
объекты/сессии/БД; рабочие данные не меняются. Бэкенд приложения, контракт,
библиотеки и серверные правила доступа в F33 не менялись.

Уже загруженные байты невозможно отозвать задним числом; клиент реагирует на
обнаруженный отказ, а каждый новый медиазапрос проверяет сервер. Все серверные
медиамаршруты квалифицируются B22. Safari/WebKit и физический телефон не проверены.
Полный make check остаётся до завершения всего плана, включая F01–F04.
