# Предпросмотр карточек и прогресс просмотра

R18 — `done` по функциональному профилю: предпросмотр, позиции гостя и аккаунта,
исправление меню.
Позиция аккаунта подключена к [контракту бэкенда](watch-progress-backend-request.md);
исправление API состава плейлиста проверено, полоса отображается.
Правила подтверждены пользователем 2026-11-17. Референсы —
[10-44](../../frontend/Reference/clipboard_2026-11-17_10-44.png) и
[10-45](../../frontend/Reference/clipboard_2026-11-17_10-45.png).
Внешний вид проверяет пользователь; скриншоты в новом профиле не снимаются.

## Предпросмотр

Видеокарточки главной, поиска, канала и состава плейлиста используют общий
[VideoHoverPreview](../../frontend/src/entities/video/ui/VideoHoverPreview.vue).
Наведение мыши или клавиатурный фокус запускает предпросмотр после короткой
задержки; короткое прохождение курсора и touch-pointer не загружают поток.
По умолчанию звук выключен. Работают переключение звука, субтитры при наличии
дорожек и перемотка. Контролы не вложены в ссылку и не открывают просмотр при
перемотке; нажатие на область видео ведёт на обычную страницу просмотра.

Метаданные читаются лениво через существующий Hey API с Query по ревизии сессии
и точному ID. hls.js импортируется только после получения метаданных; выбирается
самый низкий доступный вариант по разрешению/битрейту, автоматическое повышение
качества отключено, буфер ограничен. Без MSE используется нативный HLS: его
адаптивное качество определяет браузер. Новых API для предпросмотра не требуется.
Вложенные URI ограничены same-origin HLS-префиксом текущего видео.

Одновременно воспроизводится один предпросмотр. Уход указателя/фокуса, скрытие
вкладки, уход карточки из viewport, смена сессии/видео и размонтирование прекращают
поток, освобождают источник и отменяют чтение. Поздний ответ/импорт не запускает
уничтоженный плеер. Неудачный предпросмотр оставляет обычную карточку доступной;
401/403/404 запускают существующую перепроверку доступа к выдаче. При загрузке
или ошибке определения сессии предпросмотр не запускается. Модераторская роль не даёт предпросмотру служебного исключения.

## Позиция основного просмотра

[VideoPlayer](../../frontend/src/widgets/video-player/ui/VideoPlayer.vue) сообщает
позицию основного плеера с захваченной ревизией зрителя. Служебный плеер и
предпросмотр не создают таких записей. По запросу пользователя 2026-11-18
основной просмотр продолжает с сохранённого места — [восстановление](resume.md).

[Гостевое хранилище](../../frontend/src/entities/video/model/guest-progress.ts)
использует Pinia для клиентской координации и localStorage только для числовой
позиции по ID видео. Заголовки, имена, email, сессия и URL туда не записываются.
Регулярное сохранение ограничено одним разом в пять секунд; пауза, завершённая
перемотка, конец, скрытие страницы и уход сохраняют последнюю доступную позицию.
Перемотка назад заменяет предыдущую позицию, максимум не вычисляется.
Сбой/недоступность localStorage не мешает воспроизведению. Повреждённые значения
игнорируются. Изменение гостевого хранилища в другой вкладке обновляет чтение.

Гостевая карточка показывает полосу по позиции и длительности. После входа
гостевые значения скрыты и не сливаются с аккаунтом. Захваченная ревизия не
позволяет финальному событию старого авторизованного плеера записать позицию
в гостевое хранилище при выходе. Неопределённая сессия и ошибка `/auth/me`
не считаются гостем: полоса скрыта и запись запрещена до подтверждения зрителя.
Отказ доступа к текущему видео убирает его гостевую запись.

[watch-progress](../../frontend/src/features/watch-progress/model/progress.ts)
записывает позицию аккаунта через сгенерированный Hey API, Cookie/CSRF и точный
int64 в пути PUT. Серверный результат принадлежит Query: обновляется существующий
обычный просмотр, незавершённые чтения выдач текущей ревизии отменяются,
затем выдачи помечаются устаревшими и активные загружаются заново, включая
личные выдачи [R19](library.md). Это закрывает
гонку между финальной записью при уходе и первой загрузкой ленты. Лента, поиск,
канал и состав плейлиста читают `watch_progress` из серверной карточки; отдельных чтений
на каждое видео и локального заменителя аккаунта нет.

Регулярная запись ограничена пятью секундами. Пауза, перемотка, конец и уход
сохраняют позицию сразу; неизменная позиция не отправляется повторно. Один запрос
выполняется, ещё одна последняя позиция может ожидать: промежуточные заменяются.
Это сохраняет порядок при медленном сервере и перемотке назад. Уход страницы
использует `keepalive`, оставаясь best effort; продолжения с позиции нет.
503/сеть/CSRF не мешают плееру: рядом появляется сообщение с повтором. Успех
снимает ошибку; 404 убирает недоступное видео. Ошибка старого видео не переносится
на новое. Смена сессии отменяет запрос и очищает ожидающую запись. Поздний ответ
не обновляет кэш другого зрителя и не переносит позицию гостю.

## Меню аккаунта

Ссылки Studio/«Модерация»/«Ошибки заданий» теперь получают одинаковые стили
отдельной строки меню: прежде правило охватывало только ссылку Studio,
а служебные ссылки оставались inline. Роли и маршруты не изменялись.

## Проверки и ограничения

В Docker прошли vue-tsc/Vite build, ESLint и Prettier затронутого фронтенда.
Chromium выполнил **31**, Firefox **30 функциональных проверок**; разница —
точечная регрессия строк меню только в Chromium. Hey API повторно сгенерирован
из рабочего OpenAPI с PUT progress и watch_progress.

Профиль [preview.mjs](../../docker/browser/preview.mjs) использует реальные
изолированные API/PostgreSQL/Nginx/RustFS, декодирует HLS и проверяет выбор
минимального разрешения по настоящему master. Покрыты перемотка, mute/CC,
единственный активный поток, остановка/поздний ответ, 503/отзыв доступа,
сохранение/перезагрузка/перемотка назад гостя, отсутствие записи от предпросмотра,
изоляция при входе/выходе, ошибка определения аккаунта и использование
опубликованного progress API. После F12 связанный сценарий требует отказ
просмотра при неизвестном зрителе; [актуальная проверка доступа](watch-access.md).
Точечная регрессия отдельных строк меню выполняется только в Chromium;
сверка внешнего вида по браузерам и скриншоты не добавлены.

Профиль [progress.mjs](../../docker/browser/progress.mjs) прошёл **33 проверки
в Chromium и 33 в Firefox**, включая исправленный состав плейлиста. Проверяет запись через
реальные Cookie/CSRF/PostgreSQL, точный bigint и только числовую позицию в body,
отсутствие гостевого слияния и записи от превью, throttling/дедупликацию,
перемотку назад/ноль, одну запись в полёте с последней ожидающей позицией,
финальное сохранение при SPA-переходе и свежую полосу ленты, поиска и канала.
Другая HTTP-сессия меняет позицию, затем браузер читает её; новый вход с пустым
localStorage также видит серверную позицию. Другой аккаунт не наследует её.
Проверены 503 и ручной повтор, настоящий отказ CSRF с сохранением плеера,
приватный просмотр приглашённого, настоящий отзыв доступа/404, отмена очереди
при выходе и отсутствие позднего персонального кэша. Для каждого запуска
создаётся отдельный дополнительный зритель в изолированной БД.

Регрессия API непустого плейлиста исправлена бэкендом: реальный ответ 200
и совпадение полосы с серверной позицией проверены. Профиль требует 200,
ветка принятия известного 500 удалена.
Проверки инъекций, пределов чисел, транзакций и N+1 самого API —
[бэкенд R18](../backend/watch-progress.md); новых файлов/фоновых задач этот фронт не создаёт.

Запуск — как [профиль загрузки](upload.md#проверки): fixture `--media --jobs`
нужна для тестового admin, браузер `preview.mjs`, Firefox — `--firefox`.
Для `progress.mjs` fixture запускается с `--media --links --jobs` (без `--channel`).
Запуски последовательные, поскольку изменяют видимость одного видео.
SIGINT удаляет тестовую БД, медиа и сессии. Работающий бэкенд и рабочая БД
не меняются. Safari/native HLS и реальная экранная клавиатура не проверены.
Полный набор приложения не запускался: это профиль R18.
