# Страница просмотра: лента, подсветка и сохранение R20

R20 — `done` по функциональным профилям Chromium/Firefox.
Уточнения хедера/dropdown/автозапуска выполняются в [R21](watch-refinements.md);
ниже описано исходное состояние R20 и его профиль.
[Задача](../tasks/frontend/watch-enhancements.md),
[референс 10-12](../../frontend/Reference/clipboard_2026-11-18_10-12.png),
[согласованный API](watch-save-backend-request.md).
Внешний вид проверяет пользователь; скриншоты и сравнение оформления не выполняются.

## Правая лента

[WatchPage](../../frontend/src/pages/watch/ui/WatchPage.vue) получает обычный GET
feed через Hey API и точный адаптер ID. Используется прежний VideoList в режиме
горизонтальных карточек: автор, дата, длительность, hover-preview и полоса позиции.
Порядок/состав — как на главной, без алгоритма рекомендаций и фиктивных фильтров.
Cursor по 20, автопродолжение и кнопка/повтор. Ошибка ленты не разрушает плеер;
ошибка начального/фонового чтения скрывает прежние карточки. Ошибка продолжения
оставляет подтверждённые страницы. Ошибка превью перепроверяет доступ к выдаче.
На телефоне список переносится под основную область.

Ключ `['watch-feed', scope, video_id]`, gcTime=0. Выдача включается после проверки
просмотра и не сохраняет старый снимок при смене зрителя/видео. При отказе доступа
основной области лента убирается вместе с метаданными. Принятый прогресс основного
плеера инвалидирует также watch-feed. Это публичная лента с обычными правами,
не служебное исключение модератора.

## Подсветка

[useAmbientLight](../../frontend/src/widgets/video-player/model/ambient.ts) получает
среднее RGB из уже декодированного элемента video: уменьшение до 32×18, чтение
576 пикселей, не чаще двух раз в секунду при проигрывании. Кадр очищается сразу
после вычисления; canvas вне DOM, без toDataURL/Blob/файлов/storage/Query.
В родителя передаётся только RGB с исходными video_id/scope. WatchPage проверяет
актуальность перед применением CSS-переменной к декоративному градиенту.

В регрессии устранена гонка быстрых ↑/↓ громкости: локальное volume/muted
обновляется сразу после команды, не ждёт media-события. [Контролы](player-controls.md).

Второго video/HLS/потока, запроса изображения и изменения прогресса от подсветки
нет. Пауза/конец читают один финальный кадр; перемотка/возврат вкладки — свежий
кадр. Скрытая вкладка, уход плеера из viewport, reduced-motion, отказ/очистка
источника и размонтирование прекращают выборку и снимают подсветку. Декодер
к исходному потоку не подключается повторно. Ошибка canvas/security отключает
только подсветку; воспроизведение остаётся работоспособным. Таймер, observer,
слушатели и буфер очищаются при уходе.

Подсветка opt-in только для обычного watch; служебный плеер и hover-preview её
не запускают. Уже полученные байты видео не обещаются к отзыву задним числом;
после обнаружения отказа старый цвет/метаданные не остаются.

## Закладка и создание

Модальная панель исходного R20 заменена выпадающим списком в [R21](watch-refinements.md);
описание ниже сохраняет интеграционные правила API и исторический профиль R20.

[SaveVideo](../../frontend/src/features/save-video/ui/SaveVideo.vue) показывает
кнопку закладки рядом с лайком/жалобой. Гость идёт на вход с returnTo без
автоматического сохранения после входа. Вошедший открывает окно «Выберите
плейлист»; строка показывает название, видимость и подтверждённый выбор.
Строки переключаются сразу по PUT одной пары, окно остаётся открытым. Пока
запись ожидается, повторные нажатия не отправляют второй запрос; выбор не
становится успешным до ответа. Сбой оставляет подтверждённое состояние и явный
повтор действием. Список загружается по 20 с продолжением/повтором.

GET saved-playlists использует Query `['saved-playlists', scope, video_id]`,
gcTime=0. Общий saved берётся с сервера и учитывает selected за первой страницей.
PUT обновляет одну строку и saved у всех загруженных страниц; других выбранных
плейлистов полный набор не заменяет. Перед записью отменяется старое чтение.
После подтверждения инвалидируются затронутые представления плейлистов текущего
зрителя. Неактивные данные не используются для обхода свежей проверки прав.

Страница компонует создание через слот SaveVideo, без межслайсового импорта
features. Прежний CreatePlaylist получил необязательный videoId: тело POST
тогда содержит точное JSON-число video_id и создаёт плейлист с включением одной
транзакцией. Обычные формы Studio не передают его и сохраняют прежнее поведение.
После 201 вложенная форма закрывается, список обновляется с новым selected;
окно выбора остаётся открытым. Ошибка создания не выдаётся за сохранение,
автоматического повтора POST при неопределённом исходе нет.

Нативные dialog, Escape/Tab и возврат фокуса работают также при вложенном
создании. Потеря сессии/доступа, смена видео/зрителя и уход закрывают формы,
отменяют ожидание; поздний ответ не выбирает плейлист другого видео/аккаунта.
401 использует общий expire, 403 csrf_failed показывает ошибку без ложной
утраты просмотра, настоящий 403/404 убирает недоступную область. Имена/ошибки
выводятся как текст. Право просмотра не выводится из закладки/видимости плейлиста.

## Проверки и повтор

Профиль [watch-enhancements.mjs](../../docker/browser/watch-enhancements.mjs)
использует настоящие API/PostgreSQL/Valkey/Nginx/RustFS и скачанные HLS-материалы
в изолированной fixture `--media --links --channel --session` без `--upload`.
Запуск — по [общей инструкции](upload.md#проверки), браузер
`/checks/watch-enhancements.mjs`, Firefox — `--firefox`, последовательно.
Прокси вводит 503, задержки и снятие CSRF-заголовка; успешные данные/права/CSRF
проверяет реальный сервер. Отказ canvas и скрытая вкладка вводятся браузерным
сценарием для проверки деградации, не выдаются за отказ видеодекодера.
Кадры/пароли/cookie не печатаются. SIGINT fixture удаляет её медиа/сессии/БД;
рабочие данные не меняются.
Для регрессии профили идут последовательно. F21 studio-playlists создаёт свои
контрольные плейлисты; F13 player меняет метаданные ролика, поэтому F12
watch-access запускается на свежей `--media --links` fixture. R18 progress
требует свою чистую компактную `--media --links --jobs` fixture, без позиций
предыдущего профиля доступа; большая --channel-выдача
не подходит его фиксированной карточке первой страницы. Профили не меняют
успешные API-ответы для обхода этой подготовки данных.


Chromium прошёл **42**, Firefox — **41 функциональную проверку**. Дополнительная
проверка Chromium задаёт реальное prefers-reduced-motion через CDP; в Firefox
API эмуляции не добавлялся. Проверены:

- Правая лента 20/20/1 с точным порядком главной, отказ/повтор независимо
  от плеера; у гостя нет личного GET и автоматического сохранения после входа.
- Выбор 20/20/5, несколько плейлистов, снятие одной пары, общий saved за первой
  страницей и reload, клавиатурное действие/фокус; повторные нажатия во время
  задержанного PUT отправляют одну команду и не показывают ранний успех.
- Настоящие сохранение/снятие, ошибка 503 и явный повтор, ошибка чтения без
  старых вариантов, реальный CSRF 403 без изменения пары.
- Чужое доступное видео, собственный пустой список, отказ создания без пустого
  плейлиста, атомарный POST с включением, возврат из вложенной формы к выбору.
- Позднее чтение при смене видео/аккаунта не переносит saved/чужое название;
  реальный отзыв private закрывает плеер/ленту/подсветку/окно, настоящий 401
  очищает личные варианты и область зрителя.
- Подсветка из декодируемых пикселей, один основной video без DOM canvas,
  пауза без второго потока, перемотка, скрытие/возврат вкладки, canvas SecurityError
  без сбоя плеера; телефон 390/320, Escape/фокус и отсутствие переполнения.
- Неожиданных runtime-ошибок нет. Не снимаются и не сравниваются скриншоты.

Генерация Hey API, vue-tsc/Vite build, ESLint/Prettier затронутого кода прошли
в Docker. Синтаксис/формат браузерного профиля, ссылки документов и
`git diff --check` прошли. Регрессия на итоговом коде в обоих браузерах:
F21 Studio — по **56**, F13 контролы — по **38**, F12 доступ — по **45**,
R18 позиции — по **33** проверки. Результаты относятся к функциональным
сценариям и не заменяют визуальную приёмку пользователем.
Общий make check остаётся до завершения плана F01–F04. Safari/native HLS и физический телефон
этим этапом не квалифицированы. Бэкенд приложения и библиотеки не менялись;
новый серверный контракт пользователь реализовал отдельно.
