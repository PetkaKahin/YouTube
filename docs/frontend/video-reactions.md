# Лайк/дизлайк видео и слой меню плеера

Статус: `done` по функциональному профилю Chromium/Firefox.
[Контракт](dislikes-backend-request.md), [сервер](../backend/video-dislikes.md),
[задача R21](../tasks/frontend/watch-refinements.md). Внешний вид проверяет
пользователь; снимки и сравнение оформления не выполняются.

## Реакции

[VideoLike](../../frontend/src/features/video-like/ui/VideoLike.vue) использует
общее состояние GET like: liked/disliked/can_like/can_dislike/like_count. Hey API
сгенерирован из готового OpenAPI; PUT dislike добавлен в точный JSON-адаптер
shared/api. ID в пути остаётся строкой Identifier, не проходит через number.

Кнопки объединены в капсулу с разделителем и доступны отдельно с клавиатуры.
Публичное число показывается только у лайка; дизлайк имеет название и выбранное
состояние, но не счётчик. Нажатие выбранной кнопки снимает реакцию; установка
другой атомарно заменяет выбор через сервер. Гость переходит ко входу с returnTo,
защищённая операция после входа автоматически не повторяется.

PUT like содержит только liked, PUT dislike — только disliked. Ответ каждой
команды полностью заменяет состояние Query `['video-like', scope, video_id]`.
Один pending блокирует повтор обеих команд, сохраняя фокус и подтверждённый
выбор до ответа. Старое GET перед записью отменяется; возобновлённое чтение
получает реальное состояние сервера. Ошибка не создаёт оптимистичный успех.
CSRF 403 сохраняет доступный плеер и предлагает обновить страницу; обычный
отказ доступа убирает обе реакции и недоступное содержимое.

Подтверждение любой реакции сбрасывает текущую выдачу R19 liked: дизлайк
исключает прежний лайк, возврат к лайку использует новую серверную дату.
Область/ID/контроллер и проверки живого экземпляра сохранены из [F15](video-likes.md).
При уходе небольшая отправленная команда может завершиться для обновления
личного списка того же зрителя; кнопка другого видео не получает её результат
или ошибку. Смена области отменяет запрос; поздний ответ не обновляет нового
зрителя. Никаких локальных копий реакций или паролей в storage/Pinia нет.

## Меню над шкалой времени

В [VideoPlayer](../../frontend/src/widgets/video-player/ui/VideoPlayer.vue)
заданы локальные слои: controls — z-index 1, menu — 3, notice — 4. Корень плеера
сохраняет isolation. Меню настроек/качества/субтитров получает указатель поверх
перекрывающейся полосы времени, включая телефон; выбор пункта не перематывает
видео. Числа не выводят меню за слои оболочки и других страниц.

## Проверки и повтор

Профиль [video-reactions.mjs](../../docker/browser/video-reactions.mjs) использует
изолированные настоящие API/PostgreSQL/Valkey/Nginx/RustFS и скачанные материалы.
Fixture — `--media --links --session` без `--upload`; инструкция
[runtime](upload.md#проверки), браузер `/checks/video-reactions.mjs`,
Firefox — `--firefox`. Браузеры последовательно используют отдельные браузерные
профили. 503, задержки и снятие CSRF-заголовка вводятся прокси; реакции,
транзакции, выбор/счётчик, сессия и права остаются настоящими. Пароли/cookie не
печатаются, скриншоты не делаются. SIGINT удаляет тестовые медиа/сессии/БД.

В dev после генерации нового экспорта потребовалось обновить модульный кэш
Vite перезапуском Node: при отсутствии нового метода в отданном sdk.gen.ts
проверить содержимое dev-ответа и выполнить `./docker/run dev restart node`.
Сгенерированные файлы вручную не исправляются. Это не обход API или подмена ответа.

Chromium и Firefox прошли по **30 функциональных проверок**:

- Гостевой выбор с возвратом и без автоматического PUT после входа; отсутствие
  публичного счётчика дизлайков, настоящий none→dislike→like→dislike→none,
  повторное нажатие лайка/дизлайка, reload подтверждённого выбора.
- Общая блокировка быстрых смешанных нажатий одной командой, прежнее состояние
  до ответа; точный int64 в URL и только целевой bool в теле. Позднее GET не
  перезаписывает полный результат PUT.
- 503 и явный повтор, настоящий CSRF 403 без изменения реакции/потери плеера;
  дизлайк исключает видео из реальной R19 liked. Неожиданного HTML/счётчика нет.
- Позднее чтение после смены видео/аккаунта не переносит выбор; клавиатурный
  Enter сохраняет фокус/aria-pressed; разрешённое private и настоящий отзыв
  убирают реакции/плеер. Реальный 401 проверен через PUT после потери сессии:
  публичный необязательный GET like сам по себе может успешно ответить гостю.
- Меню качества на ПК и телефоне действительно пересекается со шкалой времени:
  elementFromPoint указывает меню, слой выше controls. Выбор качества не меняет
  currentTime. Это проверка доставки нажатий, не визуальное сравнение.
- Телефон 390/320: достижимая кнопка и отсутствие переполнения. Неожиданных
  runtime-ошибок нет.

Регрессия прежнего F15 на итоговом коде — по **36 проверок** обоих браузеров.
Генерация Hey API, vue-tsc/Vite build, ESLint/Prettier затронутого кода,
синтаксис/формат профиля, ссылки документов и git diff --check прошли в Docker.

Safari/native HLS и физический телефон не квалифицированы; полный make check
остаётся до завершения плана F01–F04. Бэкенд приложения и библиотеки не менялись.
