# Превью, плейлисты и доступ к видео

Статус: F27/F28 реализованы в [загрузке Studio](upload.md) и
[общих настройках F26](video-settings.md). Используются одни компоненты
с теми же подтверждениями записи и очисткой при смене ресурса. Критерий сходства Studio —
[ADR-0068](../decisions/0068-studio-visual-scope-and-video-options.md).

## В форме загрузки

«Информация» содержит значок и выбор плейлистов. На шаге «Доступ» при private
показывается «Указать пользователей» с модалкой по референсу. Выбор public
не стирает ранее заданные разрешения. Компоненты остаются смонтированными
при переходе между шагами, поэтому File, выбранные плейлисты и адреса не теряются.

До создания видео «Готово» сохраняет выбор в локальном черновике; UI сообщает,
что он будет применён при сохранении видео. Основное сохранение подтверждает
исходник, применяет параметры и затем публикует. Ошибка параметров оставляет
тот же черновик/исходник и не показывает успешную публикацию. Повтор использует
подтверждённые результаты, продолжая оставшиеся изменения.

После публикации «Назад» возвращает к информации: можно изменить значок,
состав плейлистов и доступ по email. Общие метаданные опубликованного видео
внутри загрузки остаются только для чтения; ссылка «Сведения о видео»
ведёт на отдельную страницу F26, где их можно изменить.

## Значок

[VideoThumbnail](../../frontend/src/features/video-thumbnail/ui/VideoThumbnail.vue)
читает GET thumbnail, показывает только готовые candidates и текущий серверный
WebP. До готовности кадров выбор из видео недоступен с пояснением.
Выбор кадра подтверждает PUT `{slot}`. Менять режимы кадр/своё изображение можно
повторно; UI отражает возвращённый сервером выбор.

Своё изображение передаётся по подписанному плану через `/uploads/`, XHR и complete.
Лимит 10 МиБ проверяется до начала, 40 мегапикселей/декодирование/анимацию проверяет
сервер. Локального списка расширений и предварительного доверенного декодирования
нет. До подтверждения complete не показывается успешный приём. Далее отдельно
ожидается подготовка нормализованного изображения; ошибка сохраняет старый выбор.
Промежуточные `running`/`preparing` не считаются завершением. Подписанные URL
и File не помещаются в QueryCache или хранилища браузера.

Изображения принимаются только с same-origin пути thumbnail текущего видео.
Ключ изображения меняется при изменении серверного выбора/состояния, чтобы новый
результат по тому же current_url не оставался старой DOM-картинкой.

## Плейлисты

Здесь описан выбор своих видео в Studio. Сохранение доступного видео любого
автора из обычного watch подключено отдельно в [R20](watch-enhancements.md):
немедленный PUT одной пары и создание с включением, без замены полного набора.


[VideoPlaylists](../../frontend/src/features/video-playlists/ui/VideoPlaylists.vue)
открывает множественный выбор своих плейлистов всех трёх режимов. Это элемент
привязки видео; общая таблица Studio сохраняет свой обычный вид без галочек.
Пустой список позволяет создать плейлист через существующую модалку F21;
после создания выбор обновляется. Все действия доступны с клавиатуры и на телефоне.

GET mine используется до создания видео, GET video/playlists — после создания.
Порции по 20, есть продолжение. Поскольку PUT заменяет полный набор, перед ним
читаются все оставшиеся страницы. Явные изменения накладываются на полный
серверный набор; неоткрытые ранее selected-плейлисты не теряются. Ответ с полным
playlist_ids подтверждает выбор и обновляет Query. Можно выбрать все или ни одного,
без новой отдельной функции «выбрать все» и без ограничения одной страницей.

## Разрешения по email

[VideoPermissions](../../frontend/src/features/video-permissions/ui/VideoPermissions.vue)
показывает введённые адреса и пагинированный серверный список. Поле принимает
несколько адресов через запятую/новую строку; синтаксис окончательно проверяет API.
Нет запросов поиска аккаунта, имени, аватара или статуса регистрации адресата.
Нормализацию подтверждает сервер; зарегистрированный и неизвестный адрес
получают одинаковый интерфейс. Email передаётся в body, а не URL.

GET permissions — cursor по 20; PUT меняет один адрес и возвращает актуальную
первую страницу. UI фиксирует каждый подтверждённый результат. Если пакет
изменений оборвался, уже подтверждённые адреса не отправляются повторно,
оставшиеся сохраняются для явного повтора. Отмена модалки отбрасывает её текущие
несохранённые изменения. Удалить ещё не принятый сервером адрес можно локально.

## Состояние и жизненный цикл

Подтверждённые данные принадлежат Query, форма хранит только незавершённые правки.
Ключи включают ревизию сессии и точный Identifier видео, `gcTime: 0`.
[useOperations](../../frontend/src/shared/lib/operations.ts) отменяет записи
и проверяет идентичность ресурса после await. При уходе/смене видео/аккаунта
File/черновики/модалки очищаются; поздняя запись не восстанавливает старый UI.
401/403/404 прекращают работу и убирают недоступные данные родительской формы.
CSRF и точные int64 проходят существующий адаптер Hey API; бэкенд не менялся.

[StudioDialog](../../frontend/src/shared/ui/StudioDialog.vue) использует native
dialog и Teleport: вложенные формы не отправляют родительскую публикацию.
Escape, Tab и возврат фокуса работают в отдельных и вложенных модалках.
Создание плейлиста из выбора переиспользует компактный режим F21.

## Проверки и ограничения

В Docker прошли vue-tsc/Vite build, ESLint и Prettier затронутых файлов.
Chromium и Firefox выполнили по **30 профильных проверок** новых блоков:
отложенное сохранение, создание плейлиста из выбора, 20/20/2, сохранение
выбранного элемента за первой страницей, все/ни одного, прямые точные int64,
зарегистрированный/неизвестный email, 20/3 адресов и отзыв, ошибки записи,
реальная передача PNG и выбор третьего кадра, телефон, поздний ответ,
CSRF и очистка адресов/превью при потере сессии.
Непосредственно затронутый сценарий загрузки дополнительно прошёл по
**41 проверке в обоих браузерах**. Общие тесты других экранов и `make check`
не запускались: фронтенд ещё не завершён.

Профиль — [creator.mjs](../../docker/browser/creator.mjs), запускается на тех же
изолированных API/worker/Nginx, что [проверка загрузки](upload.md#проверки):
в команде браузера заменить `upload.mjs` на `creator.mjs`, для Firefox добавить
`--firefox`. Рабочие данные не меняются; после SIGINT fixture удаляет тестовые
медиа, сессии и БД. Все адреса/плейлисты создаются в отдельной БД.

Тестовое изображение — готовый PNG W3C, скачанный через
[download-media.mjs](../../docker/browser/download-media.mjs); URL, размер и SHA-256
закреплены в [media-sources.json](../../docker/browser/media-sources.json).
В продукт изображение не добавляется; новые картинки/видео не генерировались.
Ошибки сохранения вводятся только тестовым HTTP-прокси.

Общий вход F26 и интеграцию блоков в настройках проверяет
[профиль настроек](video-settings.md#проверки). Safari/WebKit и реальная
экранная клавиатура не проверены.
У Studio теперь достаточно общего визуального сходства, точная пиксельная
приёмка и отдельный мобильный референс не являются её текущим требованием.
