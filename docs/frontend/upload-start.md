# Начало загрузки и метаданные видео

F22 — `done` по функциональному профилю Chromium/Firefox: выбор файла, сведения, явный доступ
и создание черновика B08. [Общий сценарий загрузки](upload.md) описывает
последующие передачу, обработку и публикацию F23–F25. Компоновка согласована
в [ADR-0067](../decisions/0067-studio-video-upload.md), для Studio достаточно
общего сходства по ADR-0068. Внешний вид проверяет пользователь, снимки не делаются.

## Поведение формы

[UploadPage](../../frontend/src/pages/upload/ui/UploadPage.vue) ждёт проверки
аккаунта. Гость получает вход с исходным returnTo, без формы файла и чтения
настроек видео. Ошибка определения личности имеет собственный повтор и не
выдаётся за гостя. Подтверждённый аккаунт открывает существующую Studio-модалку
[VideoUpload](../../frontend/src/widgets/video-upload/ui/VideoUpload.vue).

Выбирается один исходник кнопкой или перетаскиванием. Локальная проверка —
ненулевой размер до 5 000 000 000 байт. Фильтра расширений/MIME нет: допустимость
содержимого/длительности определяет сервер. Форма объясняет 5 ГБ/60 минут,
возможность видео без звука и ниже 360p. Выбор остаётся локальным и не создаёт
черновик автоматически. До создания можно выбрать другой файл.

Название берётся из имени без последнего расширения, без обрезания. Название
1–100 Unicode-символов после trim и описание до 5000 сохраняются в форме
целиком; пробелы вместо названия, NUL/одиночные суррогаты и превышение блокируют
сохранение. Ошибка объясняется у поля с возвратом фокуса. При редактировании
снимается старая полевая ошибка. Пользовательский текст выводится Vue,
включая заголовок диалога и имя файла, без HTML-вставки.

После «Информации» открыт «Доступ»: public/private без исходного выбора;
unlisted-видео не добавляется. Back сохраняет поля. «Сохранить» блокирует
повторную команду до первого await и отправляет только title/description/visibility.
Созданный объект остаётся draft и закрыт для обычного просмотра даже при public.
Точный ID попадает в URL; до подтверждения публикации/готовности нет надписи
«Сохранено» или обещания просмотра. Закрытие после создания возвращает в
каталог черновиков. File/черновик формы при уходе очищаются, принятый сервером
черновик не удаляется.

## Запросы, ошибки и контекст

Query настроек включает ID владельца вместе с областью сессии и ID видео.
Функции чтения настроек/обработки берут ID из своего ключа; ответ настроек
проверяется с исходными ID/владельцем, не с изменившимся URL. Начало мутации
проверяет живой экземпляр и поколение перед запросом. Переход между шагами
и сохранение повторно проверяют поколение/область после асинхронной валидации.
Поздний ответ не заполняет другую форму, не меняет её ID и не перенаправляет
другой аккаунт. Фокус обращается только к элементам своего диалога.

Ошибки создания сохраняют тот же File, текст и выбор доступа. Полевая ошибка
возвращает «Информацию», разблокирует её и фокусирует поле. Ошибка CSRF предлагает
обновить страницу и не закрывает разрешённую форму. 401 очищает сессию;
обычный отказ доступа закрывает сведения и останавливает операции. Передача
не объявляет создание/публикацию успешными при отказе контрольного запроса.
Автоматического повтора POST создания нет: у B08 нет ключа идемпотентности.
Отмена ответа не означает откат уже созданного черновика.

Query удаляет неактивные настройки/обработку с gcTime 0; отложенной очистки,
которая могла затронуть быстро открытый новый экземпляр, нет. Восстановление
`?video=<id>` получает свежие сведения владельца. Если File утрачен и исходник
ещё не принят, предлагается отдельная новая загрузка, а не склейка с другим
файлом. Чужой, неверный или повторный ID не раскрывает поля/источник.

## Проверки и повтор

В Docker прошли vue-tsc/Vite build, ESLint и Prettier изменённого виджета.
Chromium и Firefox выполнили по **47 функциональных проверок**.
[upload-start.mjs](../../docker/browser/upload-start.mjs) использует fixture
`--media --links --upload`: настоящие API/PostgreSQL/Valkey/Nginx/RustFS и worker,
а для каждого запуска — два новых аккаунта. Входной portrait.mp4 скачан и закреплён
в [каталоге материалов](../../docker/browser/media-sources.json), новые медиа
не генерируются. Успешные ответы не подменяются; создаются настоящие черновики.

Для отделения F22 прокси приостанавливает запрос начала передачи до его отправки
в API. Это позволяет проверить реальный draft без загрузки частей/публикации;
при уходе удержание снимается с отказом, автоматический успех не подставляется.
В конце профиля ограничение отключается: скачанный исходник с неизвестным
расширением реально передаётся, принимается, публикуется и получает доступный
готовый вариант через сервер. Это регрессия затронутой интеграции, а не полная
приёмка ошибок F23–F25 или утверждение о новом кодировании дедуплицированного файла.
Передача впоследствии проверена отдельным [профилем F23](upload-transfer.md).

Профиль проверяет личность/гостя/returnTo, отсутствие расширительного фильтра,
нулевой/превышающий/граничный размер по File-метаданным, несколько файлов при drop,
необрезанное имя без расширения/длинное имя, смену исходника до draft,
100/101 и 5000/5001 Unicode-символов, пробелы и одиночный суррогат, обязательный
public/private, Back, 503/422/CSRF с сохранением формы и без записи,
несколько submit с одной командой, точные ID и подтверждённый draft без просмотра.

Проверены private, буквальный HTML-подобный текст, чужие права, закрытие в
каталог черновиков, поздние настройки другого ID, ошибка чтения/повтор,
новая загрузка после утраты File, принятый draft после отмены ответа,
смена аккаунта до ответа, 401 без запрещённой записи, ошибка/повтор личности,
неверный/повторный/чужой restore-ID. На ширине телефона — клавиатура шагов,
удержание фокуса и Escape с возвратом к «Создать».

503, полевая 422 и задержки вводятся прокси; настоящие CSRF 403/401, метаданные,
права, передача и готовность проверяются API. Проверки 5 ГБ используют подмену
File.size без выделения/передачи 5 ГБ; пустой/несколько файлов — только локальные
негативные примеры. Серверная проверка фактической длительности, содержимого
и большого исходника относится к B09/B10 и F23. Подписанные URL, File и текст
пользователя не печатаются в отчёт. File/подписанные URL не хранятся в Query,
локальные поля не передаются в variables MutationCache; подтверждённые серверные
сведения принадлежат Query и удаляются при уходе/смене личности.

Запуск — как [общий профиль загрузки](upload.md#проверки), fixture
`--media --links --upload`, браузер upload-start.mjs; Firefox — `--firefox`.
Браузерному контейнеру нужны mounts `/checks`, `/work` с manifest и `/media`
с portrait.mp4. Профили идут последовательно. SIGINT fixture завершает worker
и удаляет её БД, сессии и медиа, рабочие данные не затрагиваются.

Новых библиотек, контрактов и изменений бэкенда нет. Серверные транзакции,
SQL и сбои хранилищ покрывает B08/B09; здесь проверяются браузерные последствия
отказа HTTP и отсутствие запрещённой записи. Передача проверена в F23;
обработка проверена отдельным [профилем F24](upload-processing.md);
подтверждение публикации — [профилем F25](upload-publication.md).
Safari/WebKit и физический телефон не квалифицированы;
общий `make check` остаётся до завершения плана.
