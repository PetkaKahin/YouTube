# Чтение и публикация комментариев

F16 — `done` по функциональному профилю Chromium/Firefox. Обсуждение использует готовый
[B30](../backend/comments.md). Лайки комментариев проверены отдельным
[профилем F17](comment-likes.md); в F16 они служат серверными данными популярной сортировки.
Внешний вид проверяет пользователь, скриншоты не снимаются.

## Поведение

[VideoDiscussion](../../frontend/src/widgets/discussion/ui/VideoDiscussion.vue)
показывает записи из Query. Ключ включает область сессии, точный ID видео
и сортировку; функция запроса получает ID/порядок из этого ключа. Новые идут
первыми по умолчанию. Популярные сортируются сервером по всему обсуждению,
при равенстве лайков более новые выше. На клиенте загруженные страницы не
переставляются вместо серверного порядка.

Порция — 20 по [ADR-0059](../decisions/0059-list-cursors-and-channel-order.md).
Следующая загружается при прокрутке либо кнопкой. Ошибка продолжения сохраняет
подтверждённые страницы и позволяет повторить тот же cursor. Повторившийся ID
не создаёт вторую строку. Начальная/фоновая ошибка чтения показывает отказ
с повтором, а не пустой успешный список или старые записи.

Гость читает обсуждение и переходит ко входу с возвратом. Вход не публикует
комментарий автоматически. Форма отправляет только `text`; автора определяет
сервер. Имя берётся из регистрации, а текст выводится интерполяцией Vue.
Непустой ввод до 2000 Unicode-символов включительно сохраняется целиком;
пробельный/NUL-ввод и превышение блокируют отправку без обрезания. Серверная
валидация остаётся обязательной, в том числе для недопустимых суррогатов.

Ожидание блокирует повторную отправку и изменение отправляемого текста.
201 очищает форму, сообщает о публикации и заново запрашивает список в выбранном
порядке. Ошибка сохраняет черновик и возвращает фокус; сообщение сервера не
вставляется как HTML. `csrf_failed` просит обновить страницу и не закрывает
разрешённое обсуждение. Enter в textarea создаёт перенос; отправка доступна
клавиатурой через кнопку. Есть отмена черновика и раскрытие длинной записи.

## Доступ и поздние ответы

Неактивные снимки комментариев не сохраняются (`gcTime: 0`), включая прежнюю
сортировку. При уходе отменяется чтение/ожидающий ответ публикации; черновик
очищается. Запись фиксирует ID и область сессии до запроса. Поздние успех/ошибка
не очищают форму другого видео или аккаунта и не показывают там сообщение
от предыдущей операции. Отмена ответа не обещает откат уже принятой записи:
при возврате загружаются реальные комментарии сервера.

401 проходит через общую очистку сессии. Отказ доступа закрывает обсуждение,
очищает черновик/сообщения и отменяет/удаляет запросы всех его сортировок,
после чего экран перепроверяет метаданные. Владелец private сохраняет плеер,
но обсуждение недоступно и ему, и приглашённому. При возврате public старые
записи восстанавливаются только после свежего ответа списка. Само получение
публичных метаданных не восстанавливает их при отказе чтения комментариев.

## Проверка и повтор

В Docker прошли vue-tsc/Vite build, ESLint и Prettier изменённого компонента.
Chromium и Firefox выполнили по **52 функциональных проверки**.
После изменения общей координации запросов в F17 профиль повторно прошёл
по 52 проверки в обоих браузерах; форма, страницы и очистка доступа сохранены.

[comments.mjs](../../docker/browser/comments.mjs) использует изолированную
fixture `--media`, реальные API/PostgreSQL/Valkey/Nginx/RustFS и скачанные медиа.
Публикации и подготовка порядка выполняются штатным API: создаются 43 записи,
у двух старых устанавливаются одинаковые лайки разными зрителями. Проверяется
популярность за пределами первой страницы и порядок при равенстве счётчиков.
Успешные ответы не подменяются; прокси вводит задержки, 503 и отсутствие CSRF.
Смена видимости, отказ 401/404 и валидация 422 настоящие.

Профиль покрывает пустое public-обсуждение, гостя/вход, пробелы/NUL/2001,
границу 2000 с emoji, точный многострочный текст, имя другого автора, HTML/SQL
как текст, раскрытие/сворачивание, отмену, двойную отправку и проверку БД после
ошибок. Проверяются 20/40/конец, продолжение после ошибки, прокрутка, сортировки
и их поздние ответы, начальная/фоновая ошибка чтения, переход/выход/смена
аккаунта до ответа, очистка снимков, private/public и отсутствие старых записей
до подтверждения сервера. На ширине телефона — меню со стрелками/Escape,
возврат фокуса, Enter в textarea и публикация клавиатурой. Фокус вкладки
Chromium включается через CDP только для теста, поведение приложения не меняется.

Запуск fixture/gateway — как в [профиле загрузки](upload.md#проверки),
с `--media` вместо `--upload`. Вместо upload.mjs выполнить comments.mjs,
для Firefox добавить `--firefox`. Браузеры запускаются последовательно:
Chromium использует public, Firefox — silent из той же fixture. Дополнительные
записи получают уникальный префикс, повтор не требует удаления комментариев
через отсутствующий в ТЗ интерфейс. Пароли/cookie и содержимое комментариев
в диагностический отчёт не записываются. Остановка fixture через SIGINT
удаляет её БД/сессии/объекты, рабочие данные не затрагиваются.

Новых библиотек, контрактов или изменений бэкенда нет. Контроль SQL-транзакций,
сбой PostgreSQL и серверные ограничения покрывает B30, этот профиль проверяет
браузерный сценарий и неизменность данных после отказов HTTP. Комментарий не
принимает пути, команды или сетевые назначения; соответствующих обработчиков
на фронте нет. Общий `make check` остаётся до конца плана. Safari/WebKit,
настоящий телефон и его экранная клавиатура этим профилем не проверены.
