# Заполненная главная и перепроверка карточек

Функциональные сценарии заполненной F09 проверены. Визуальную приёмку
пользователь выполняет сам; весь поиск F10/F11 остаётся отдельной работой.
Этот профиль не объявляет весь поиск завершённым. Контракт — [лента B23](../backend/feed.md).

## Лента

Главная получает только готовые публичные опубликованные видео. Порядок
`added_at DESC, id DESC` и cursor по 20 определяет сервер; карточки дедуплицируются
по точному Identifier. Есть прокрутка/кнопка продолжения. Ошибка следующей
порции сохраняет ранее загруженные карточки и предлагает повтор; первая ошибка,
ожидание и пустая выдача имеют отдельные состояния.

Превью и название открывают `/watch?v=<id>`, подпись автора и аватар — канал
по тегу. Карточка показывает длительность, автора и дату без вымышленных метрик.
Пропорции превью стабильны; изображение вписывается с сохранением исходного
соотношения сторон. Название остаётся полным в ссылке/данных, визуально занимает
до двух строк. На ПК сетка содержит три колонки при 1920×935, на телефоне — одну.

## Изменение доступа после загрузки

Найден и исправлен случай: видео становится приватным после получения ленты,
превью отказывает в доступе, но его прежнее название остаётся в карточке.
[VideoCard](../../frontend/src/entities/video/ui/VideoCard.vue) теперь сообщает
`previewError`. Родитель перепроверяет соответствующую выдачу через API;
исчезнувшее из неё видео удаляется вместе с метаданными. Если API подтверждает
публичность, остаётся нейтральная иконка вместо неработающего изображения:
отсутствие превью не означает неготовое видео.

[useVideoCardVerification](../../frontend/src/entities/video/model/verify.ts)
объединяет одновременные ошибки в последовательную перепроверку, учитывает
новые сигналы во время чтения и прекращает работу после ухода/ошибки API.
Начальная перепроверка отменяет прежнее чтение, чтобы не принять снимок,
полученный до отказа превью. Повторный запрос того же сломанного изображения
не создаётся автоматически, поэтому нет цикла «ошибка картинки → запрос».

Общий обработчик подключён на главной, в поиске и на канале. Данные ленты,
поиска и публичных списков канала имеют `gcTime: 0`: после ухода старые снимки
не используются для краткого показа уже закрытых метаданных при возвращении.
Это не серверный push: изменение обнаруживается при следующей проверке API,
ошибке превью или возврате на страницу. Смена сессии сохраняет общую очистку
персонального кэша. HTML-подобный текст не исполняется.

## Проверки

В Docker прошли vue-tsc/Vite build, ESLint и Prettier затронутых файлов.
Chromium и Firefox выполнили по **20 функциональных проверок**. Новый профиль
не снимает скриншоты и не проверяет геометрию: внешний вид принимает пользователь.

Профиль [feed.mjs](../../docker/browser/feed.mjs) работает с реальными
изолированными API/PostgreSQL/Nginx/RustFS и готовыми скачанными материалами.
Проверяет 41 видео, порядок API, 20/20/1 и точные int64, отсутствие
private/hidden/draft/pending, превью, переходы к просмотру/каналу,
ошибки первой/следующей порции и повтор, loading/empty, длинное название,
навигацию на ПК/телефоне и реальную смену public → private. Отдельные проверки подтверждают
удаление отозванных карточек из поиска и канала, без принятия всего F10/F18 заново.
Back проверяется через SPA-переход с задержанным ответом: старые карточки до
нового ответа не показываются. Владелец меняет тестовое видео отдельной HTTP-сессией,
не подменяя сессию зрителя. Состояния 503/empty/задержки вводятся только прокси.

Запуск — как [профиль загрузки](upload.md#проверки), fixture `--media --channel`,
браузер `feed.mjs`, Firefox — `--firefox`. Профили запускаются последовательно,
так как меняют видимость одних видео. SIGINT удаляет тестовые медиа/БД/сессии;
рабочие данные не меняются. Safari/WebKit и реальная экранная клавиатура
не проверены. Полные проверки приложения здесь не запускаются.

Видеокарточки дополнены [предпросмотром R18](hover-preview.md): отдельный
плеер с перемоткой, полосой позиции гостя и серверной полосой аккаунта.
Это не меняет порядок ленты и правила публичного доступа.
