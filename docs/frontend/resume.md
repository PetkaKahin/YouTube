# Продолжение просмотра с сохранённой позиции

Статус: `done` по функциональному профилю и регрессии плеера/записи.
Пользователь явно запросил 2026-11-18 продолжать видео с последнего времени;
прежнее исключение автопродолжения в R18/R21 для этого запроса отменено.
[Основной прогресс](hover-preview.md), [API позиции](watch-progress-backend-request.md).

## Источник и восстановление

WatchPage передаёт VideoPlayer initialPosition: для аккаунта — position_seconds
из подтверждённого GET видео, для гостя — число из прежнего Pinia/localStorage.
Гостевая позиция не подставляется аккаунту; источник зависит от подтверждённого
зрителя. Поля/методы бэкенда и SDK не меняются.

Плеер фиксирует исходную позицию один раз на экземпляр video_id/scope.
Собственные PUT прогресса, обновления API/другой вкладки и refetch метаданных не
перематывают уже открытый плеер. Новое открытие/reload получает актуальную позицию.
Смена видео/аккаунта пересоздаёт экземпляр и использует только свою позицию.

После получения настоящей media metadata позиция ограничивается duration и
применяется к currentTime. До завершения исходного seek закрыты запуск/перемотка
и отправка прогресса; начальный нулевой кадр скрыт под состоянием загрузки.
Автозапуск R21 ждёт восстановления, ручной запуск при запрете браузера также
начинается с сохранённого времени. Нет второй копии видео или запроса медиа
другого ресурса. HLS сначала получает metadata обычным способом, затем seek
выбирает нужный участок; недостоверное localStorage не задаёт произвольную
начальную границу загрузки HLS до проверки реальной длительности.

Нет позиции/невалидное значение — начало с нуля. Число за длительностью
ограничивается настоящим концом; play на завершённом элементе не вызывается
автоматически, чтобы браузер не начал повтор с нуля. Явный ручной повтор остаётся
доступным. Порог «почти досмотрено» и произвольное округление к началу не вводятся.

## Запись и ошибки

Начальная загрузка/seek для восстановления не активируют запись прогресса:
простое открытие паузы не создаёт PUT и не меняет дату истории. После настоящего
play или пользовательской перемотки прежнее сохранение (регулярно/пауза/уход)
работает, включая перемотку назад. Защита восстановления действует также при
пересборке качеств и повторе потока после ошибки, не записывает служебный сброс
currentTime=0. Предпросмотр и служебный плеер не используют личную начальную
позицию и не создают account-прогресс.

Отказ прав по-прежнему убирает плеер/метаданные; знание позиции не обходит доступ.
Поздние media-события старого экземпляра не записывают позицию нового зрителя.
При уходе до metadata/seek старая сохранённая позиция остаётся нетронутой.

## Проверки

[resume.mjs](../../docker/browser/resume.mjs) — настоящие API/PostgreSQL/Valkey/
Nginx/RustFS/HLS, отдельная fixture `--media --links --jobs --session` по
[инструкции](upload.md#проверки). Браузер `/checks/resume.mjs`, Firefox — `--firefox`;
режим разрешённого автозапуска — `--autoplay-allow` только в тестовом профиле
браузера. Скачанные материалы, без генерации медиа/скриншотов.

Проверки гостя/аккаунта, reload/SPA, перемотки назад, недостоверной позиции,
смены аккаунта/видео, private/отзыва и разрешённого/запрещённого автозапуска
выполняются последовательно. Прежний progress.mjs проверяет запись/полосы;
player.mjs — восстановление после ошибки/контролы. Профили требуют своих чистых
fixture: не смешивать заранее записанные позиции с ожиданием отсутствия позиции.
Новый профиль прошёл в Chromium и Firefox: по **28 проверок** обычного режима
и по **10** с разрешённым автозапуском. Проверены:

- Гостевая середина, пауза при запрете autoplay, reload без изменения localStorage,
  отсутствие самопроизвольной перемотки при изменении локального значения.
- Пользовательская перемотка назад/в ноль сохраняется и восстанавливается;
  слишком большое значение ограничивается концом, ручной повтор с него работает;
  отрицательное/null/текст/не finite значения безопасно дают начало.
- Нет аккаунтных PUT из гостевого просмотра. Аккаунт использует серверное время,
  игнорируя другое гостевое; paused restore и refetch не записывают позицию.
- Новое время на сервере не двигает открытый плеер, но применяется после reload;
  rewind аккаунта остаётся новым источником следующего открытия.
- SPA между двумя видео и смена аккаунта используют независимые позиции;
  настоящее воспроизведение продолжает сохранение, разрешённое private
  восстанавливается, после отзыва сохранённая позиция не оставляет плеер.
- Разрешённый браузером autoplay начинает проигрывать с сохранённой середины
  гостя/аккаунта; нулевой начальный кадр не перезаписывает её. Телефон без
  переполнения, неожиданных runtime-ошибок нет.

Регрессия в Chromium и Firefox: player.mjs — по **38 проверок**, progress.mjs —
по **33**. В player.mjs готовность учитывает завершение начальной перемотки;
буферизация с удержанными сегментами проверяется отдельно без сохранённой
позиции. В progress.mjs аккаунт с явно записанным нулём по-прежнему стартует
с нуля, игнорируя гостевое время; положительная позиция проверена в resume.mjs.
Сборка/типы, ESLint/Prettier изменённых исходников и формат браузерного профиля
прошли в Docker; относительные ссылки затронутых документов проверены.

Бэкенд приложения и библиотеки не менялись. Safari/native HLS и физический
телефон не квалифицированы; внешний вид проверяет пользователь. Общий make check
остаётся до завершения общего плана F01–F04.
