# Жалоба на видео

F29 реализована на экране просмотра. Референс пользователя от 2026-11-17 —
[обычная модалка](../../frontend/Reference/clipboard_2026-11-17_08-49.png).
Сохраняется её оформление; набор причин определяется
[ADR-0016](../decisions/0016-report-reasons-and-updates.md), а не полным списком YouTube.

## Поведение

Под доступным видео меню «…» → «Пожаловаться» открывает native dialog
«Причина жалобы». Причина изначально не выбрана; без неё отправка отключена.
Шесть вариантов соответствуют готовому [контракту B32](../backend/moderation.md).
Свободный текст, дополнительные шаги и внешние ссылки не добавлены.
Гость переходит ко входу с возвратом к видео; жалоба до входа не отправляется.

POST `/api/v1/videos/{id}/reports` передаёт только `{reason}` с cookie/CSRF
через адаптер сгенерированного Hey API. Только подтверждённый `accepted: true`
закрывает окно и показывает «Жалоба отправлена на рассмотрение.».
Видео продолжает отображаться: сообщение не обещает скрытия или решения.
Повторная отправка разрешена, обновление единственной записи выполняет сервер.
Служебные данные, отправитель и количество жалоб не загружаются.

На время отправки выбор, отмена и повторный submit заблокированы. Ошибка
сохраняет выбор для повтора и не показывает успех. 401 очищает сессию;
403/404 убирают недоступный просмотр. Обычное закрытие очищает выбор/ошибку.
Escape и «Отмена» возвращают фокус на «…», Tab остаётся внутри, стрелки
переключают radio. На телефоне окно помещается в экран и прокручивается
при недостатке высоты; исходный референс — фрагмент ПК, не мобильный снимок.

## Код и жизненный цикл

[ReportVideo](../../frontend/src/features/report-video/ui/ReportVideo.vue)
скомпонован в странице watch через публичный API FSD. Поля формы локальны;
MutationCache не получает ни причину, ни видео в переменных вызова и не хранит
ответ с метаданными. Query с жалобами обычному зрителю не создаётся.
Ключ экземпляра и операций включает ревизию сессии и точный Identifier видео.
Уход, смена видео/аккаунта и отказ доступа отменяют запрос и уничтожают форму;
поздний ответ не восстанавливает окно или сообщение. ID больше 2^53 не округляются.

## Проверки

В Docker прошли vue-tsc/Vite build, ESLint и Prettier затронутых файлов,
по **29 профильных проверок в Chromium и Firefox**.

Профиль [reports.mjs](../../docker/browser/reports.mjs) использует реальные
изолированные API/PostgreSQL/Nginx/RustFS с тестовыми готовыми медиа.
Проверяет шесть причин, вход/возврат, отсутствие выбора, ошибку/повтор,
двойную отправку, блокировку в ожидании, CSRF и точный int64, отсутствие лишних
полей, недоступное private, 401/404, поздний ответ, Escape/Tab/возврат фокуса,
ПК 1920×935 и телефон 390/320. Ошибки и задержка вводятся тестовым прокси;
успешные жалобы принимает настоящий API. Рабочая БД не меняется.

Запуск — как [профиль загрузки](upload.md#проверки): fixture достаточно `--media`,
в команде браузера заменить `upload.mjs` на `reports.mjs`; Firefox — `--firefox`.
Остановка fixture по SIGINT удаляет её медиа, сессии и БД. Safari/WebKit
и реальная экранная клавиатура не проверены. Полный `make check` остаётся
после завершения остальных задач фронтенда. Служебная часть —
[очередь и решения F30–F32](moderation.md).
