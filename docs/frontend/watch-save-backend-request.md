## Согласовано

Кнопка закладки на обычной странице просмотра позволяет сохранить любое
доступное видео, включая чужое, в несколько своих плейлистов всех трёх режимов.
Нажатие строки сразу добавляет/убирает видео; окно остаётся открытым для
нескольких выборов. «Новый» открывает создание плейлиста; при успешном создании
текущее видео сразу включается. Пустой список также позволяет создать плейлист.
Гость входит с возвратом, без автоматической записи после входа.

Это расширяет R16: существующие GET/PUT video/playlists обслуживают Studio
и позволяют автору выбирать плейлисты только своего видео. Нельзя применять
их к чужому видео или ослаблять проверку владельца редактора ради кнопки.
Список справа на watch — обычная главная лента; подсветка считается клиентом
по кадрам. Для этих двух элементов новые API не нужны.

## Контракт

### GET `/api/v1/videos/{video_id}/saved-playlists?cursor=…`

Требует сессию и обычное право просмотра текущего видео. Возвращает собственные
плейлисты текущего аккаунта, включая public/unlisted/private, в существующем
порядке created_at DESC/id DESC. Cursor по 20, привязан к аккаунту и video_id.

```json
{
  "items": [{"id": 123, "channel_id": 10, "title": "Учёба", "description": "", "visibility": "private", "created_at": "…", "updated_at": "…", "selected": true}],
  "next_cursor": null,
  "saved": true
}
```

Элемент — существующий PlaylistResponse + selected. saved означает наличие
видео хотя бы в одном собственном плейлисте во всём списке, не только на странице.
Это подтверждённое состояние значка закладки; счётчик не требуется.
Пустая выдача — 200 items=[]/next_cursor=null/saved=false, не ошибка.

### PUT `/api/v1/playlists/{playlist_id}/videos/{video_id}`

Тело `{selected: true|false}`. Меняет только одну пару; другие плейлисты этого
аккаунта и всех остальных аккаунтов не затрагиваются. Ответ 200:

```json
{"playlist_id": 123, "video_id": 456, "selected": true, "saved": true}
```

saved вычисляется после записи для этого зрителя. Повтор true не создаёт дубль,
не переносит уже включённое видео в конец и не меняет даты повтором; false для
отсутствующей пары также идемпотентен. Удаление и новая установка добавляют в
конец по принятому порядку состава плейлиста. Ручной перестановки нет.
Применяется сессионная CSRF-защита. Клиент не передаёт владельца/роль.

### POST `/api/v1/playlists`: необязательный `video_id`

Сохранить прежнее создание по title/description/visibility. Если передан video_id,
проверить обычное право просмотра и **в одной транзакции** создать свой плейлист
и включить видео. При отказе добавления/прав/зависимости новый пустой плейлист
не остаётся. Ответ 201 — прежний PlaylistResponse; успешный commit означает,
что видео уже включено. Раздельные create и PUT не обеспечивают согласованное
автоматическое включение при сбое/отзыве между ними.

Поля video_id нет у обычного создания Studio. Дополнительных ограничений на
число своих плейлистов и выбранных элементов нет. Клиент не повторяет создание
автоматически после неопределённого исхода/обрыва ответа и не выдаёт его за успех.

## Права, совместимость и ошибки

- GET/PUT и создание с video_id используют обычную проверку доступного
  published/visible/ready видео: public, своё private или разрешённое private.
  Модератор/admin не получает обхода; draft/hidden/неготовое/отозванное — общий 404.
  PUT проверяет владение плейлистом. Нет закрытых имён/превью/признаков членства
  при отказе. GET не создаёт просмотр/позицию/лайк/запись плейлиста.
- Для гостя 401; отказ прав на цель/чужой плейлист — 404. CSRF — прежний
  403 csrf_failed; неверные поля/cursor — 422 по принятому формату. Сессия
  проверяется до разбора cursor. Ответы персональные no-store/Vary: Cookie.
- Права на плейлист не открывают видео. Состав личного/публичного плейлиста
  корректно возвращает доступные видео любых авторов, в прежнем порядке и с
  их настоящими авторами. Нужна проверка всех путей чтения состава и каналов;
  недоступные видео исключаются до LIMIT, без placeholders/утечек счётчиков.
- Перевод видео в private, отзыв email, hide или утрата готовности не очищают
  сохранённые пары при чтении. Они исключаются из выдачи по обычным правам.
  При восстановлении доступа действуют сохранённые включения.
- Прежний Studio PUT полного набора для своего видео меняет только плейлисты
  автора и не удаляет сохранения других пользователей. Параллельные операции
  разных пар не теряются; отзыв прав и запись согласованы транзакционно.
- Точные int64 и существующий JSON-формат сохраняются. Обновить OpenAPI; фронт
  получает DTO/методы через Hey API, без ручного редактирования генерации.

## Приёмка бэкенда

401/CSRF/404/422 и сбои БД без ложного успеха; чужое public, разрешённое private,
отзыв/hidden/draft/не готовое/admin; чужой плейлист; все режимы своих плейлистов;
20/21 и курсор другого аккаунта/видео; saved для selected за первой страницей;
повторы без дублей/изменения порядка/дат; снятие одной пары без потери остальных;
одновременные записи разных пар; создание+сохранение атомарно с откатом;
совместимость Studio полного набора и состава с авторами разных видео;
без N+1, SQL-инъекций и частичных успешных выдач. Рабочее API не имитируется.
