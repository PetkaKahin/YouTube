# Личные разделы и навигация R19

R19 — `done` по функциональному профилю Chromium/Firefox.
[Контракт и бизнес-правила](library-backend-request.md), [референсы](references.md#личные-разделы-r19--2026-11-18),
[задача](../tasks/frontend/library.md). Внешний вид проверяет пользователь;
снимки и сравнение оформления по браузерам не выполняются.

## Страницы и sidebar

- `/feed/subscriptions` использует тот же [VideoList](../../frontend/src/widgets/video-list/ui/VideoList.vue)
  в режиме сетки, что главная. Сервер возвращает видео активных подписок.
- `/feed/history` показывает горизонтальные карточки по последнему принятому прогрессу.
- `/feed/liked` показывает список по текущему лайку и отдельный блок с названием,
  именем аккаунта и превью первого доступного видео. Недостоверные счётчики/даты
  обновления и сообщение о скрытых записях не выдумываются.
- `/feed/playlists` показывает собственные плейлисты всех трёх режимов с реальным
  доступом. Ссылка `/playlist?list=<id>` открывает существующий обычный просмотр.
  Контракт не содержит обложек/числа видео: сохраняется общая нейтральная карточка
  плейлиста, без запроса состава каждого элемента и без N+1. Управление — в Studio.

«Подписки» в sidebar открывают ленту; соседняя кнопка раскрывает/скрывает каналы.
Изначально видны семь каналов, «Развернуть» показывает первую серверную порцию,
«Ещё каналы» запрашивает следующий cursor по 20, «Свернуть» возвращает семь.
Названия и ссылки принадлежат реальным каналам; аватар с инициалом используется
по текущему контракту без изображения. Нет фиктивных индикаторов новых видео.

Остальные пункты — «История», «Плейлисты», «Понравившиеся». В компактной навигации
сохраняются ссылки, раскрытие каналов доступно в полной панели. На телефоне
«Подписки» доступны снизу, «Вы» открывает drawer с личными разделами. Escape
закрывает drawer и возвращает фокус вызвавшей его видимой кнопке; Tab удерживается
на доступных элементах панели. Поддерживаются прямые URL, reload и Back/Forward.

Гость видит вход с внутренним returnTo; личные GET до подтверждения сессии не
отправляются. Loading, empty, отказ определения личности, ошибка чтения,
ошибка продолжения и отказ прав различаются. Продолжение видео/плейлистов —
IntersectionObserver с кнопкой повтора; серверный размер порции — 20.
Сортировку, фильтры, удаление/очистку истории, Shorts, Watch later, воспроизведение
всего списка и перемешивание этот этап не добавляет.

## Код и жизненный цикл

[LibraryPage](../../frontend/src/pages/library/ui/LibraryPage.vue) владеет списками;
[AppShell](../../frontend/src/widgets/app-shell/ui/AppShell.vue) — навигацией и
внутренним SubscribedChannels. Их данные принадлежат Query, Pinia не дублирует
списки. SDK сгенерирован из OpenAPI; четыре новые функции проходят общий
точный int64-адаптер. Сервер остаётся источником доступа и порядка.

Query keys: `['library-videos', scope, kind]`, `['library-playlists', scope]`,
`['subscribed-channels', scope]`. Кэш неактивных списков — gcTime=0. Смена вида
личной страницы пересоздаёт её наблюдателей и ждёт свежего ответа; при отказе
прав прежние данные и кэш этой выдачи удаляются. При ошибке продолжения остаются
только подтверждённые страницы. Дедупликация по точному ID сохраняет порядок API.

Подтверждённый лайк сбрасывает выдачу liked текущей области; подписка — каналы
и ленту subscriptions. Перед сбросом отменяется старое чтение, результат другого
аккаунта не инвалидирует новый. Отправленная небольшая команда лайка/подписки
дожидается подтверждения после SPA-перехода: обновление личной выдачи не зависит
от жизни исходной кнопки. Её поздняя ошибка/выбор не переносятся на другой экран.
Принятый прогресс обновляет позиции во всех
видеовыдачах, включая R19; история заново использует серверную хронологию.
Создание плейлиста в Studio видно при следующем свежем открытии личного списка.

Видеокарточки используют прежние hover-preview и полосу просмотра. Ошибка
превью/предпросмотра запускает перепроверку прав выдачи. Во время смены/проверки
аккаунта и при отказе не показываются прежние списки, имя и обложка liked.
AbortSignal, смена scope и транспортная защита [F33](access-lifecycle.md) не
позволяют поздним ответам восстановить данные прошлого аккаунта. Отзыв private
исключает видео из liked/history на следующем подтверждённом чтении. Уже
загруженные байты не обещаются к удалению задним числом.

## Проверки

Профиль [library.mjs](../../docker/browser/library.mjs) использует изолированный
настоящий API/PostgreSQL/Valkey/Nginx/RustFS и скачанные материалы, без создания
новых изображений/роликов. Fixture — `--media --links --channel --session` без
`--upload`, по [общей инструкции](upload.md#проверки); браузер — `/checks/library.mjs`,
Firefox — `--firefox`. Браузеры запускаются последовательно. Сценарий создаёт
свои тестовые аккаунты/подписки/лайки/позиции через обычные HTTP-команды с CSRF.
Рабочая БД не меняется; SIGINT fixture удаляет тестовые сессии/медиа/БД.
Прокси вводит 503 и задержки, успешные данные/порядок/cursor/права/401 настоящие.
Пароли/cookie и закрытые URL в диагностике не печатаются.

Chromium и Firefox прошли по **47 функциональных проверок**:

- Четыре прямых гостевых URL без личных GET, вход с возвратом и настоящие
  пустые ответы всех разделов, без автоматического создания/лайка/подписки.
- Каналы sidebar: семь → двадцать → двадцать два, исходный порядок API,
  раскрытие/скрытие независимо от перехода и ссылка на реальный канал.
- Видео подписок 20/20/1, liked/history 20/1, собственные плейлисты 20/20/5:
  точные ID > 2^53, отсутствие дублей, реальная серверная хронология/позиции.
- Первый отказ 503 и повтор, отказ продолжения без потери подтверждённой
  страницы, повтор без дубля, безопасный текст плейлиста.
- Подтверждённый unlike исключает видео; отмена подписки обновляет sidebar
  и ленту, новый принятый прогресс поднимает одну запись истории. Дополнительные
  сценарии задерживают настоящий PUT до сервера, уходят со страницы кнопки
  и проверяют обновление уже открытой выдачи после позднего подтверждения.
- Свой private-плейлист открывает обычный состав. Поздний ответ владельца
  после входа другого аккаунта не возвращает его кэш или карточки. Переход
  между видами личных страниц ждёт свежее чтение без старого снимка.
- Разрешённое private-видео присутствует; реальный отзыв исключает его из
  истории и понравившихся. Настоящая потеря Valkey-сессии очищает оба списка
  и каналы; служебных исключений в новых клиентских запросах нет.
- Телефон 390/320: drawer, фокус при открытии/закрытии, рабочий личный переход,
  отсутствие горизонтального переполнения и неожиданных runtime-ошибок.

Генерация Hey API, vue-tsc/Vite build, ESLint/Prettier изменённых исходников,
синтаксис/формат профиля и локальные ссылки документов прошли в Docker.
Регрессия прошла в обоих браузерах: главная — по **20**, лайки видео — по **36**,
подписки — по **38**, серверная позиция — по **33** проверки. После исправления
завершения команд при SPA-переходе F15/F19 повторены на итоговом коде.
Для F09/F15/F19 использованы чистые fixture без лайков новых тестовых зрителей;
F09 требует `--channel`, F15/F19 — обычные `--media --links`,
R18 progress — `--media --links --jobs`. Это разные наборы данных, не подмена API.
Safari/WebKit и физический телефон не квалифицированы; общий make check остаётся
до завершения общего плана F01–F04. Бэкенд приложения и контракт не менялись.
