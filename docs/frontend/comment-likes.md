# Лайки комментариев

F17 — `done` по функциональному профилю Chromium/Firefox, с готовым [B31](../backend/comments.md).
Чтение, форма и общие права обсуждения — [F16](comments.md).
Внешний вид проверяет пользователь; скриншоты не снимаются.

## Реализация

[VideoDiscussion](../../frontend/src/widgets/discussion/ui/VideoDiscussion.vue)
владеет командами лайка и обновляет серверное состояние в Query.
[CommentItem](../../frontend/src/widgets/discussion/ui/CommentItem.vue)
показывает запись, ожидающую кнопку и ошибку своей операции. Кэш и счётчики
не копируются в локальное состояние: локальная Map содержит только контроллеры
ожидающих запросов по ID комментария.

Гость переходит ко входу с текущим returnTo; после входа лайк автоматически
не отправляется. Вошедший зритель может поддержать свой или чужой доступный
комментарий. PUT передаёт только целевой bool `liked`; ID видео/комментария
фиксируются до отправки. Выбор и счётчик меняются после подтверждения сервера.
Повторные нажатия при ожидании одной пары не создают новую команду; разные
комментарии можно лайкнуть параллельно.

Перед командой отменяются незавершённые чтения обсуждения. Автоматическое
чтение, продолжение списка и его повтор приостановлены до окончания всех
лайков этого экземпляра. Проверка ожидания есть и в обработчике продолжения,
чтобы нажатие в одном кадре с лайком не обходило ещё не обновившийся disabled.
Ответ PUT обновляет соответствующий ID во всех существующих сортировках.
Запоздавший снимок списка не сбрасывает подтверждённый выбор и не теряет
ответ другой одновременно выполняющейся команды.

После последней команды список заново получает порядок с сервера, включая
popular и уже загруженные cursor-страницы. На клиенте записи не переставляются
по локальному счётчику. Во время запроса показывается обновление; подтверждённые
строки сохраняются до ответа. Смена сортировки во время PUT ждёт его окончания
и затем читает новый порядок. При равных лайках более новый комментарий выше.

`aria-pressed` описывает выбор, `aria-busy`/`aria-disabled` — ожидание. Обычный
disabled используется при смене/загрузке сессии, ожидание лайка не снимает
клавиатурный фокус. Сбой не оставляет локальный успех: ошибка появляется у
исходной строки, повтор доступен. `csrf_failed` сохраняет обсуждение и предлагает
обновить страницу. Детали HTTP-ошибки не вставляются в DOM как HTML.

## Приватность и отмена

Команда захватывает ID и область сессии; ответ применяется только к живому
экземпляру с теми же видео/зрителем. Ошибка строки дополнительно проверяет
исходный ID комментария. Поздние ответы не выбирают кнопку другого аккаунта
или видео и не показывают там прежнюю ошибку. При уходе контроллеры отменяются;
отмена ответа не обещает откат уже принятого сервером лайка. Возврат читает
фактический результат. Снимки обсуждения после ухода не сохраняются по F16.

401 использует общую очистку сессии. Отказ обычного доступа останавливает
ожидающие лайки, закрывает всё обсуждение и удаляет запросы всех его сортировок.
Владелец private сохраняет плеер, но не видит комментарии/их счётчики. При
возвращении public записи и прежние лайки доступны только после свежего чтения.
Лайк не предоставляет доступ и не снимается автоматически при смене видимости.

## Проверки

В Docker прошли vue-tsc/Vite build, ESLint и Prettier обоих изменённых компонентов.
Chromium и Firefox выполнили по **38 функциональных проверок** F17.
Непосредственно изменённое чтение/публикация F16 повторно прошли по **52 проверки**
в обоих браузерах: форма, страницы, сортировки и смена доступа сохранили поведение.

[comment-likes.mjs](../../docker/browser/comment-likes.mjs) использует fixture
`--media`, настоящие API/PostgreSQL/Valkey/Nginx/RustFS, скачанные медиа и 41
комментарий, созданный через API. Успешные ответы не подменяются. Прокси вводит
только задержки, 503 и отсутствие CSRF; сессии, 401/403/404 и смена видимости
проверяются реальным API. Текст комментариев, пароли и cookie в отчёт не пишутся.

Проверены собственный/чужой комментарий, установка/снятие и ноль, перезагрузка,
гость/вход без автокоманды, bool и точные ID в маршруте, быстрые клики и отсутствие
двойной записи, HTTP-ошибка и повтор, CSRF без закрытия разрешённого обсуждения,
буквальный вывод ошибки, поздний GET, две параллельные команды и запрет чтения
до завершения обеих. Отказ обновления после успешного PUT сохраняет лайк на
сервере; повтор списка показывает фактическое состояние.

Проверены независимый вклад зрителей, гостевой агрегат без чужого выбора,
истёкшая сессия без запрещённой записи, поздние успех/ошибка при переходе,
выход/смена аккаунта до ответа, смена сортировки при ожидании, popular с равными
счётчиками, перемещение записи из следующей страницы по свежему серверному
порядку без дублей, private/public и отсутствие лайка после запрета. На ширине
телефона проверены Enter/Space, подпись и сохранение фокуса при ожидании.

Запуск — как [профиль загрузки](upload.md#проверки), fixture `--media` вместо
`--upload`, браузер comment-likes.mjs; Firefox — `--firefox`. Профили идут
последовательно: Chromium использует public, Firefox — silent. SIGINT fixture
удаляет изолированные БД/сессии/объекты, рабочие данные не затрагиваются.

Новых библиотек, API-контрактов и изменений бэкенда нет. SQL/блокировки и сбой
постоянного хранилища относятся к готовому B31, браузер проверяет результат
и неизменность записи после отказа HTTP. Команда не принимает свободный текст,
пути или внешние назначения. Safari/WebKit и физический телефон не проверены;
эмуляция ширины не квалифицирует устройство. Общий `make check` отложен до
завершения текущего плана; визуальную приёмку эти проверки не заменяют.
