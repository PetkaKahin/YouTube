# Поиск трёх типов

F10 — `done` по функциональному профилю. Поиск подключён к готовому
[API B24](../backend/search.md); правила — [R04](../project/search.md).
Внешний вид проверяет пользователь. Фильтры и сортировки F11 реализованы
и приняты по [отдельному профилю](search-filters.md); ниже описан F10.

## Поведение и код

[SearchPage](../../frontend/src/pages/search/ui/SearchPage.vue) получает видео,
каналы и плейлисты через Hey API и TanStack Query. Текст берётся из
`search_query` в URL, обрезаются крайние пробелы. Прямой переход, обновление
и Back/Forward восстанавливают запрос и строку в общей оболочке. Новое
подтверждение строки открывает поиск по новому запросу.

Разрешено 1–100 Unicode-символов; пустой/длинный прямой запрос показывает
пояснение и не отправляется. Строка в оболочке подтверждается кнопкой или Enter,
на телефоне — после раскрытия мобильного поиска. Запросы, имена, теги и описания
выводятся как текст; подсказок, поиска по email или рекомендаций нет.

Ключ Query содержит ревизию сессии и параметры. Поздний ответ отменённого запроса
не заменяет новую выдачу. Страницы по 20 продолжаются серверным cursor;
интерфейс сохраняет порядок API и устраняет повторы по типу/точному ID.
Следующая порция загружается при приближении конца или кнопкой. Ошибка первой
страницы отличается от ожидания и пустого результата; ошибка продолжения
оставляет уже полученные строки и предлагает повтор.

Ссылка видео ведёт на `/watch?v=<точный id>`, автор — на канал. Результат канала
ведёт по его тегу, одинаковые имена не объединяются. Плейлист открывает состав
на канале автора с `list=<точный id>`. Доступ каждого видео проверяется отдельно;
разрешение по email не делает приватное видео результатом публичного поиска.
Позиция просмотра и ленивый предпросмотр используют общую
[карточку R18](hover-preview.md).

## Проверки и границы

[search.mjs](../../docker/browser/search.mjs) работает в Docker через реальный
изолированный API/PostgreSQL/Nginx/RustFS. Fixture `--media --channel` создаёт
41 публичное видео, 41 публичный плейлист и три канала с одинаковыми именами;
готовые медиа берутся из ранее скачанных материалов.

В Chromium и Firefox прошли по **39 функциональных проверок**.
Первый профиль F10 завершил приёмку существующей реализации без изменений
кода приложения. После изменений F11 эти 39 проверок повторены в обоих
браузерах; сборка и проверки затронутого кода — в профиле F11.
Общие тесты приложения не запускались.
Смешанная выдача содержит 85 строк, порции 20/20/20/20/5; видео и плейлисты
по отдельности — 20/20/1. Все строки и порядок сравниваются с полным ответом API,
включая ID больше 2^53. Проверяются переходы трёх типов и автора видео,
поиск имени/@тега другим регистром, отсутствие private/hidden/pending/draft и
unlisted/private-плейлистов, отсутствие поиска по описанию/email, буквальные
SQL/HTML-строки и безопасный вывод названий/описаний.

Проверены 100 и 101 Unicode-символ, пустой запрос, 503 первой/следующей страницы,
повтор без дубликатов, запоздалый ответ после смены запроса, Back/Forward,
обновление страницы, приглашённый зритель и мобильный ввод Enter/переход на канал.
Ошибки и задержки вводит только тестовый HTTP-прокси; успешные ответы, cursor,
метаданные и права реальные. Скриншоты не создаются, геометрия не сравнивается.

Запуск — как [профиль загрузки](upload.md#проверки), с fixture `--media --channel`
и браузером `search.mjs`; Firefox — `--firefox`. После прогона SIGINT очищает
тестовые медиа, БД и сессии. Рабочие данные не меняются.
Новых зависимостей, секретов, загрузок или фоновых задач поиск не добавляет.
Пределы длительности/периодов, сочетания фильтров и SQL-конкурентность самого API
остаются в B24/B25; F11 проверяется своим профилем. Safari, реальная экранная клавиатура
и полная приёмка приложения не выполнялись.
