# Studio: контент и создание плейлистов

F21 — `done` по функциональному профилю Chromium/Firefox. Размещение и форма подтверждены
пользователем — [ADR-0066](../decisions/0066-studio-playlist-interface.md),
[референсы](references.md#личный-список-плейлистов-studio).
F22 проверен отдельным [профилем начала загрузки](upload-start.md).
Первый этап [передачи/обработки/публикации F23–F25](upload.md) и [параметры видео F27/F28](video-options.md)
реализованы в форме загрузки и [общих настройках F26](video-settings.md).

## Интерфейс и данные

Меню аккаунта → «YouTube Studio» и `/studio` открывают
[свои видео и черновики](video-settings.md) на `/studio/content/videos`.
Вкладка «Плейлисты» ведёт на `/studio/content/playlists`. У Studio отдельная оболочка; собственный
публичный канал сохраняет обычный интерфейс и public-списки, как чужой канал.
Гость получает предложение войти с возвратом в Studio; личный список до входа
не запрашивается. В оболочке есть выход и переход на обычный YouTube.

«Контент на канале» → «Плейлисты» показывает таблицу из
GET `/api/v1/playlists/mine`: название/описание, тип, доступ, дата изменения.
Все три режима владельца, порядок и cursor по 20 определяет API.
Следующая порция загружается при прокрутке или кнопкой; ID дедуплицируются.
Переход по названию использует общий `/playlist?list=<id>` с составом на канале.
Для пустого списка, загрузки и ошибок предусмотрены отдельные состояния/повтор.
Ошибка следующей страницы сохраняет подтверждённые строки; ошибка фонового
чтения скрывает старую таблицу и предлагает повтор, не выдавая её за свежий ответ.
Превью, число видео, просмотры, поиск и фильтры из полной Studio не имитируются:
соответствующих данных или сценариев в нашем контракте/ТЗ нет.

Меню «Создать» также открывает [загрузку видео](upload.md).
Оно доступно во всей Studio и в обычной шапке рядом с аватаром; переход
к созданию плейлиста с другого экрана описан в [настройках Studio](video-settings.md#создать-в-шапке).
«Создать» → «Создать плейлист» открывает модалку «Новый плейлист»:
название 1–100 Unicode-символов после trim, описание до 5000 и три режима.
Исходный доступ `public` («Открытый доступ») взят из снимка пользователя.
Название и описание выводятся обычным текстом, превышение длины не обрезается.
Другие поля полной формы YouTube не добавлены. Создание не меняет состав
или доступ к видео; состав выбирается в [форме видео](video-options.md#плейлисты).

POST `/api/v1/playlists` выполняется с cookie/CSRF через адаптер Hey API.
Сохранение подтверждает сервер; затем модалка закрывается, список начинается
с первой порции и показывается «Плейлист создан». Ошибка сохраняет черновик,
ошибка поля возвращает фокус к полю. На время запроса редактирование, закрытие
и повторная отправка блокируются. После обычного закрытия черновик очищается.
Escape закрывает модалку, Tab удерживает фокус внутри, фокус возвращается
на «Создать». Меню также закрывается по Escape и нажатию снаружи.
Ошибки поля снимаются при его редактировании. Реальная ошибка валидации
связывается с полем и получает фокус внутри своего диалога после разблокировки.
Синхронный флаг отправки блокирует несколько submit в одном кадре.
Позднее событие close не очищает уже открытую новую форму.

## Код и приватность

- [Страница](../../frontend/src/pages/studio-playlists/ui/StudioPlaylistsPage.vue)
  владеет Query списка с ключом ревизии сессии; [оболочка](../../frontend/src/widgets/studio-shell/ui/StudioShell.vue)
  содержит навигацию и выход.
- [Создание](../../frontend/src/features/create-playlist/ui/CreatePlaylist.vue)
  хранит черновик локально. Перед отправкой фиксируются поля, сигнал и область
  сессии. MutationCache получает вызов без полей формы, результат содержит
  только область сессии; при закрытии наблюдатель сбрасывается. Ответы/ошибки
  проверяют живой экземпляр, область и ревизию формы.
- Смена пользователя/выход/401 очищают старые запросы, личный интерфейс
  и черновик. 403/404 списка удаляют его данные. При уходе запрос отменяется,
  неактивный снимок удаляется Query с gcTime 0. Новый экземпляр ждёт свежего
  чтения; отложенная очистка после ухода не удаляет замену по тому же ключу.
  Поздний ответ не восстанавливает таблицу и не закрывает форму другого аккаунта.
  Отмена ответа не обещает откат уже принятого сервером плейлиста.
- URL `create=playlist` проверяет прежние маршрут/область после nextTick,
  чтобы не открывать модалку после ухода. Параметр потребляется через replace.
- ID остаются точными строками, включая значения больше 2^53. Сырой SDK
  страницы не импортируют; бэкенд на фронтенд-этапе не менялся.
  Актуальная генерация клиента включает метод своих видео по Q50.

## Проверки и границы приёмки

В Docker прошли vue-tsc/Vite build, ESLint затронутых файлов и форматирование.
Chromium и Firefox выполнили по **56 функциональных проверок**.
Актуальный профиль — [studio-playlists.mjs](../../docker/browser/studio-playlists.mjs),
Chromium/CDP и Firefox/BiDi, без скриншотов. Используются отдельная БД, настоящие
API/PostgreSQL/Valkey/Nginx/RustFS и скачанные медиа fixture `--media --links`.
Для каждого запуска через API регистрируются два новых автора; рабочая БД
не используется. Прокси вводит задержки, 503, отказ списка 403, разрыв соединения
и удаление CSRF. Создание, реальные 401/CSRF 403/валидация 422 и права настоящие;
успешные ответы не подменяются. Поля формы, пароли и cookie в отчёт не пишутся.

Проверены ожидание сессии и гость без личного запроса, вход с возвратом,
пустой список, public по умолчанию, пробелы/NUL/101/5001 и точные Unicode-границы
100/5000, trim без обрезания, Escape/Tab/фокус, позднее событие close,
одна команда при нескольких submit, ожидание без ложного успеха, создание
всех трёх режимов и безопасный HTML-подобный текст. Проверяются реальные права
private/unlisted и обнаружение только public на обычном канале.

Проверены 503, сетевой отказ, CSRF и 422 без вставки строки, сохранение черновика,
полевая ошибка/фокус и явный повтор. Список из 41 записи проходит 20/20/1 с
ошибкой продолжения, повтором, прокруткой и порядком сервера без дублей.
Создание отменяет запоздавшее чтение и возвращает первую страницу с новой
записью. Начальная/фоновая ошибка и отказ доступа не оставляют успешную таблицу;
повторы восстанавливают реальное состояние.

Проверены переход из своей таблицы к составу, «Создать» в публичной шапке,
одноразовый URL-параметр, локальный черновик вне MutationCache, поздние список
и уже подтверждённое создание после ухода, смена владельца до ответа без очистки
его новой формы, истёкшая сессия без запрещённой записи, ошибка/повтор определения
аккаунта и выход. Новый плейлист доступен в выборе видео без выбранной галочки.
Компактная форма внутри выбора также создаёт и обновляет реальные варианты,
не меняя настройки/приватность видео. На ширине телефона — создание клавиатурой
и Escape в меню. Кнопки/поля проверяются функционально, геометрия не сравнивается.

Запуск fixture/gateway — как в [профиле загрузки](upload.md#проверки),
с `--media --links` вместо `--upload`. Затем:

```bash
docker run --rm --network youtube_default --user "$(id -u):$(id -g)" \
  --volume "$PWD/docker/browser:/checks:ro" \
  --volume /tmp/frontend-browser-results:/work --workdir /checks \
  youtube-browser-check /checks/studio-playlists.mjs
```

Для Firefox добавить `--firefox`; прогоны идут последовательно. SIGINT fixture
удаляет её БД, сессии и объекты. Ранний профиль studio.mjs с 39 проверками
сохранён как свидетельство первого этапа; текущая приёмка использует новый
профиль и не повторяет его визуальные замеры/снимки.

Новых библиотек, контрактов и изменений бэкенда нет. Для Studio пользователь
разрешил общее сходство по [ADR-0068](../decisions/0068-studio-visual-scope-and-video-options.md);
внешний вид проверяет самостоятельно. Safari и настоящая экранная клавиатура
не квалифицированы. Серверные отказы PostgreSQL/Valkey и SQL/транзакции покрывает B26;
здесь проверяется поведение UI и неизменность записей при отказах HTTP.
Новых обработчиков путей/команд/внешних назначений нет; текст передаётся JSON
и выводится Vue. Полный `make check` остаётся до завершения текущего плана.
