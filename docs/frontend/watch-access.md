# Прямой просмотр и состояния доступа

F12 — `done` по функциональному профилю: исправлены ожидание сессии
и неактивный кэш метаданных. [Основной просмотр и плеер](watch.md),
[обычные права](../backend/private-access.md), [защищённая раздача](../backend/media-delivery.md).
Новых функций и изменений API нет; внешний вид проверяет пользователь.
В Docker прошли vue-tsc/Vite build, ESLint и Prettier затронутого кода.

## Изменения

[WatchPage](../../frontend/src/pages/watch/ui/WatchPage.vue) ждёт подтверждения
сессии, включая подтверждённого гостя, до запроса метаданных. Это исправляет
воспроизведённый случай: при задержанном `/auth/me` запрос приватного видео уже
отправлялся. Бэкенд проверял Cookie, но UI ещё не определил зрителя.

Начальная проверка показывает загрузку. Ошибка определения аккаунта показывает
отдельный отказ с рабочим повтором; она не считается гостем. Повторная ошибка
не разрешает запрос видео. При сбое фоновой проверки убираются название,
метаданные, дочерние действия и плеер; освобождаются источник и звук.
После успешного повтора метаданные читаются для подтверждённой ревизии заново.

Неактивный запрос метаданных имеет gcTime 0: Back не рисует старые персональные
данные до свежей проверки API. Запрошенный ID берётся из захваченного query key,
а не из изменяемого URL в момент запуска функции. Ключ содержит ревизию сессии
и точный int64; старый ответ отменённого запроса не заменяет другое видео.
Описание раскрывается локально и сбрасывается при смене ключа.

Недоступные private/hidden/draft/unready/отсутствующее видео получают одинаковое
объяснение без закрытых названий, автора, превью и качеств. Гость может перейти
ко входу с внутренним returnTo. Ошибка чтения метаданных отличается от отказа
доступа и поддерживает повтор. Некорректный ID отклоняется до API; чужой HLS URL
в ошибочном DTO не создаёт плеер. Сервер продолжает проверять каждый медиазапрос.

## Проверки

[watch-access.mjs](../../docker/browser/watch-access.mjs) работает в Docker с
fixture `--media` и реальными API/PostgreSQL/Nginx/RustFS, Cookie/CSRF,
скачанными AV1/AAC/WebVTT-материалами. Профиль не снимает скриншоты.
До исправления `--probe-session` воспроизвёл запрос метаданных при задержанном
ответе текущего аккаунта. Chromium и Firefox после исправления прошли по **45 проверок**.
Изменённая интеграция прогресса R18 прошла по **33 проверки** в обоих браузерах:
финальная запись при уходе работает без сохранения неактивных метаданных.

Покрыты загрузка/ошибка/повтор определения сессии, прекращение активного
приватного просмотра при ошибке, public/private и владелец/приглашённый/посторонний/
гость, обычный отказ владельцу hidden/draft/unready, максимальный int64 и
неправильные/повторные ID, 503 метаданных и повтор, некорректный внешний HLS URL,
пользовательский HTML как текст, раскрытие описания и переход автора на телефоне.

Смена видео останавливает прежний источник; задержанный ответ не заменяет
новое название. Владелец отзывает разрешение отдельной HTTP-сессией: Back ждёт
новый ответ без вспышки старых метаданных, проверка активного видео останавливает
плеер. MutationObserver проверяет промежуточные изменения DOM при Back.
Завершение серверной сессии убирает приватные данные и не записывает позицию
аккаунта гостю. Ошибки/задержки/испорченный HLS URL вводит только прокси;
успешные права, отзыв, сессии и медиа настоящие.

Запуск — как [профиль загрузки](upload.md#проверки), fixture `--media`, браузер
`watch-access.mjs`; Firefox — `--firefox`. SIGINT удаляет тестовые БД/сессии/медиа;
рабочие данные не меняются. Новых файлов пользователь не загружает этим экраном,
новых фоновых задач и секретов нет. Границы транзакций и SQL-инъекции самого
API покрываются B20/B21; полноэкранный режим/качества/субтитры относятся к F13/F14,
полная приёмка сессий ко всем экранам — F07/F08/F33. Safari и реальный телефон
этим профилем не проверяются; общий набор приложения не запускается.
