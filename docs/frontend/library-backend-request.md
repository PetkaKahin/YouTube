# R19: личные разделы обычного интерфейса — требования к API

Статус: четыре метода бэкенда реализованы; миграция 0027 применена в dev,
маршруты и DTO доступны в его OpenAPI. Фронт может получить типы через Hey API.
Поведение и порядок подписанных каналов согласованы пользователем 2026-11-18.
[Реализация и 37 профильных проверок](../backend/library.md).
Неработающие ссылки и фиктивные данные в приложение не добавляются.

## Согласовано

- В sidebar появляются «Подписки», «История», «Плейлисты», «Понравившиеся».
  [Референс](../../frontend/Reference/clipboard_2026-11-18_08-22.png).
- «Подписки» открывают ленту видео каналов, на которые подписан пользователь;
  отдельное раскрытие показывает список этих каналов со ссылками на них.
- Остальные пункты открывают отдельные личные страницы обычного интерфейса.
  История упорядочена по последнему просмотру, понравившиеся — по времени лайка;
  плейлисты — собственные. Создание/редактирование контента остаётся в Studio.
- Для всех списков действует [ADR-0059](../decisions/0059-list-cursors-and-channel-order.md):
  cursor, порции по 20. Источники личных данных — серверные сессия/PostgreSQL.
  Полноценная история гостя, уведомления, очистка/удаление истории и новые
  виды плейлистов этим запросом не добавлены.

## Новые методы

Все четыре GET требуют сессию; гость получает 401. Пользователь определяется
сервером, без account_id/role из query. Ответ страницы — `{items, next_cursor}`,
последняя страница имеет next_cursor=null. Пустой список — 200 с items=[].
Ответы no-store/Vary: Cookie. Некорректный/чужой cursor — 422 invalid_cursor.
ID точные int64 по существующему контракту. OpenAPI включает методы и DTO.

| Метод | Состав и порядок |
| --- | --- |
| GET `/api/v1/channels/subscriptions?cursor=…` | Только каналы активных подписок текущего аккаунта; элементы как существующий ChannelResponse. Порядок created_at DESC, id DESC подтверждён пользователем. |
| GET `/api/v1/videos/subscriptions?cursor=…` | Видео из активных подписок; только public/published/visible с готовым вариантом, как в обычной публичной ленте. По added_at DESC, id DESC. |
| GET `/api/v1/videos/liked?cursor=…` | Активные лайки текущего аккаунта, только видео, доступные ему сейчас по обычным правилам просмотра. По времени текущего лайка DESC, video_id DESC. |
| GET `/api/v1/videos/history?cursor=…` | Одна запись видео по последнему принятому прогрессу текущего аккаунта; только доступные ему сейчас видео. По watch_progress.updated_at DESC, video_id DESC. |

Три видео-метода возвращают существующие FeedCardResponse: автор/ссылка канала,
превью, длительность и персональный watch_progress. Нового формата
карточки не требуется. В истории watch_progress не null; его updated_at позволяет
показать дату последнего просмотра. При другом источнике истории бэкенд должен
явно согласовать дату в DTO, не подменяя её датой загрузки/публикации видео.
liked_at фронту для карточки не обязателен: сортировка/граница принадлежат серверу.

Для понравившихся понадобится сохраняемое время текущего лайка: сейчас
video_likes содержит только пару ID. Повтор PUT liked=true не поднимает запись;
после снятия и нового лайка — новое время. Старые записи не имеют достоверной
исторической даты: заполнение при миграции — техническое решение бэкенда,
не выдавать его за восстановленную точную пользовательскую хронологию.

История использует уже существующие принятые записи PUT progress, без новой
команды записи. Чтение карточки/страницы, hover-preview и служебный плеер не
создают просмотр. Новые принятые позиции, включая перемотку назад, поднимают
это видео; дубликат строки видео в истории не создаётся. Порог просмотра,
слияние гостевых данных и счётчик просмотров не добавляются.

## Существующий метод для плейлистов

GET `/api/v1/playlists/mine?cursor=…` уже возвращает собственные плейлисты
всех трёх режимов с названием, описанием, видимостью и датами. Он подходит
для обычной страницы «Плейлисты»; отдельная копия данных не нужна. Порядок
по созданию, новые первыми, id DESC при равенстве сохраняется.
Состав открывается через существующий просмотр плейлиста с независимой
проверкой каждого видео. Собственный private-плейлист не открывается другим.
Новые счётчики, обложки плейлистов и даты их просмотра не требуются.

## Инварианты и приёмка бэкенда

- Подписка/лайк/история не предоставляют разрешение на видео. История и лайки
  могут содержать разрешённое private, но после отзыва/скрытия/утраты готового
  варианта оно не возвращается. Лента подписок остаётся public, как обычная лента.
  Нет закрытых названий, превью, ссылок, счётчиков или персональных данных другого
  аккаунта. GET не удаляет исходные записи только из-за временной недоступности.
- Снятие подписки исключает канал/его видео при следующем чтении, снятие лайка
  исключает видео из понравившихся. Повторы не создают дубликаты. Чтения не
  меняют историю, like/subscription-состояния и даты метаданных видео/канала.
- Cursor привязан к аккаунту/виду выдачи и устойчивому составному порядку;
  нет пропусков доступных записей из-за фильтрации уже после LIMIT. Позиции
  и авторы читаются пакетно, без N+1. Пустая страница не маскирует ошибку.
- Проверить реальные 401/права/изоляцию аккаунтов, границы 20/21, равные даты,
  неверный/чужой cursor, повторы, снятие подписки/лайка, повторный просмотр,
  private/отзыв/hidden/draft/не готовое видео, SQL-ввод и сбои зависимостей.
  Не возвращать частичный успешный ответ при отказе чтения.

Библиотеки, медиаформаты, публичная выдача канала и существующие PUT лайка/
подписки/progress не меняются по смыслу. Данные не имитируются на фронте.
Референсы страниц получены 2026-11-18; подписки оформляются как главная.
