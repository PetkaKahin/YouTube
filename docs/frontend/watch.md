## Экран и доступ

`pages/watch` владеет запросом метаданных через TanStack Query. Ключ содержит
ID видео и область сессии. Прямое открытие не зависит от карточки в ленте.
Показываются название, канал со ссылкой, дата и описание с раскрытием.
Пользовательский текст выводится интерполяцией Vue, без HTML-вставки.
Переходы, отказ API и смена личности убирают прежние метаданные/плеер.
Ожидание проверки сессии, повтор после её сбоя и отсутствие неактивного кэша
при Back — [F12](watch-access.md).

Недоступные public/private, draft, hidden, неготовое и отсутствующее видео
сохраняют общий серверный отказ: UI не угадывает скрытую причину и не раскрывает
закрытые название/канал/превью. Гостю доступен вход с возвратом к текущему URL.
Ошибки сети имеют отдельное состояние с повтором.

На просмотре боковая панель по умолчанию закрыта и открывается как drawer;
мобильная нижняя навигация скрыта, как в собранном референсе. На ПК сохранена
геометрия основного столбца. Рекомендации вне ТЗ не заполняют правый столбец.
Лайки, подписка, комментарии и [жалоба на видео](reports.md) подключены.
Ссылка автора ведёт к [странице канала F18](channel-playlists.md).

## Воспроизведение

`widgets/video-player` использует `hls.js` 1.7.4 и собственные Vue/SCSS-контролы
по [ADR-0065](../decisions/0065-hls-client.md). Доступны запуск/пауза, перемотка,
звук, полноэкранный режим при поддержке API, готовые качества и встроенные субтитры.
Управление с клавиатуры: Space/K, стрелки, J/L, M, F, C, Home/End; фокус полей
и кнопок не перехватывается. Меню поддерживают стрелки и Escape с возвратом фокуса.
Контролы скрываются при воспроизведении и остаются доступны клавиатуре.

Качества берутся из master и сопоставляются с готовыми серверными вариантами;
выбор сохраняет позицию/паузу. WebVTT берётся из исходных дорожек, добавленных
сервером в HLS. Автогенерации и отдельной загрузки субтитров нет.
Обновление готовых качеств после повторного запроса метаданных пересоздаёт HLS
с восстановлением позиции, состояния воспроизведения и доступного выбора
качества/субтитров — [F14](player-quality.md).

Видео вписывается через `object-fit: contain`. Для fMP4/AV1 не требуется
transmux-worker; внешний скрипт/worker не загружается. Модуль просмотра загружается
лениво, поэтому hls.js не входит в начальную загрузку главной.
Медиассылки ограничены тем же origin и путём текущей публикации.

На HTTP 401/403/404 от медиа плеер уничтожается, источник снимается,
метаданные, лайки и кэш обсуждения текущего видео удаляются. Выход и смена видео также уничтожают HLS
и останавливают звук. Уже полученные байты не обещаются к отзыву.
После исчерпания штатных повторов hls.js ошибка сегмента прекращает ожидание,
доступна явная попытка повторить с восстановлением последней подтверждённой
позиции и состояния паузы — [проверка F13](player-controls.md).
Ошибка субтитров выключает дорожку и сообщает
об отказе, не выдавая её за успешно выбранную.

При отсутствии MSE предусмотрен native HLS; ошибка native-плеера повторно
проверяет доступ через API, поскольку HTTP-код медиазапроса браузер не сообщает.
Ручной выбор качества native-ветки пока не реализован. Safari/WebKit, настоящий
телефон и его fullscreen/клавиатура ещё не проверены. Поддержка AV1/AAC зависит
от браузера и его декодеров; библиотека не заменяет отсутствующий кодек.

## Проверки и готовые материалы

Используются скачанные тестовые дорожки Shaka и Chromium; генерации изображения
и звука нет. Ссылки, размеры и SHA-256 находятся в
[media-sources.json](../../docker/browser/media-sources.json). Скачивание проверяет
хеш; файлы хранятся вне репозитория. Для короткого входа копируются первые
12 секунд готовых видео/аудио, готовые VTT включаются в MP4, у портретного образца
копируется видеодорожка без звука. Подготовленный файл проходит обычную загрузку
и конвейер приложения; это проверяет реальный серверный AV1/AAC/WebVTT.

Отдельная БД, случайный префикс сессий и собственные объекты RustFS изолируют
проверки от рабочих данных. Изображения/медиа удаляются по записям этой БД при
остановке fixture, затем удаляются сессии и БД. Входные скачанные файлы сохраняются
для повторных проверок. Рабочие worker не получают задания тестовой БД.

В Chromium прошли 40 сценариев просмотра на 1920×935 и 390×844 —
AV1/AAC, пауза/перемотка, меню качеств, сохранение позиции, реальные WebVTT,
mute/fullscreen, беззвучное вертикальное видео, private owner/invited/stranger,
отзыв при запросе качества, direct URL и большие ID, безопасный текст,
ошибка API/повтор, остановка звука/источника при уходе и выходе из private,
отказ сегмента и восстановление после повтора. Firefox прошёл 26 проверок,
включая AV1/AAC, WebVTT, смену качества с сохранением позиции, клавиатуру,
беззвучное вертикальное видео и очистку источника на ПК/телефоне, а также
лайк видео/комментария, подписку и публикацию комментария.
Все 27 сценариев действий в Chromium прошли на итоговом коде.
Шесть unit-сценариев ID/медиассылок/подписей/времени прошли. Повторная проверка
оболочки Chromium после нового layout — 42 сценария прошли.
Полная визуальная приёмка до 2 CSS px для просмотра ещё не выполнена.
Генерация Hey API, vue-tsc/Vite build, ESLint, Prettier, Ruff/форматирование
вспомогательных fixture и локальные ссылки документации проверены в Docker.
Vite сообщает о размере отдельного chunk просмотра с полной hls.js более
500 кБ; начальный chunk главной не содержит плеер. Общий `make check` остаётся
до завершения выполняемого плана по проектному скиллу.

## Лайки, подписка и обсуждение

`features/video-like` хранит серверное состояние в Query; PUT задаёт целевой
`liked`, ожидающий запрос блокирует повтор. Счётчик/состояние меняются после
подтверждения, ошибка сохраняет прежнее значение. Гость переходит ко входу
с возвратом к текущему видео; действие после входа не отправляется автоматически.
Незавершённый GET отменяется перед командой, неактивный снимок не сохраняется;
ошибка CSRF отделена от потери доступа. Фокус кнопки при ожидании сохраняется.
Проверки гонок, ошибок и смены зрителя — [F15](video-likes.md).
`features/subscribe-channel` работает так же через B07, скрывает подписку
на собственный канал и не показывает отсутствующие в контракте счётчики/колокольчик.
Согласованность с каналом, гонки, ошибки, фокус и независимость private-доступа
проверены в [F19](subscriptions.md): по 38 проверок Chromium/Firefox.

`widgets/discussion` доступен только у public-видео. Бэкенд определяет право
записи, авторов, порядок и cursor по 20. Исходный порядок — новые сначала;
популярность сортируется сервером по всему обсуждению. После лайка при popular
список запрашивается заново; страницы не переставляются локально.
Бесконечная прокрутка дополнена кнопкой продолжения/повтора, повторившиеся ID
на границе страниц не дублируются на экране.

Форма, ошибки, безопасность текста, очистка всех сортировок и поздние ответы
проверены в [F16](comments.md): по 52 проверки Chromium/Firefox. Неактивный
снимок обсуждения не сохраняется; CSRF отделён от потери доступа.
Переход в private закрывает обсуждение, сохраняя владельцу плеер.
Лайки комментария и чтение списка координируются общим блоком обсуждения;
параллельные команды, ошибки, фокус и серверный порядок проверены в
[F17](comment-likes.md): по 38 проверок Chromium/Firefox. F16 после изменений
повторно прошёл по 52 проверки в обоих браузерах.
Ответы, дизлайки, удаление и редактирование не добавляются.

Проверки действий: установка/снятие и отказ лайка видео/комментария и подписки,
двойное нажатие, гость/собственный канал, 2000/2001 и пробелы, DOM-инъекция,
ошибка публикации, настоящие cursor-страницы и popular, поздний ответ другого
видео, недоступность private-обсуждения и действия на телефоне. Публичный
канал проверен в [F18](channel-page.md), подписка — в [F19](subscriptions.md).
Утрата доступа дополнительно проверена в [F33](access-lifecycle.md).
Полное визуальное сходство проверяет пользователь.

## Повторить проверку

Нужен работающий dev: `make frontend-dev`. Образ браузеров собирается командой
из [описания основы](implementation.md#повторить-браузерные-проверки).
В Firefox образ устанавливает системный `libavcodec59` для AAC.

```bash
mkdir -p /tmp/frontend-media /tmp/frontend-browser-results
docker run --rm --network youtube_default --user "$(id -u):$(id -g)" \
  --volume "$PWD/docker/browser:/checks:ro" \
  --volume /tmp/frontend-media:/media --entrypoint node \
  youtube-node /checks/download-media.mjs
```

Запустить fixture в отдельном терминале, оставив его работающим:

```bash
./docker/run dev run --rm --no-deps -T --name youtube-frontend-watch-api \
  --volume "$PWD/docker/browser:/checks:ro" \
  --volume /tmp/frontend-browser-results:/work \
  --volume /tmp/frontend-media:/media:ro \
  python python /checks/fixture.py --media
```

В другом терминале создать временный Nginx и выполнить проверки:

```bash
./docker/run dev run --rm --no-deps -d --name youtube-frontend-watch-gateway \
  --volume "$PWD/docker/browser/watch-nginx.conf:/etc/nginx/frontend-watch.conf:ro" \
  nginx -c /etc/nginx/frontend-watch.conf -g 'daemon off;'
docker run --rm --network youtube_default --user "$(id -u):$(id -g)" \
  --volume "$PWD/docker/browser:/checks:ro" \
  --volume /tmp/frontend-browser-results:/work --workdir /checks \
  youtube-browser-check /checks/watch.mjs
docker run --rm --network youtube_default --user "$(id -u):$(id -g)" \
  --volume "$PWD/docker/browser:/checks:ro" \
  --volume /tmp/frontend-browser-results:/work --workdir /checks \
  youtube-browser-check /checks/interactions.mjs
docker run --rm --network youtube_default --user "$(id -u):$(id -g)" \
  --volume "$PWD/docker/browser:/checks:ro" \
  --volume /tmp/frontend-browser-results:/work --workdir /checks \
  youtube-browser-check /checks/firefox.mjs --watch
```

Затем `docker kill --signal=SIGINT youtube-frontend-watch-api`: fixture удаляет
свои данные и завершает контейнер. Дождаться сообщения об очистке и выполнить
`docker stop youtube-frontend-watch-gateway`. Внешние порты не публикуются.

Основной плеер сообщает позицию с ревизией зрителя для гостевого и серверного
сохранения. При выходе позиция аккаунта не попадает в гостевые данные;
запись и полосы аккаунта подключены — [R18](hover-preview.md).
