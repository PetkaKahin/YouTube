# Лайки видео

F15 — `done` по функциональному профилю Chromium/Firefox. Кнопка использует
[B29](../backend/video-likes.md), общий экран и обычный доступ —
[F12](watch-access.md). Внешний вид проверяет пользователь; снимки не делаются.

## Поведение и состояние

[VideoLike](../../frontend/src/features/video-like/ui/VideoLike.vue) получает
`liked`, `like_count`, `can_like` через Hey API. Серверное состояние принадлежит
Query, ключ включает область сессии и точный ID видео. Гость видит общий счётчик
и переходит ко входу с текущим URL в returnTo. После входа команда автоматически
не выполняется. Автор также может поставить лайк собственному видео.

PUT содержит только целевой bool `liked`. Кнопка показывает подтверждённое
состояние до ответа; повторные нажатия при ожидании игнорируются. `aria-pressed`
описывает выбор, `aria-busy` и `aria-disabled` — ожидание. При отправке фокус
сохраняется на кнопке, поэтому повторное действие с клавиатуры не требует
искать её заново. Ожидание не подменяет право `can_like`.

Перед командой отменяется незавершённое чтение того же ключа; автоматическое
чтение приостановлено до окончания команды. Затем состояние вновь сверяется
с сервером. Старый GET не перезаписывает подтверждённый результат PUT.
Сетевая ошибка или 5xx не создаёт локального успеха; можно повторить действие.
Подробности серверной ошибки не вставляются в DOM. Отказ `csrf_failed` сообщает
о необходимости обновить страницу и сохраняет разрешённое видео с прежним
лайком. Он отделён от отказа обычного доступа.

При уходе отменяется чтение, неактивный снимок Query не сохраняется. Уже
отправленная небольшая команда продолжает ждать подтверждение после SPA-перехода:
если зритель прежний, результат обновляет его выдачу liked, даже когда исходная
кнопка размонтирована. Кнопка другого видео не получает старый результат или
ошибку. Живая операция отменяется при смене области; любой поздний ответ отдельно
проверяет scope перед изменением Query. ID/область фиксируются до отправки,
неподтверждённый результат не объявляется успехом. [Приёмка R19](library.md).

401 использует общую очистку сессии; отказ доступа GET/PUT убирает метаданные,
плеер и счётчик через экран просмотра. Лайк не открывает private. Приглашённый
может лайкнуть доступное private, но гость/посторонний не видит его счётчик.
Смена видимости не удаляет прежние лайки; агрегат остаётся серверным.

R21 подключает дизлайк к тому же Query и объединяет кнопки —
[актуальная реализация и проверка](video-reactions.md). Ниже — исторический
профиль F15 и общие правила обработки like.

## Проверки

В Docker прошли vue-tsc/Vite build, ESLint и Prettier изменённого компонента.
Chromium и Firefox выполнили по **36 функциональных проверок**.
[video-likes.mjs](../../docker/browser/video-likes.mjs) выполняет профиль через
реальные API/PostgreSQL/Valkey/Nginx/RustFS и отдельную fixture `--media`.
Успешные ответы не подменяются. Прокси вводит только задержки, 503, разрыв
соединения и удаление CSRF-заголовка. Смена видимости, вход/выход, чтение и запись
лайков выполняются настоящим API. У искусственных HTTP-ошибок есть no-store.

Проверяются:

- Гостевой ноль, вход с возвратом без автоматического лайка, собственное видео,
  установка/снятие, перезагрузка и независимый вклад нескольких зрителей.
- Быстрые нажатия с одной командой, ожидание без ложного успеха, точный int64
  в URL и единственное поле `liked`; счётчик после снятия остаётся нулевым.
- Задержанный GET одновременно с PUT, начальная/фоновая ошибка чтения и повтор,
  503 и сетевой отказ команды с проверкой неизменности серверного состояния.
- Настоящие CSRF 403, 401 после выхода вне UI и 404 после отзыва доступа;
  закрытое видео не оставляет счётчик или плеер. Ошибочный HTML не исполняется.
- Поздние чтение, успех и ошибка после перехода; выход/смена аккаунта до ответа;
  отсутствие неактивного снимка и чтение реально принятой команды при возврате.
- Приглашённый private и отсутствие гостевого доступа; клавиатура, фокус
  и доступная подпись на ширине телефона. Chromium проверяет эмуляцию касания,
  Firefox — Enter и Space без повторного фокусирования.

Запуск fixture/gateway — как в [профиле загрузки](upload.md#проверки),
с `--media` вместо `--upload`. Затем выполнить:

```bash
docker run --rm --network youtube_default --user "$(id -u):$(id -g)" \
  --volume "$PWD/docker/browser:/checks:ro" \
  --volume /tmp/frontend-browser-results:/work --workdir /checks \
  youtube-browser-check /checks/video-likes.mjs
```

Для Firefox добавляется `--firefox`; профили запускаются последовательно,
поскольку меняют общие тестовые лайки/видимость. Каждый запуск сбрасывает только
состояние изолированной fixture. Пароли/cookie не записываются в результаты.

Свободного текста или нового парсера в команде нет; SQL/пути/лимиты исходного
видео остаются ответственностью готового B29 и не перепроверяются полным
серверным набором. Общий `make check` отложен до конца плана. Safari/WebKit
и физический телефон не квалифицированы; мобильная эмуляция их не заменяет.
