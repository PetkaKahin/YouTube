# Публичная страница канала

F18 — `done` по функциональному профилю Chromium/Firefox, с готовым
[B06](../backend/channel-page.md). [Канал и состав плейлиста](channel-playlists.md)
описывает маршруты и композицию. Подписка проверена отдельным [профилем F19](subscriptions.md),
состав — отдельным [профилем F20](playlist-contents.md).
Внешний вид проверяет пользователь, снимки не делаются.

## Запросы и жизненный цикл

[ChannelPage](../../frontend/src/pages/channel/ui/ChannelPage.vue) ждёт
подтверждённой сессии, включая подтверждённого гостя, перед запросом профиля
и списков. Ожидание и ошибка определения аккаунта имеют собственные состояния;
повтор проверяет сессию, затем получает данные канала. При её ошибке прежний
профиль и карточки убираются.

Query владеет профилем и двумя cursor-списками. Ключи включают область сессии,
канонический тег и для списков — ID подтверждённого канала. Функции запросов
берут тег/ID из своего ключа, не из изменившегося URL или текущего профиля.
Видео и плейлисты проверяются на принадлежность этому ID; неверный DTO
не показывает карточки другого канала под правильной шапкой.

Ключ невыбранной выдачи переключается на пустой контекст. Одного enabled=false
недостаточно: наблюдатель иначе сохраняет прежний снимок. После смены ключа
старый запрос перестаёт наблюдаться и удаляется через gcTime 0. При возврате
на вкладку, в том числе через Back/Forward, показывается загрузка до свежего
ответа. Выбор состава плейлиста также отключает контекст каталога; закрытие
состава заново читает список. Профиль после ухода тоже не сохраняется в кэше.

Незавершённые запросы используют AbortSignal, поздние ответы не заменяют новую
вкладку или другой канал с таким же именем. Ошибка профиля убирает его списки;
ошибка чтения списка сохраняет только правильную шапку и рабочий повтор.
Ошибка следующей страницы сохраняет подтверждённую часть и повторяет cursor.
ID остаются точными строками, порядок сервера и дедупликация сохраняются.

## Публичный интерфейс

`/@tag` и `.../videos` открывают видео, `.../playlists` — public-плейлисты.
Регистр тега не меняет канал; имя не служит идентификатором. Профиль показывает
реальные имя/тег и первую букву в аватаре. Доступны только две вкладки ТЗ,
без придуманных метрик, баннера и редактирования профиля.

Свой канал остаётся обычным публичным каналом: ни владелец, ни приглашённый
не получают private/hidden/draft/неготовые видео в каталоге. Private/unlisted
плейлисты там также отсутствуют; управление находится в Studio. Новый канал
после регистрации показывает настоящие пустые списки. Права отдельных видео
при этом сохраняются: приглашение может разрешать прямой просмотр без появления
карточки на публичной вкладке.

Видео ведёт к обычному просмотру по точному ID. Плейлист открывает существующий
состав на своём канале, прямые `/playlist?list=...` сохраняют прежнее разрешение
канала по Q49. Текст заголовков остаётся текстом Vue. Точные URL вкладки,
выбранного состава и заголовок документа восстанавливаются при навигации.

## Проверки и повтор

В Docker прошли vue-tsc/Vite build, ESLint и Prettier изменённого ChannelPage.
Chromium и Firefox выполнили по **49 функциональных проверок**.
После изменения обработки отказа состава в F20 профиль повторно прошёл
по 49 проверок в обоих браузерах; переходы и вкладки сохранены.
[channel-page.mjs](../../docker/browser/channel-page.mjs) использует fixture
`--media --channel --links`: настоящие API/PostgreSQL/Valkey/Nginx/RustFS,
41 готовое публичное видео и 41 public-плейлист, три канала с одинаковым именем
и разными тегами, закрытые и пустые объекты. Новый пустой канал дополнительно
создаётся регистрацией через API. Рабочие данные не используются.

Проверены ожидание сессии без преждевременного запроса, профиль/тег/заголовок,
две вкладки, страницы 20/20/1 по реальным cursor и порядку, ошибка продолжения
обоих списков, повторы, отсутствие дублей, public-фильтрация для гостя/владельца/
приглашённого, прямое разрешение private без появления на канале, пустые списки,
новая регистрация и совпадающие имена. HTML-подобные заголовки настоящих видео
и плейлистов остаются текстом; детали ошибки не исполняются.

Проверены удаление старого ключа при смене вкладки, отсутствие карточек до
нового ответа, поздние профиль/список, ошибка сессии/профиля/выдачи и повтор,
некорректный DTO чужого канала, Back без вспышки карточки после реальной смены
public → private (MutationObserver), Forward/reload, регистр и неверный тег,
точные переходы к просмотру/пустому составу, закрытие состава, прямой unlisted
и отказ private без чужих метаданных. На ширине телефона вкладка и состав
открываются с клавиатуры. Скриншоты и сравнение геометрии не выполняются.

Прокси вводит задержки, 503 и два ошибочных DTO с чужим ID канала; эти DTO
проверяют защиту клиента и не выдаются за ответы исправного сервера. Остальные
успешные ответы, пагинация, регистрация, права, Cookie/CSRF и смена видимости
настоящие. В отчёт не записываются cookie/пароли или содержимое объектов.

Запуск — как [профиль загрузки](upload.md#проверки), с `--media --channel --links`
вместо `--upload`; браузер channel-page.mjs, Firefox — `--firefox`. Профили
запускаются последовательно; SIGINT fixture удаляет её БД, сессии и объекты.
Новых библиотек, контрактов и изменений бэкенда нет. SQL/сбои хранилищ остаются
проверками B06, здесь проверяется браузерный результат после отказов HTTP.
Профиль канала не принимает текстовых форм, файлов или внешних назначений.
Safari/WebKit и настоящий телефон не квалифицированы; общий `make check`
остаётся до конца плана. Подписка проверена отдельно в F19, права элементов
плейлиста — в F20.
