## Подсветка и оформление

Источник среднего RGB остаётся единственным — кадр основного VideoPlayer.
WatchPage передаёт цвет также оболочке через узкий provide/inject-контракт
[watch-appearance](../../frontend/src/shared/lib/watch-appearance.ts). Состояние
находится в app, загруженные кадры в него не попадают. AppShell получает только
цвет для хедера; не импортирует страницу и не читает её DOM. Оба градиента
используют одну силу подсветки. Источник защищён владельцем/scope/video_id;
уход/смена видео/доступа и отключение подсветки убирают также цвет хедера.
Открытие мобильного поиска не сбрасывает цвет паузы.

Исправление по замечанию пользователя 2026-11-18: в SCSS правило
`masthead--ambient` перенесено после базового фона `.masthead`. Раньше следующий
`background` перекрывал градиент при правильных RGB/class. Проверка только
переданного цвета этого не обнаруживала; теперь проверяется также фактический
`getComputedStyle(header).backgroundImage` и его RGB из декодированного кадра.

Кнопки сохранения/действий увеличены до круглых 48px; лайк использует капсулу,
плеер — отдельные полупрозрачные группы play/volume/time и правых контролов
по новому снимку. Для телефона размеры уменьшаются. Главы, рекламные кнопки,
новые режимы и фиктивная кнопка «Поделиться» из полного YouTube не добавляются.
Дизлайк и объединение реакций подключены — [реализация](video-reactions.md).

## Выпадающий выбор плейлиста

[AnchoredDropdown](../../frontend/src/shared/ui/AnchoredDropdown.vue) размещает
панель рядом с закладкой через Teleport и обычные координаты viewport. Нет
showModal, backdrop, aria-modal и блокировки фона. Панель выбирает место сверху/
снизу и ограничивает ширину/высоту текущим экраном; пересчитывается при scroll,
resize и изменении высоты содержимого. ResizeObserver/слушатели снимаются при уходе.

Клик снаружи, повтор кнопки, Escape и Tab из панели закрывают список. Escape и
кнопка закрытия возвращают фокус к закладке; Tab/клик на другое поле сохраняют
его фокус. Tab не заперт в панели. Создание нового плейлиста
сохраняет отдельную форму dialog; пока она открыта, dropdown не перехватывает её
Escape/фокус/внешний клик. После создания возвращается прежний выбор с новым
selected. Неподтверждённое сохранение не считается успехом, выбранные строки и
сессионный Query работают как в [R20](watch-enhancements.md).

## Автозапуск

Обычный watch явно включает autoplay у VideoPlayer. При первом canplay источника
вызывается play со звуком; попытка привязана к поколению/жизненному циклу плеера.
При разрешённой браузером политике прямое открытие и переход между видео запускают
текущий ролик. Старый источник останавливается и освобождается. Ручная пауза не
приводит к повторной автоматической попытке на следующем canplay.

NotAllowedError/AbortError не выдаются за сломанное видео или успешный запуск.
При запрете браузера остаётся кнопка ручного запуска. Принудительный скрытый mute и обход браузерной политики не добавляются.
Продолжение по сохранённой позиции отдельно запрошено после R21 — [реализация](resume.md). Плеер сотрудников opt-in не получает: у него нет autoplay по умолчанию.
Повтор после сбоя/пересборка качеств сохраняют существующие позицию и паузу/игру.

## Проверки

[watch-refinements.mjs](../../docker/browser/watch-refinements.mjs) использует
настоящий API/HLS и изолированную fixture `--media --links --channel --session`
по [инструкции runtime](upload.md#проверки). Для Firefox добавить `--firefox`.
Обычный режим проверяет реальный запрет автозапуска; `--autoplay-allow` отдельно
разрешает его только в тестовом профиле браузера (Chromium launch flag, Firefox
profile preference), без изменения приложения. Проверки идут последовательно.
Успешное сохранение/создание, cursor, права и сессия настоящие; 503/задержка/
снятие CSRF вводятся прокси. Скачанные материалы не заменяются генерацией.

Новый профиль прошёл: Chromium — **48**, Firefox — **47** проверок. Разница —
CDP-эмуляция reduced-motion только в Chromium. В каждом браузере дополнительно
прошли **4 проверки** режима `--autoplay-allow`: реальный старт со звуком по
прямому адресу, автоматический старт нового SPA-видео с очисткой прежнего
источника, сохранение ручной паузы и очистка хедера/плеера при уходе.

В основном профиле проверены обычный запрет автозапуска, не модальный dropdown,
расположение в viewport, pointerdown снаружи и Escape с возвратом фокуса,
прежние сохранение/создание/продолжение/ошибки/CSRF/права/сессия из R20,
синхронный RGB хедера и страницы, очистка скрытой вкладки и телефон.
Тесты не сравнивают внешний вид кнопок/иконок по браузерам. Реакции и исправление
слоя меню квалифицируются отдельным [профилем](video-reactions.md).

Сборка vue-tsc/Vite, ESLint/Prettier изменённых исходников и синтаксис
браузерного профиля/помощников прошли в Docker. После готовности дизлайка SDK
повторно получен из OpenAPI; реакции и слои меню дополнительно прошли по 30
проверок обоих браузеров. [Результаты](video-reactions.md).
Регрессия прошла в обоих браузерах: контролы плеера — по **38**,
действующий лайк — по **36** проверок. Итоговый профиль после уточнения передачи фокуса прошёл: 48/47 проверок,
включая сохранение фокуса при уходе в другое поле. Проверки документов и
`git diff --check` прошли; тестовое окружение очищено. Дизлайк подключён к готовому API, без localStorage/фиктивных ответов;
[итоговый профиль реакций](video-reactions.md). Safari/WebKit
и физический телефон не квалифицированы; общий make check остаётся до конца
плана F01–F04. Бэкенд приложения и библиотеки не менялись.

Для регрессии чёрного хедера профиль `watch-refinements.mjs
--ambient-header-only` использует ту же fixture и реальный HLS. До исправления
падает на итоговом фоне при корректном RGB; после исправления в Chromium и
Firefox прошли по **9 проверок**: итоговый градиент на ПК/телефоне, пауза,
перемотка, скрытие/возврат вкладки, уход и следующее видео, отсутствие runtime
ошибок. Скриншоты не создаются. Повторные сборка/типы, ESLint/Prettier AppShell
и формат/синтаксис профиля прошли в Docker.
