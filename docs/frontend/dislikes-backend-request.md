# R21: дизлайк видео — требования к бэкенду

Статус: бэкенд реализован, миграция 0028 применена в dev; методы и DTO доступны
в его OpenAPI. Фронт может получить типы через Hey API и подключить кнопку.
Поведение согласовано пользователем 2026-11-18.
[Реализация и 27 профильных проверок](../backend/video-dislikes.md).
Клиент сгенерирован, рабочая кнопка подключена — [фронтенд](video-reactions.md).

## Согласовано

Дизлайк без публичного счётчика. Лайк и дизлайк взаимоисключаются: установка одного
атомарно снимает другой. Повторное нажатие выбранной кнопки снимает реакцию.
Гость идёт на вход с возвратом, без автоматического применения после входа.
Реакция не даёт доступа к видео и не влияет на порядок главной/подписок.
Дизлайки комментариев и персональные рекомендации не добавляются.

## Совместимый HTTP-контракт

Сохранить GET/PUT `/api/v1/videos/{id}/like` и тело PUT `{liked: boolean}`.
Добавить в их LikeResponse обязательные `disliked: boolean` и `can_dislike: boolean`;
существующие `liked`, `can_like`, `like_count` остаются. GET гостя по доступному
public возвращает оба выбора false, обе возможности false и публичный like_count.

Добавить PUT `/api/v1/videos/{id}/dislike`, тело `{disliked: boolean}` со строгим bool.
Ответ — тот же полный LikeResponse. Публичного или персонального числа дизлайков
в DTO нет; отдельный GET не требуется. Сессия/CSRF и точные int64 прежние.
Ответы персональные `Cache-Control: no-store`, `Vary: Cookie`.

| Команда | Результат |
| --- | --- |
| liked=true | liked=true, disliked=false |
| disliked=true | liked=false, disliked=true |
| liked=false | Снимает только лайк, текущий дизлайк сохраняется |
| disliked=false | Снимает только дизлайк, текущий лайк сохраняется |

Повтор целевого состояния идемпотентен. При переходе like→dislike счётчик лайков
уменьшается один раз; dislike→like увеличивается один раз. Счётчик неотрицателен
и соответствует активным лайкам после commit. В R19 liked больше не возвращается
видео с дизлайком. Возврат к лайку считается новой активной отметкой с новым
временем; повтор true не поднимает запись. Другие пары/видео не меняются.

Нужна единая сериализация конфликтующих команд одной пары и атомарное изменение
выбора/счётчика. Внутренняя схема хранения — решение бэкенда; две независимые
записи без запрета одновременной активности не обеспечивают инвариант.

## Права, ошибки и приёмка

Обычные права просмотра: public или доступное private, published/visible/ready.
Участник своего/разрешённого private может реагировать. Модератор/admin не обходит
просмотр. draft/hidden/неготовое/отозванное — общий 404 без счётчика/выбора.
Сохранённая реакция не открывает медиа и не удаляется только из-за временной
недоступности. Гость PUT — 401; CSRF — прежний 403 csrf_failed; неверное тело — 422.
Нет actor_id/role из тела, утечек чужого выбора и частичного успешного ответа.

Проверить none/like/dislike и все переходы, повторы/снятие другой реакции,
параллельные like/dislike одной пары, точный счётчик и откат при сбое,
изоляцию аккаунтов/публикаций, отсутствие публичного dislike_count, GET без записи
истории/прогресса, CSRF/401/404/422, SQL-ввод, сбой БД, отзыв прав под блокировкой,
совместимость старого PUT like и выдачи R19 liked/её хронологии. Обновить OpenAPI.
