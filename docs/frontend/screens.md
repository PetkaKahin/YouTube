# Экраны

Статус: экраны ТЗ и [задач F01–F33](../tasks/frontend/README.md) реализованы,
включая личные разделы, Studio, модерацию и ошибки заданий.
Маршруты и текущее покрытие — [реализация](implementation.md),
[итоговая приёмка](final-acceptance.md), [просмотр](watch.md),
[канал и плейлисты](channel-playlists.md), [Studio](studio.md),
[загрузка видео](upload.md), [свои видео и настройки](video-settings.md).
Публичный UI и наблюдаемое поведение повторяют YouTube 1 в 1 в пределах ТЗ.
Для Studio достаточно общего сходства — [ADR-0068](../decisions/0068-studio-visual-scope-and-video-options.md).
Дальнейшие детали UI обсуждаются в ходе разработки; критерии и исключения —
[соответствие YouTube](youtube-parity.md). Ранее согласованный список с галочками
остаётся требованием. Формы входа/регистрации пользователь разрешил оформить
самостоятельно по ТЗ — [ADR-0063](../decisions/0063-frontend-ui-and-reference-scope.md).
Для создания/редактирования своего контента выбрана отдельная Studio по
[ADR-0066](../decisions/0066-studio-playlist-interface.md). Публичный собственный
канал имеет тот же интерфейс, что чужой; управление и закрытые списки туда
не переносятся. F21 завершён по функциональному профилю — [покрытие](studio.md).
Для каждого экрана нужны состояния загрузки, ошибки, пустого результата
и отсутствия доступа, если они применимы. Основные действия доступны с клавиатуры,
полям и иконкам нужны понятные подписи; фокус не теряется при модальных действиях.

## Важные состояния

Дополнение R21: подсветка хедера, выпадающий выбор плейлистов, автозапуск и
согласованный дизлайк — [состояние](watch-refinements.md).

Дополнение R20: справа на watch — главная лента, подсветка по кадрам и закладка
для немедленного сохранения в свои плейлисты, включая создание с видео —
[реализация](watch-enhancements.md).

Дополнение R19: пользователь запросил личные страницы истории, понравившихся,
плейлистов и ленту подписок с раскрытием списка каналов в sidebar.
[Объём и зависимости API](library-backend-request.md), [задача](../tasks/frontend/library.md).
Страницы и sidebar подключены — [реализация и приёмка](library.md).

- **Регистрация:** несовпадающий повтор пароля не принимается; успешная
  регистрация создаёт пустой канал. Проверка тега и ошибка занятого значения
  соответствуют [Channel](../backend/modules/channel.md).
  Длины имени/пароля и проверка email следуют [валидации User](../backend/modules/user.md);
  шага подтверждения почты нет.
- **Имя и тег:** имя из регистрации показывается в названии канала и у автора
  комментария. Повторяющиеся имена допустимы; уникален тег. Правила отображения —
  [User](../backend/modules/user.md), правила тега — [Channel](../backend/modules/channel.md).
- **Просмотр:** загрузка HLS, buffering, ошибка, нет готового качества, приватное
  видео без разрешения, скрытое видео. Недоступность не раскрывает приватные данные.
  Проверка сессии предшествует чтению метаданных; её отказ имеет свой повтор
  и не превращается в гостевой просмотр — [F12](watch-access.md).
  Для приватного видео блок комментариев недоступен по бизнес-правилу.
- **Лайк / подписка:** гость получает переход ко входу. Повторный клик во время
  запроса не создаёт дубликат; оптимистическое обновление, если выбрано, откатывается при ошибке.
- **Загрузка:** процент передачи файла отделён от обработки. Показываются состояния
  исходника и качеств; ошибка высокого качества не маскирует готовое низкое.
  Управление приватными разрешениями находится в этом сценарии и согласованных
  настройках видео в ЛК.
  Владелец вводит email; корректный адрес принимается независимо от наличия
  аккаунта. Форма не ищет и не показывает имя, тег, аватар или статус регистрации
  адресата. Правила — [Video](../backend/modules/video.md). Для приватного просмотра
  достаточно входа в аккаунт с разрешённым email; дополнительного шага
  подтверждения почты нет.
  Видео без аудиодорожки допустимо: форма не требует звук, плеер воспроизводит
  такой файл без звука. Правила аудио по качествам — в [конвейере](../backend/video-pipeline.md).
  Форма сообщает пределы 5 ГБ и 60 минут и показывает серверную причину отказа
  при превышении. Исходник ниже 360p не отклоняется только из-за разрешения.
  Форма не отклоняет файл только из-за отсутствия его расширения в локальном
  списке: допустимость проверяет сервер по содержимому. При окончательном
  частичном сбое показываются готовые и неуспешные качества; при полном сбое —
  причина ошибки, без сообщения о готовности видео к просмотру.
- **Жалоба:** действие находится на экране просмотра доступного видео, запрос
  подтверждается сервером. [Реализована модалка F29](reports.md);
  успех означает приём на рассмотрение, без сообщения о скрытии.
- **Модерация:** обычный пользователь не открывает служебный экран; приватный
  контекст жалобы загружается только через разрешённый служебный сценарий;
  [очередь и решения](moderation.md) используют отдельные маршруты.
- **Плейлисты в ЛК:** в настройках видео отображается выпадающий список своих
  плейлистов с независимыми галочками. Отмечаются текущие включения видео;
  можно выбрать все или снять все. Снятие галочки исключает видео только из
  соответствующего плейлиста. При сохранении/ошибке UI показывает фактический
  результат, не выдавая неуспешное сохранение за успешное.
  Форма создания содержит обязательное название, необязательное описание
  и режим плейлиста: публичный, по ссылке или приватный (только владельцу).
  Списка email у плейлистов нет. Доступ по email сохраняется у приватных видео.
  Новое видео добавляется в конец; ручной перестановки нет.
  Разрешение на плейлист не открывает приватные видео внутри него;
  недоступные данные не раскрываются. Расположение формы и элементов
  реализовано в [Studio](studio.md) по согласованным референсам.

Общая оболочка содержит переходы только к реализуемым экранам. Поиск доступен
из оболочки. Состав плейлиста показывается на канале с переходом к существующему
просмотру. Пользователь также согласовал ЛК с настройками видео и создание
плейлистов в отдельной Studio. В шапке перед аватаром находится «Создать»
с переходами к загрузке и созданию плейлиста; [реализация](video-settings.md#создать-в-шапке).
Отдельное быстрое создание с включением видео доступно из закладки watch по
[R20](watch-enhancements.md).

## Проверка соответствия

После согласования референсов проверять геометрию, типографику, цвета, сетку,
плеер, формы, переходы и все применимые состояния взаимодействия на ПК и телефоне.
Одной статичной картинки недостаточно. Не добавлять кнопки YouTube, для
которых ТЗ не предусматривает действия. Размеры, браузеры и язык — [Q07](../tasks/open-questions.md).
