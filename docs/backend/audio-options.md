# Q03: сравнение аудиокодеков

Статус: исследование на 2026-11-13; после сравнения пользователь выбрал AAC-LC
ради совместимости — [ADR-0041](../decisions/0041-aac-lc-audio.md).
Приоритеты — сжатие, малозаметные потери и разумные затраты.
AV1 для видео выбран в [ADR-0039](../decisions/0039-av1-encoding.md).

## Кандидаты

| Вариант | Основание рассматривать | Ограничения для проекта |
| --- | --- | --- |
| AAC-LC | Предусмотрен Apple для HLS; встроенный `aac` есть в нашем FFmpeg | Не является безусловным лидером качества при низком битрейте |
| Opus | Сильный кандидат на сжатие речи и музыки; `libopus` уже есть в образе | HLS.js поддерживает Opus в fMP4 при поддержке браузером; в перечне аудиокодеков Apple HLS Opus отсутствует |
| HE-AAC v1/v2 | Варианты AAC для низких битрейтов; предусмотрены Apple HLS | Apple не рекомендует HE-AAC выше 64 кбит/с; `libfdk_aac` отсутствует в текущем образе, для этого кодировщика нужна отдельная сборка |
| xHE-AAC | Разработан для адаптивного потока, включая очень низкие битрейты | Кодировщика в текущем образе нет; нужна отдельная интеграция. Для совместимого Apple HLS всё равно требуется дорожка AAC/HE-AAC |

У Opus есть основание ожидать лучшее качество на ограниченном битрейте:
в публичном слепом тесте 2014 года с целевой скоростью 96 кбит/с он опередил
Apple AAC. Это исторический результат конкретных кодировщиков и тестовых
записей, а не измерение нашего FFmpeg и не фиксированный процент экономии.
Сводная диаграмма разработчиков Opus также не предназначена для извлечения
точных значений качества или выигрыша.

Нельзя утверждать, что Opus несовместим с HLS вообще: воспроизведение через
MSE-плеер и нативный HLS — разные пути. HLS.js здесь приведён как пример
публично документированной поддержки, а не выбранная библиотека фронтенда.
Наличие Opus-декодера в браузере само по себе не подтверждает работу всей
связки AV1 + Opus + HLS на конкретном устройстве.

## Проверка текущего образа

В Docker `youtube-bootstrap-python` проверены версия, список кодировщиков
и справка `ffmpeg -h encoder=aac` / `ffmpeg -h encoder=libopus`.
Установлен FFmpeg `7.1.5-0+deb13u1`; доступны встроенный `aac`, `libopus`,
`libvorbis`, `libmp3lame` и `flac`. Кодировщиков `libfdk_aac` и xHE-AAC нет.
Новые зависимости не устанавливались.

Замеры скорости/CPU/размера на представительном аудио, прослушивание качества
и браузерные проверки HLS не проводились. Наличие кодировщика не означает
готовность или проверенную совместимость медиаконвейера.

## Результат выбора

Opus — кандидат с упором на эффективность сжатия; пользователь предпочёл
AAC-LC ради совместимости HLS и снижения сложностей воспроизведения.
Выбор принят в ADR-0041. Пользователь также согласовал максимум стерео
с сохранением моно. Битрейты согласованы в
[ADR-0042](../decisions/0042-audio-bitrates.md); моно всегда вдвое ниже стерео.
Там же согласованы 48 кГц для всех качеств и режим CBR встроенного `aac`
через `-b:a`, без VBR по параметру качества.
Качество и затраты на реальном материале ещё не измерены.
