# Поиск видео, каналов и плейлистов

Реализован общий GET `/api/v1/search` по согласованным
[бизнес-правилам](../project/search.md) и [ADR-0057](../decisions/0057-simple-search.md).
Завершены B24/B25: плейлисты подключены к ранее готовым видео/каналам.

## Контракт

`q` — буквальная подстрока без учёта регистра, 1–100 символов после trim;
пустой запрос отклоняется. Видео ищется по названию, канал — по имени/@тегу,
плейлист — по названию. Email, описания и текст субтитров не участвуют.
%, _, !, обратная косая черта, SQL/HTML/path/URL остаются данными.

Необязательные параметры:

- `type=video|channel|playlist`; без type смешиваются все три типа.
- `sort=created|updated`, по умолчанию created; новые сначала.
- `duration=short|medium|long`, границы ровно 3/20 минут входят в medium.
- `period=today|week|month|year`, календарные начала Europe/Moscow.
- Повторяемый `feature=hd|4k|hdr|subtitles`, сочетание через «И».
- `cursor` для продолжения выдачи по 20 результатов.

Видео — только public/published/visible с готовым вариантом, независимо от
сессии и email-разрешений. Признаки проверяются по одному доступному варианту:
4K+HDR требует 2160p HDR; subtitles — группу WebVTT в актуальном master.
Готовность и применимые фильтры проверяются до заполнения страницы/lookahead.
Каналы и плейлисты игнорируют duration/feature; содержащиеся видео для этого
не читаются и не используются как агрегированные признаки.

Плейлисты — только public, включая пустые. Private/unlisted исключаются
в SQL до limit/lookahead для гостя, владельца и staff. Известная ссылка или
право на видео не делают плейлист обнаружимым. Поиск не читает состав,
не выдаёт число видео, превью содержимого или права на входящие публикации.
[Просмотр плейлиста](playlists.md) проверяет доступ к каждому видео отдельно.

Ответ `items/next_cursor`: элементы с type и соответствующим полем video,
channel либо playlist; остальные поля null, next_cursor явно null в конце.
Video — карточка [главной](feed.md). Channel — id/name/tag/created_at/updated_at;
пока профиль не редактируется, updated_at=created_at. Playlist содержит
id/title/description/created_at/updated_at и публичный channel(id/name/tag).
Нет total, email, ролей, owner_id, служебных ключей или прямых RustFS URL.
Ответы no-store/Vary Cookie; кэш прав или результатов не вводится.

Неизвестное значение/повтор одиночного параметра/повреждённый cursor дают общий
422 без отражения ввода. Неизвестные query-поля игнорируются как в остальном API.
Сбой любого источника даёт общий 500 без частичных результатов и изменений.
Поисковый текст/cursor не записываются в access-журналы приложения и Nginx.

## Даты и курсор

Сортировка: дата DESC, тип video → channel → playlist при равной дате, затем id DESC.
Для created используется завершение загрузки видео, создание канала/плейлиста;
для updated — фактическое изменение владельцем. Изменение состава плейлиста
меняет updated_at, повторное сохранение того же состава — нет.
Период всегда фильтрует дату создания/добавления, включая sort=updated.

Курсор содержит версию, дату/тип/id границы, исходный момент календарного периода
и SHA-256 нормализованного запроса/параметров. Версия 1 и старые коды video=1,
channel=0 сохраняют смысл; playlist=2. Ранг типа хранится отдельно от кода:
при переходе источников сравнивается порядок типов, а не числовой код.
Поддельные переполнения календаря отклоняются до SQL. Курсор не предоставляет
прав, не подписывается, не содержит текст запроса; смена фильтров отклоняется.

Окно МСК фиксируется первым запросом, включая его текущий момент; полночь
не сдвигает продолжаемую выдачу. Исторического снимка данных нет: видимость
и готовность проверяются заново, скрывшиеся результаты исключаются и на
следующей странице. Правки сортируемой даты могут переместить объект.

## Реализация

БД и зависимости на этом этапе не менялись, используется ревизия 0017.
PostgreSQL читает ограниченные порции кандидатов по 21; общий сценарий
объединяет источники, выдаёт 20 и сохраняет границу последнего результата.
Channel.public.FindChannels/FindPlaylists участвуют в транзакции вызывающего
сценария. Имена авторов читаются пакетно через User.public.GetPublicNames,
без JOIN к чужим таблицам; плейлисты соединяются только с собственным профилем.
Нового поискового сервиса, библиотек, секретов и фоновых задач нет.
