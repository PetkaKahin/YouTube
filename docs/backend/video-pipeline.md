## Ограничения загрузки

Утверждено пользователем:

- Максимальный размер исходного файла — **5 ГБ**, включительно.
- Максимальная длительность — **60 минут**, включительно.
- Превышение любого ограничения отклоняется с понятной причиной; видео
  не обрезается автоматически до допустимой длительности.
- Сервер проверяет реальный размер и длительность. Предварительная проверка
  в форме помогает пользователю, но не заменяет проверку полученного файла.
- Принимаются видеофайлы любых форматов, которые используемая сборка FFmpeg
  может корректно прочитать и обработать. Фиксированного списка разрешённых
  расширений нет; наличие поддерживаемого расширения само по себе не гарантирует
  допустимость содержимого.
- У исходника должна быть видеодорожка; звуковая дорожка необязательна.
  Повреждённый или неподдерживаемый файл отклоняется с понятной причиной,
  произвольные данные не считаются видео только по имени файла.

## Состояния

Не смешивать независимые признаки:

| Признак | Начальная модель |
| --- | --- |
| Передача исходника | pending (черновик до передачи) → uploading → uploaded либо failed |
| Обработка | pending → processing → ready, partial либо failed |
| Отдельное качество | pending → processing → ready либо failed |
| Публикация | draft либо published |
| Видимость | public либо private |
| Модерация | visible либо hidden |

`partial` означает: хотя бы одно качество готово, часть завершилась ошибкой.
При продолжающейся работе состояние остаётся `processing`, но готовые качества
уже могут воспроизводиться. `ready` означает готовность всех запланированных качеств.
В API владельца этот расчёт уже работает по одному SQL-снимку; preview/WebVTT
не блокируют состояния AV-вариантов. Воспроизведение зрителем ещё не подключено.
Для просмотра нужны публикация, разрешение, отсутствие скрытия и хотя бы один
готовый вариант. Повторное кодирование не меняет эти разрешения.

## Путь файла

Направление загрузки выбрано пользователем 2026-11-13: браузер передаёт части
напрямую в RustFS по временным подписанным ссылкам. FastAPI управляет разрешениями
и проверками, не проксирует байты и не вычисляет хеш большого файла в HTTP-запросе.
Согласована дедупликация по доверенному серверному слепку до кодирования
с переиспользованием совместимых готовых результатов. Дедупликация глобальная
для всех аккаунтов, включая HLS/превью; общие готовые результаты хранятся,
пока остаётся хотя бы одна пользовательская ссылка. Оригиналы временные
по [ADR-0040](../decisions/0040-temporary-originals.md).
У публикаций разные медиассылки с независимой проверкой
прав; общий физический объект не даёт общего доступа.
Слепки содержимого исходных дорожек и превью без описательных тегов проверяются
до целевой конвертации. Подтверждённый дубль не кодируется повторно.
Слепок строится по сжатым данным и значимым техническим параметрам с точной
временной шкалой; полное декодирование для сравнения не выполняется.
Не влияющие на воспроизведение описательные теги в постоянные медиа не переносим.
Алгоритм digest — SHA-256, выбрана очередь Procrastinate —
[ADR-0034](../decisions/0034-sha256-and-procrastinate.md).
Направление и границы — [ADR-0030](../decisions/0030-direct-upload-and-deduplication.md)
и [ADR-0031](../decisions/0031-global-shared-media.md). Слепки и общие записи уже
подключены; совместимые готовые HLS-дорожки и превью физически переиспользуются.
Публичные медиассылки и просмотр остаются до B22.

1. Вошедший пользователь выбирает файл, вводит метаданные и явно выбирает видимость.
   Создаётся черновик, связанный с владельцем; клиент показывает прогресс передачи байтов.
2. Исходник попадает в закрытый RustFS. Завершение подтверждается сервером по
   наличию и свойствам объекта, а не только по сообщению клиента.
3. В PostgreSQL сохраняются сведения об исходнике, очередь и состояние заданий.
   Задания нельзя терять при перезапуске или потере Valkey. Для выполнения выбрана
   Procrastinate; параметры выполнения согласованы в ADR-0035.
4. Worker запускает ffprobe: проверяет реальный формат, дорожки, включая субтитры, размеры,
   ориентацию, длительность. Неподходящий файл заканчивается понятной ошибкой.
5. FFmpeg создаёт превью и независимые HLS-варианты. На каждое допустимое качество
   приходится отдельная задача и отдельно сохранённый результат. Сначала минимальное
   качество, затем остальные; обработка выполняется вне HTTP-процесса и его event loop.
6. Готовое качество публикуется только после записи и проверки всего комплекта
   сегментов и плейлиста. Master playlist содержит только готовые варианты.
7. После завершения передачи и сохранения метаданных пользователь подтверждает
   публикацию на том же экране. Если качество ещё не готово, экран показывает
   обработку; воспроизведение открывается после готовности первого варианта.

Ранний просмотр низкого качества и более поздняя готовность HD/4K соответствуют
[справке YouTube](https://support.google.com/youtube/answer/71674?hl=en),
проверенной 2026-11-11. Отдельный прогресс обработки не выдаётся за прогресс загрузки;
если точный процент неизвестен, показываются этапы, без выдуманного числа.

## Качества

Выходной видеокодек — только AV1, кодировщик — SVT-AV1 через FFmpeg,
из обсуждавшихся пресетов 6/8 выбран 6. Настройка не является подтверждённым
пресетом YouTube; причины и границы — [ADR-0039](../decisions/0039-av1-encoding.md).
Для SDR приняты однопроходный CRF и `tune=0`; таблица CRF и приёмка качества —
[ADR-0043](../decisions/0043-sdr-av1-profile.md).
Дополнительного потолка видеобитрейта нет; реальные битрейты готовых
сегментов включаются в HLS — [ADR-0048](../decisions/0048-uncapped-video-crf.md).
FPS ограничен сверху 30 до 480p и 60 от 720p, без повышения меньшей исходной
частоты. Формат — 4:2:0; SDR использует 8 бит для входа до 8 бит и 10 бит
для более разрядного входа. Правила дробных частот и приёмка —
[ADR-0044](../decisions/0044-frame-rate-and-sdr-depth.md).
Оригинал нужен временно для слепка дедупликации и перекодирования,
постоянного архива нет — [ADR-0040](../decisions/0040-temporary-originals.md).
Оригинал удаляется после завершения всех зависимых работ; при ошибке остаётся
для повторов. Ранний просмотр первого качества не разрешает очистку.
Кодирование отдельных дорожек подключено; границы и проверка — [AV1/AAC](encoding.md).

Лестница: **360p, 480p, 720p, 1080p, 1440p, 2160p (4K)**.
Для горизонтального 16:9 это 640×360, 854×480, 1280×720, 1920×1080,
2560×1440, 3840×2160. Это ориентиры, а не принудительное растяжение кадров.

- Не повышать исходное разрешение. Вариант создаётся, только если исходник
  после учёта поворота позволяет вписать его без увеличения сторон.
- Сохранять пропорции, поддерживать вертикальное и нестандартное видео без
  обрезки; название качества и расчёт целевого прямоугольника учитывают ориентацию.
- Исходник 1080p не получает 1440p и 2160p; 4K получает всю допустимую лестницу.
- Исходники ниже 360p принимаются. Для них готовится вариант в исходном
  разрешении без увеличения до 360p; в доступных качествах указывается фактическое
  разрешение. Применяется сильное сжатие с сохранением разборчивости изображения
  относительно исходника, без превращения результата в неразличимую картинку.
- HDR, ограничения битрейта, сегменты и ресурсные лимиты
  остаются в технической части [Q03](../tasks/open-questions.md).
  Принятый профиль CRF для SDR проверяется по бизнес-критерию разборчивости
  на примерах исходников.

## Аудио в вариантах видео

Утверждённое правило: для низких качеств видео также снижается качество
аудиодорожки. Вариант низкого качества должен экономить трафик и на видео,
и на звуке; нельзя оставлять во всех вариантах одно исходное тяжёлое аудио.

Уровни аудио утверждены пользователем, Q12 закрыт; уровень 1080p+
добавлен в ADR-0042:

| Качество видео | Уровень аудио |
| --- | --- |
| 360p и ниже | Сильное сжатие, приоритет экономии трафика |
| 480p | Умеренное сжатие, промежуточное качество звука |
| 720p | Обычное качественное аудио |
| 1080p и выше | Повышенный битрейт относительно 720p |

Пользователь уточнил градацию: для 1080p и выше стереозвук — 240 кбит/с;
битрейты остальных профилей приняты. Моно для каждого качества использует
вдвое меньший битрейт, включая 120 кбит/с для 1080p+.
Текущая таблица параметров — [ADR-0042](../decisions/0042-audio-bitrates.md).

Видео без аудиодорожки разрешено загружать и смотреть без звука. Отсутствие
аудио не является ошибкой проверки или обработки и не блокирует публикацию,
если остальные требования выполнены. Уровни аудио применяются при наличии звука.

Аудиокодек — AAC-LC, встроенный кодировщик FFmpeg `aac`; решение и границы —
[ADR-0041](../decisions/0041-aac-lc-audio.md). Выходной звук — максимум стерео:
моно сохраняется, многоканальный звук сводится к стерео.
Выходная частота — 48 кГц для всех качеств; режим CBR через `-b:a`
по таблице ADR-0042, без VBR по параметру качества.
Упаковка — AV1/fMP4, сегменты около 6 секунд и отдельные переиспользуемые
AAC-плейлисты по [ADR-0047](../decisions/0047-hls-packaging.md).
Полный master формирует [адаптер Video](hls.md) по данным готовых дорожек;
техническая проверка AV1/AAC `CODECS`, SDR/PQ, битрейтов и декодирования
через master прошла. [Сборка по результатам worker](readiness.md) подключена;
защищённая зрительская раздача ещё впереди.
Сравнение AAC-LC, Opus, HE-AAC и xHE-AAC, ограничения HLS и проверка наличия
кодировщиков — [варианты аудио](audio-options.md). Кодирование подключено к очереди.

## Субтитры

Утверждено пользователем 2026-11-12: для первой версии используются только
дорожки субтитров, уже встроенные в загруженный видеофайл. Они подготавливаются
для воспроизведения вместе с видео с сохранением временной привязки.
Отдельная загрузка файлов субтитров и автоматическая генерация в этот объём не входят.
Отсутствие субтитров не мешает обработке и просмотру видео.

Выбраны WebVTT для текстовых дорожек и независимая ошибка неподдерживаемой
или повреждённой дорожки. PGS/DVD/DVB без OCR не поддерживаем —
[ADR-0049](../decisions/0049-embedded-text-subtitles.md).
Отдельный [адаптер подготовки](subtitles.md) и общая группа в master реализованы;
постоянные задания и RustFS подключены, сборка публичного master и права ещё впереди.
Фильтр «Субтитры» описан в [правилах поиска](../project/search.md).
Фоновая подготовка дорожек не меняет дату изменения видео, как и кодирование качеств.

## HDR и SDR

Принят принцип двух версий: для поддержанного HDR-исходника готовим HDR
в 10-битном AV1 и SDR в AV1 с тональным преобразованием. Обычный SDR-исходник
получает только SDR. SDR готовится во всей допустимой лестнице, HDR — только
1080p+ без увеличения разрешения. Для HDR принят CRF 28 с preset 6,
одним проходом и `tune=0`. Другие HDR-форматы должны преобразовываться
в обычный HDR, а не отклоняться только из-за отсутствия совместимой базы.
Надёжность, доступ и оставшиеся параметры —
[ADR-0045](../decisions/0045-hdr-and-sdr-versions.md).
Выходной HDR — HDR10/PQ/BT.2020, SDR-версия HDR-исходника — BT.709;
обе версии в 10 бит 4:2:0. Механизм — FFmpeg/libplacebo, BT.2390 и
программный Vulkan Mesa/Lavapipe на CPU, без обязательного GPU.
Технические пробы в dev/prod на Linux/amd64 прошли —
[ADR-0046](../decisions/0046-cpu-hdr-conversion.md).
Преобразование подключено к [кодированию отдельных дорожек](encoding.md);
полная приёмка HDR-профилей и просмотр ещё впереди.

## Признаки готовых качеств

Для поиска HD означает наличие готового качества от 720p, 4K — готового 2160p,
HDR — готовой HDR-версии, доступной зрителю. Проверяется результат обработки,
а не только характеристики исходного файла. Качество в процессе обработки
не включает соответствующий признак. [Канонические правила поиска](../project/search.md).

Критерий HDR утверждён пользователем, Q17 закрыт. Принцип сохранения HDR
и профиль качества/цвета согласованы в ADR-0045, механизм преобразования —
в ADR-0046; это ещё не реализованные бизнес-фильтры поиска.

## Повторяемость и сбои

- Очередь, задания и состояния качеств — в PostgreSQL. Valkey не является
  хранилищем очереди; его потеря не теряет принятую работу.
- Сбой качества повторяет только его задачу. Уже готовые варианты и их
  результаты не пересоздаются из-за ошибки другого качества.
- Временные результаты изолированы идентификатором попытки. Повторное выполнение
  не перезаписывает готовый вариант повреждённым или неполным набором файлов.
- Lease/heartbeat либо другой согласованный механизм обнаруживает погибший worker.
  Число попыток ограничено; параметры согласованы в ADR-0035.
  Каждая ошибка попытки сохраняется в постоянной истории, в том числе перед
  последующим успехом. Требования для будущего административного повторного
  запуска — [диагностика заданий](background-jobs.md).
- Ошибка 4K не закрывает готовое 360p. Если нет ни одного готового варианта,
  воспроизведение не открывается; экран загрузки объясняет сбой.
- Утверждено пользователем 2026-11-12: после окончательного сбоя отдельного
  качества готовые варианты остаются доступны с учётом видимости и модерации.
  Автор видит частичную ошибку на экране загрузки.
- Если после обработки не готово ни одного качества, просмотр не открывается,
  видео не попадает в публичные выдачи, автору показывается понятная причина
  ошибки. Завершённая передача исходника сама по себе не означает готовность видео.
- Скрытие или отзыв доступа во время обработки остаются в силе после её завершения.
- FFmpeg имеет ограничения CPU, памяти, диска и времени; пользовательский текст
  не становится shell-командой. Локальный временный диск не является архивом исходников.

## Защищённая раздача

Исходники и все артефакты находятся в закрытых бакетах. Публичность видео не
означает публичность бакета. Браузер получает медиаданные через проверяемый путь.
API не прокачивает большие видео через обычные JSON-обработчики.

Проверяются master playlist, media playlists, сегменты, init-файлы при их наличии,
превью и подготовленные субтитры. Защита только master playlist недостаточна. Отзыв доступа и скрытие
проверяются на каждом последующем запросе к медиа; кэш не может отменить отказ.
Нельзя кэшировать положительное разрешение без согласованной инвалидации.
