# Главная лента

Реализован API B23 по [ADR-0056](../decisions/0056-feed-cursor-pagination.md).
Пользователь подтвердил cursor-пагинацию; согласованная порция — 20 видео.

GET `/api/v1/videos/feed?cursor=...` доступен гостю и вошедшему пользователю.
Ответ: items и next_cursor (null, когда продолжения нет). Карточка содержит
id/title/added_at/duration_seconds, channel (id/name/tag) и preview_url
готового выбранного превью либо null. Нереализованные счётчики не выдумываются.
Длительность берётся из презентационной шкалы основной видеодорожки плана:
стартовый сдвиг контейнера и невыбранные дорожки не удлиняют карточку.
Видео для владельца/приглашённого также исключается, если оно private.
Лайки, готовность следующих качеств и поздняя публикация не меняют порядок.

Сортировка — added_at DESC, id DESC. Курсор — канонический base64url без padding:
версия 1, точные микросекунды UTC относительно Unix epoch и bigint ID.
Размер следует из бинарного формата, произвольный длинный ввод не разбирается.
Курсор не подписывается: он только выбирает границу; сервер связывает значения
параметрами SQL и заново применяет фильтры. Некорректный/повторяющийся cursor
даёт общий 422 без отражения значения. OFFSET и общее число результатов не нужны.

Добавлен частичный индекс public/published/visible по (added_at DESC,id DESC).
Состояния и проверенные артефакты читаются из Video; фактическая готовность
вычисляется тем же кодом, что для просмотра. Кандидаты читаются ограниченными
порциями, неготовые/повреждённые результаты отбрасываются до формирования
страницы и определения продолжения. Превью не является условием готовности видео.
Публичные данные каналов/имён читаются пакетно через Channel.public/User.public,
без JOIN к чужим таблицам и без N+1. Email/роль/пароль не читаются для карточки.
Неполная связка профиля автора не превращается в частичную карточку.

Ответы no-store/Vary: Cookie; Valkey не хранит страницы или разрешения.
Запрос не читает RustFS, не запускает FFmpeg и не меняет бизнес-состояния.
URL превью принадлежит публикации и проверяет права заново при загрузке.
Транзакция страницы не означает снимок всей ленты между запросами: после
публикации/готовности старого видео оно может появиться ниже текущей границы.

Приёмка: пустая/последняя/полная страница и переходы через 20/21 элемент,
одинаковые даты/микросекунды, поздняя публикация, новые элементы выше границы,
исчезновение граничного видео, свежие private/hidden/отзыв, фильтрация до
пагинации/продолжения, полный AV1/AAC и partial, отсутствие превью, общий файл
с разными правами, отсутствие персональных/служебных данных, подмена/инъекции
cursor, сбои БД/канала и отсутствие кэша/изменений при отказах. Проверки в Docker.

## Реализация и профильные проверки

Код: [курсор и DTO](../../backend/src/video/domain/feed.py),
[сценарий](../../backend/src/video/application/feed.py),
[SQL и адаптер автора](../../backend/src/video/infrastructure/feed.py),
[HTTP](../../backend/src/app/http/feed.py),
[начальная миграция video_publications](../../backend/migrations/versions/0009_video_publications.py).

59 новых проверок прошли в Docker. Границы: 0/1/19/20/21/40/41 видео,
точные микросекунды и одинаковые даты, все страницы без дубликатов,
удалённый граничный объект, новый объект выше курсора, private/hidden/draft/NULL-date,
пустые/повреждённые результаты и обязательный AAC до заполнения страницы.
Приватное видео с email-разрешением открывается зрителю, но отсутствует в ленте;
владелец и staff также не получают его через главную. Отсутствие превью не закрывает
готовое видео. Проверены поздняя публикация и независимость даты добавления.

Для 20 разных авторов и одного lookahead — три SELECT на порцию: Video, Channel,
User. User-запрос выбирает только id/name, без email/role/password_hash.
Часть массовых проверок создаёт ссылки публикаций на один настоящий пакет,
подготовленный FFmpeg; HTTP-проверка cursor выполняет 21 настоящую загрузку.
Используются изолированные БД с миграциями, PostgreSQL/RustFS/Procrastinate.
Ошибки cursor не отражают ввод. Проверены длина, алфавит/padding, версия,
переполнение времени/bigint, инъекции/пути/URL, повтор query-параметра,
сбой чтения профилей и отсутствие частичной/кэшированной страницы после отказа.

Длительность проверяется по выбранной видеодорожке, независимо от стартового
контейнерного сдвига и невыбранных дорожек. Лента не выполняет get_object/head_object;
гость читает её при отказе Valkey. DOM и интерфейс главной остаются фронтенду;
поиск/канал/плейлисты не реализуются этим этапом.

## Итоговые проверки — 2026-11-15

Полная регрессия бэкенда в Docker (2 CPU/8 ГиБ, без дополнительного swap):
**982 passed за 759,73 с**. Ruff/Formatter (209 файлов), Basedpyright,
оба Tach, uv audit (85 пакетов без известных проблем), Compose dev/prod config
и HTTP smoke прошли. Миграция 0016 применена, Alembic check без расхождений.
Приложение и оба worker работают с актуальным кодом.

Сборки dev/prod прошли с UV_OFFLINE=1 из кэша закреплённых зависимостей:
обычные попытки встретили внешний tls handshake eof при запросе hatchling в PyPI.
Временные Dockerfile/Compose override отличаются только включением offline;
постоянный Dockerfile, lock-файл и проверка TLS не изменялись.

Квалификация настоящих Nginx/FastAPI/RustFS в dev/prod прошла с лентой:
карточка появляется при public, исчезает при private, содержит канал и текущий
WebP, корректную длительность (1 с без контейнерного сдвига 5 с), без персональных
или служебных полей. Проверка выполнена после удаления оригиналов и с запрещёнными
get_object/head_object клиента FastAPI. Дополнительно production-квалификация
проверила GetFeed с принудительным отказом Valkey и без pytest.

Аудит Compose Secrets: 12 контейнеров, 78 поверхностей, argv/environment прочитаны
без пропусков, findings=[], status=pass. Проверены тела/заголовки ответов,
безопасные журналы и отсутствие частичных результатов при сбое чтения профилей.

Документы: 122 Markdown-файла, 1203 локальные ссылки ведут на существующие
файлы; якоря отдельно не проверялись. `git diff --check` чистый.
