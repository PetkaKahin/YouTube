# Готовность обработки и сборка master

Реализована внутренняя сборка master по постоянным результатам AV1/AAC/WebVTT
и чтение готовности владельцем. Зрительская выдача подключена в
[B11/B22](media-delivery.md); итоговые проверки отдельного этапа приведены ниже.

Состояние вычисляется из постоянных записей одним снимком PostgreSQL, без Valkey
и отдельной копии статусов в кэше. Новая схема БД не требуется. Поле processing
публикации остаётся состоянием первичных этапов; после построения плана API
вычисляет результат по его дорожкам. Фоновая готовность не меняет даты,
публикацию, приватность или модерацию.

Вариант готов, когда готовы проверенные видео и обязательный AAC; отсутствие
звука в плане допустимо. Незавершённые AV-задания сохраняют processing, даже
если уже есть доступный вариант. После завершения всех AV-заданий результат
ready/partial/failed определяется по [B18](../tasks/backend/processing.md#b18-показывать-достоверную-готовность-и-открывать-целые-варианты).
Повреждённый дескриптор результата не включается в master. Превью и субтитры
имеют отдельные состояния и не закрывают готовое видео.

Master собирается целиком в памяти по этому же снимку: реальные AV1C/AAC,
FPS, размеры, цвет и размеры/длительности сегментов. Отдельные группы WebVTT
привязаны к совместимым видеошкалам; отсутствующие, пустые и ошибочные дорожки
не попадают в master. Язык включается после готовности его совместимых пакетов
для всех включённых видеовариантов; это не задерживает видео. Группы сохраняют
одинаковые логические имена/языки, отличаясь URI; у разных AAC-групп общее имя
Audio. Правило одинакового состава — [RFC 8216 §4.3.4.1.1](https://www.rfc-editor.org/rfc/rfc8216#section-4.3.4.1.1),
проверено 2026-11-14. Внутренние относительные ссылки идентифицируют дорожки,
но не раскрывают RustFS-ключи. HTTP-зритель получает master с логическими
ссылками публикации после [проверки прав](media-delivery.md);
готовность сама по себе доступа не даёт.

GET `/api/v1/videos/{id}/processing` предназначен только владельцу. Ответ:
передача, общая обработка, причина первичного отказа, все запланированные
качества с состояниями и безопасными кодами ошибок, только готовые качества
в available_qualities, признаки HD/4K/HDR/4K+HDR, отдельные состояния превью
и субтитров. Процента, object key, digest, job ID и общих физических ID нет.
Настройки владельца показывают ту же общую готовность. Чужой и отсутствующий
ID неразличимы; ответы no-store и Vary: Cookie. Исходник здесь не удаляется.
Следующим этапом подключена [очистка оригиналов](original-cleanup.md): она
проверяет также превью, субтитры и остальные зависимые работы, а не только ready AV.

Для подготавливаемого превью показано состояние стандартного набора трёх кадров;
выбор и обработка собственного изображения остаются в [API превью](thumbnails.md).
Состояния субтитров приводятся по уже созданным связям с видеошкалами; до готовности
видеодорожки связей может ещё не быть. Их отсутствие не означает отсутствия
субтитров в исходнике. HD/4K/HDR здесь технические признаки результата;
[публичный поиск](search.md) проверяет их по готовым доступным вариантам.
Состояние без процентов и ключей не является разрешением
на просмотр. Чтение не обращается к RustFS: проверка/полная запись происходят перед
commit ready в кодировщике. Повторная проверка существования всех объектов на каждый
запрос не производится; отказ/утрата RustFS дают ошибку раздачи, сохраняя права.

Код: [домен](../../backend/src/video/domain/readiness.py),
[сценарий](../../backend/src/video/application/readiness.py),
[один SQL-снимок и master](../../backend/src/video/infrastructure/readiness.py),
[HTTP](../../backend/src/app/http/videos.py).

Приёмка: раннее низкое качество, ожидание обязательного AAC, частичный и полный
отказ, повторы, общий результат разных публикаций, согласованность снимка при
конкурентном завершении, отдельные ошибки WebVTT/превью, неверные дескрипторы,
инъекции в URI/метаданные, недоступная БД, права владельца и безопасные ответы.

## Проверки — 2026-11-14

Полная регрессия бэкенда в ограниченном Docker-контейнере (2 CPU/8 ГиБ,
без дополнительного swap): **791 passed за 703,11 с**. Старые проверки,
ожидавшие processing после полного кодирования, обновлены до ready;
проверки незавершённых этапов продолжают ожидать pending/processing.

В Docker прошли 42 новые проверки: доменный расчёт и повреждённые манифесты,
реальные общие AV1 двух аккаунтов, незакоммиченные изменения/rollback/commit,
отказ запроса в аварийной транзакции, реальное кодирование 360/480 с отказом 720,
ожидание AAC, скрытие/даты, HTTP с реальной загрузкой и очередью, чужие роли,
отсутствующие/некорректные ID, утрата сессии и отсутствие физических ключей в JSON.
Отдельный связанный прогон HLS/AV1/AAC/WebVTT — 116 passed; HTTP-контракт до
добавления сквозной загрузки — 11 passed. Эти прогоны пересекаются.
Код проверок: [расчёт и манифесты](../../backend/src/video/tests/test_readiness.py),
