# Собственные видео Studio

Статус: `done`, серверная часть Q50 для входа в настройки F26.

## Контракт

GET `/api/v1/videos/mine?publication=published|draft&cursor=...` требует
HTTP-сессию. По умолчанию `publication=published`; `draft` возвращает отдельный
список черновиков. В обоих списках новые первыми: `created_at DESC, id DESC`.
Загрузка, обработка и правки порядок не меняют; `added_at` для сортировки не нужен.

Ответ: `{items: VideoSettingsResponse[], next_cursor: string | null}`.
Порция — 20 по [ADR-0059](../decisions/0059-list-cursors-and-channel-order.md).
Поля, точные числовые int64 и вычисленная обработка
совпадают с GET `/api/v1/videos/{id}/settings`. Список включает свои public/private,
все состояния загрузки/обработки и visible/hidden. Публичные фильтры канала
здесь не применяются. Email-разрешения и роли staff чужие видео не добавляют.

Владелец берётся из сессии, параметры owner_id и размера страницы не принимаются.
Курсор привязан к назначению, владельцу и publication; не даёт прав доступа.
Вход проверяется перед разбором параметров/курсора. Гость получает 401;
некорректный, чужой, повторённый параметр или курсор другого списка — общий 422.
Ответы, включая ошибки, имеют `Cache-Control: no-store` и `Vary: Cookie`.
Ошибка БД не возвращает частичные метаданные. Ключей хранилища, ссылок загрузки,
аналитики и счётчиков в ответе нет. Метод и DTO входят в OpenAPI.

## Реализация и проверка

Добавлен индекс `(owner_id, publication, created_at DESC, id DESC)` в
[миграции 0025](../../backend/migrations/versions/0025_owner_video_lists.py),
применённой в dev. Сценарий Video.public.GetMyVideos проверяет аккаунт перед
фильтром/курсором. Репозиторий ограничивает выборку 21 строкой до чтения готовности
и получает метаданные/обработку одним SELECT; сценарий возвращает до 20 записей.
Новых зависимостей и медиазаданий нет. Фронтенд F26 — отдельный этап.

Код: [сценарий](../../backend/src/video/application/publications.py),
[граница страницы](../../backend/src/video/domain/own_videos.py),
[чтение](../../backend/src/video/infrastructure/publications.py),
[HTTP](../../backend/src/app/http/videos.py).

В Docker прошли **18 профильных проверок**:
[границы курсора](../../backend/src/video/tests/test_own_videos.py) и
[HTTP](../../backend/tests/test_own_videos_http.py). Проверены пустые списки,
страницы 20/20/1, сортировка при одинаковой дате, отсутствие
перестановки после изменений, отдельные draft/published, все собственные состояния,
bigint > 2^53, совпадение с GET settings и вычисленная ошибка обработки.
Проверены один SELECT страницы, auth перед параметрами, потеря сессии,
email-разрешение/staff без чужих видео, чужой/другой курсор, инъекции,
неверные/повторные параметры и 500 без частичного списка при отказе БД.
Ruff, форматирование и Basedpyright затронутых файлов прошли.
Метод, параметры и SessionCookie подтверждены в OpenAPI работающего dev;
гость через Nginx получает 401 с no-store/Vary. Общие проверки не запускались.
