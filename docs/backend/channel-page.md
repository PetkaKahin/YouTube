# Публичная страница канала

Реализованы сценарии и API B06 по [ADR-0059](../decisions/0059-list-cursors-and-channel-order.md).
Бизнес-правила доступа — [Channel](modules/channel.md).

## API

- GET `/api/v1/channels/{tag}` — id/name/tag/created_at/updated_at профиля.
- GET `/api/v1/channels/{tag}/videos?cursor=...` — items карточек главной и next_cursor.
- GET `/api/v1/channels/{tag}/playlists?cursor=...` — items метаданных плейлистов и next_cursor.

Tag — уникальный тег канала, без учёта регистра; допустим один префикс @,
как при регистрации. Недопустимый или отсутствующий тег даёт одинаковый 404.
Имя не является идентификатором; пустой существующий канал доступен гостю.
Редактирование профиля, баннеры, подписки и их счётчики в B06 не добавляются.
Пока профиль не редактируется, updated_at=created_at.

Каждый список — cursor по 20, next_cursor=null в конце. Видео сортируются
по added_at DESC/id DESC, плейлисты — created_at DESC/id DESC. Для видео
используются те же условия доступа и подготовленных AV1/AAC, длительность
основной дорожки и выбранное превью, что в главной ленте. Приватные, скрытые,
неопубликованные и неготовые видео исключаются до заполнения страницы/lookahead,
в том числе для владельца, приглашённого и staff. Чужие каналы исключаются в SQL.

В списке плейлистов только public, включая пустые и содержащие недоступные видео.
Private/unlisted не видны даже владельцу; его полный список остаётся в B26.
Состав не читается: нет счётчиков, превью из скрытого содержимого или наследования
прав на видео. Метаданные плейлиста совпадают с ответом создания/просмотра,
без owner_id и selected.

Курсоры привязаны к ID канала и виду списка; перенос на другой канал, в главную
или owner-список отклоняется как общий 422. Регистр/@ в том же теге не меняют
контекст. Курсор не даёт прав и не фиксирует снимок: каждый запрос повторяет
фильтры видимости/готовности. Повтор cursor-параметра и повреждение токена — 422
без отражения ввода. Ответы no-store/Vary Cookie. Ошибки зависимостей — общий 500,
без частичных результатов, поисковых/персональных полей и изменений данных.

## Реализация и приёмка

БД: миграция 0018 добавляет частичный индекс Video (owner_id, added_at DESC,
id DESC) для публичного списка канала. Таблицы/зависимости/секреты не добавляются;
Channel использует существующие профиль/плейлисты и индекс порядка владельца.

Channel владеет поиском профиля по тегу и списком своих public-плейлистов.
Имена получает пакетно через User.public. Video координирует публичный список
видео через Channel.public.FindChannel, без JOIN к чужим таблицам. Главная
и список канала используют общий сборщик карточек/проверку готовности;
все участвующие чтения идут в транзакции сценария, байты RustFS не читаются.
