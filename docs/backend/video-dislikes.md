# Взаимоисключающие реакции видео R21

Статус: `done`, серверная часть. [Согласованные правила и HTTP-контракт](../frontend/dislikes-backend-request.md).

Начальная схема определяет reaction=like|dislike в таблице video_likes.
Историческое имя сохраняется; одна строка с PK(video_id,account_id) хранит
единственный активный выбор, CHECK запрещает другие значения.
Новая пара без явно заданной реакции по умолчанию получает like.

Существующая блокировка публикации сериализует обе команды и обычную
проверку доступа с отзывом/скрытием. Целевой true вставляет/заменяет реакцию
атомарно, при смене ставится новое created_at. Повтор true сохраняет дату;
false удаляет только совпадающий вид реакции. Счётчик вычисляется по активным
like в PostgreSQL, без отдельной изменяемой копии. R19 liked фильтрует reaction
до LIMIT, поэтому дизлайк не сокращает страницу и не попадает в liked.

GET/PUT like возвращают прежние поля плюс обязательные disliked/can_dislike;
PUT dislike возвращает тот же DTO. Счётчика дизлайков нет. Обычные права,
CSRF, no-store/Vary и int64 сохраняются; реакции не меняют метаданные,
порядок публичных выдач и прогресс просмотра. Новых библиотек и медиазаданий нет.

## Код и проверка

Video.public.SetVideoDislike использует общие LikeActions с SetVideoLike:
[сценарии](../../backend/src/video/application/likes.py),
[SQL и агрегат](../../backend/src/video/infrastructure/likes.py),
[доменный DTO](../../backend/src/video/domain/likes.py),
[HTTP](../../backend/src/app/http/video_likes.py).
LikeResponse обязателен для GET/PUT like и PUT dislike; отдельного GET dislike нет.
Поле reaction входит в начальную [схему БД](database-schema.md).
Счётчик дизлайков ни в одном ответе не возвращается.

При первичной реализации в Docker прошли **27 профильных проверок**: 25 сценариев
[R21 HTTP/БД](../../backend/tests/test_video_dislikes_http.py), один существующий
сценарий совместимости [PUT like](../../backend/tests/test_video_likes_http.py)
и один сценарий старой миграции. После свёртки истории ограничения схемы
проверяются в [начальных миграциях](../../backend/tests/test_initial_migrations.py).
Проверены все 12 переходов none/like/dislike, идемпотентные даты, false другой
реакции, публичный точный like_count и приватность выбора, параллельные команды,
откат после смены/вставки при сбое агрегата, изоляция аккаунтов/публикаций,
guest/CSRF/422/инъекции/404, private-владелец/приглашение/отзыв/admin без обхода,
hidden/draft/неготовое и проигрыш блокировки смене приватности.

R19 liked фильтрует 23 дизлайка до страниц 20/1; возврат к лайку получает новую
дату и поднимает видео, повтор true сохраняет дату. GET не меняет метаданные,
историю или прогресс. CHECK/PK запрещают неверный/двойной выбор.
Сохранение старых пар/дат проверялось до свёртки истории; для текущей тестовой
БД предусмотрено пересоздание. Downgrade/повторный upgrade начальной схемы проверяются отдельно.

Ruff, форматирование и Basedpyright затронутых файлов прошли. Методы и DTO
подтверждены в OpenAPI dev; общий прогон и тесты фронтенда не запускались.
