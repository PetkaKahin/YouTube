# Комментарии и их лайки B30–B31

Статус: B30/B31 реализованы и проверены: домен, PostgreSQL, DI и HTTP/OpenAPI.
Правила — [Comment](modules/comment.md),
приёмка — [B30/B31](../tasks/backend/interactions.md).

## HTTP-контракт

- `GET /api/v1/videos/{video_id}/comments?sort=newest|popular&cursor=...`:
  `items`, `next_cursor`, `can_comment`; по умолчанию `newest`, порция 20
  по [ADR-0059](../decisions/0059-list-cursors-and-channel-order.md).
- `POST /api/v1/videos/{video_id}/comments`: `{text}`, сессия и CSRF,
  ответ 201 с созданным комментарием.
- `GET/PUT /api/v1/videos/{video_id}/comments/{comment_id}/like`:
  чтение состояния и команда `{liked: boolean}`; ответ
  `{liked, like_count, can_like}`. PUT требует сессию и CSRF.

Комментарий содержит `id`, `author_name`, `text`, `created_at`, `liked`,
`like_count`. Автор определяется сервером; имена читаются пакетом через
User.public. Email, роль, внутренние медиаданные и идентификатор аккаунта
в ответы не входят. Неизвестные JSON-поля игнорируются по общему контракту.
Текст сохраняется без обрезания и возвращается как строка JSON;
пустой/пробельный текст и длина свыше 2000 символов отклоняются.
NUL и одиночные суррогаты Unicode отклоняются до записи в PostgreSQL.

Гость читает доступное public-видео; публикация и лайки требуют вход.
Private, hidden, draft и видео без готового качества закрывают обсуждение,
включая владельца, приглашённых и служебные роли. Старые записи сохраняются
и снова доступны после возвращения public и обычных прав просмотра.
Чужой `comment_id` в маршруте другого видео не открывает запись.

Курсор содержит границу сортировки и привязку к видео/порядку, без текста
и персональных полей. Порядок: `created_at DESC, id DESC`; для popular перед
ними стоит реальное `like_count DESC`. Изменение лайков между запросами
может сдвигать позиции; курсор не является снимком обсуждения.
Некорректный курсор/текст/тип даёт 422, отсутствие сессии — 401,
недоступное видео или комментарий — одинаковый 404. Ответы используют
`Cache-Control: no-store` и `Vary: Cookie`; разрешения не кэшируются.

## Хранение и границы

Миграция 0022 создаёт `comment_entries` и `comment_likes` в PostgreSQL,
с внешними ключами и уникальной парой «комментарий, аккаунт».
Comment владеет таблицами; доступ к видео делегируется узкому Video.public
в общей транзакции. Video удерживает разделяемую блокировку публикации,
затем заново проверяет доступ: ожидающий запрос не обходит смену видимости
или скрытие. Лайки дополнительно сериализуются по комментарию, счётчик
вычисляется из записей. Комментарии и лайки не меняют `updated_at` видео.
Valkey и RustFS для хранения обсуждения не используются.

Домен/порты/сценарии находятся в `backend/src/comment/domain` и `application`,
SQL/адаптеры/DI — в `infrastructure`, HTTP — в `app/http/comments.py`.
Video.public.RequireDiscussionVideo участвует в транзакции вызывающего модуля;
он не открывает вложенную транзакцию и не экспортирует ORM или репозиторий.
Данные авторов приходят из User.public.GetPublicNames.
Новые библиотеки, настройки ресурсов и медиазадания не потребовались.

## Проверки

Полный pytest в Docker прошёл: **1360 тестов**, включая 94 профильные проверки:
домен/cursor, реальные миграции и constraints,
HTTP с сессиями/CSRF, собственные/чужие лайки и их повторы, две сортировки
на 43 комментариях с одинаковым временем, порции 20/20/3, подмена полей,
private/hidden/draft, сохранение обсуждения при смене видимости, блокировки
PostgreSQL со сменой доступа и commit/rollback, отказ Valkey и откат при
ошибке пакетного чтения имён или счётчика после записи лайка.

Исправлен обнаруженный тестом дефект: внешний JOIN не должен считать NULL
идентичностью гостя и выставлять `liked=true` комментарию без лайков.
Гостевое состояние проверяется отдельно для пустой и непустой пары.
Для общих Problem Details добавлены `no-store`/`Vary: Cookie`, включая
валидацию до входа в маршрут; регрессия дополнительно проверяет заголовки 422.

SQL/HTML-последовательности остаются строками JSON, текст не попадает в логи,
ошибки не раскрывают содержимое/персональные данные. Комментарии не принимают
пути, shell-команды, XML или сетевые назначения: соответствующих обработчиков
и внешних обращений здесь нет. DOM чтения/публикации проверен в
[функциональном профиле F16](../frontend/comments.md), лайки — в
[профиле F17](../frontend/comment-likes.md). Проверка JSON API сама по себе
не подтверждает безопасность вставки в браузере.

`./docker/check_delivery dev` и `prod` прошли: настоящие Nginx/FastAPI,
отдельная БД, подготовленные AV1/AAC/WebVTT/WebP, сессии и CSRF, 2000/2001
символ, guest/owner/recipient, private/hidden, пагинация, популярный порядок,
повторы лайков и неизменность настроек видео. Prod работает без pytest.
Собственные тестовые БД, медиаданные, контейнеры и сессии удаляются.

Ruff/Formatter, Basedpyright, оба аудита Tach, Alembic check и uv audit
(85 пакетов, известных уязвимостей нет) прошли. Аудит секретов dev: 9 контейнеров,
56 поверхностей,
findings=[]; окружение двух процессов PostgreSQL не прочитано, поэтому полного
покрытия процессов этот запуск не доказывает.
Локальные ссылки документации и `git diff --check` проверены; якоря отдельно
не проверялись. Новые библиотеки и secret-настройки не добавлены.
