# Channel

По R19 подключён [список подписанных каналов](../library.md), а Video получает
ID подписанных владельцев через Channel.public.GetSubscribedOwners.

Статус: создание пустого канала при регистрации, тег и отображаемое имя
и создание плейлистов с выбором в настройках видео, поля и режимы видимости
плейлистов и порядок добавления утверждены пользователем;
остальные правила R03/R16 — базовая спецификация.
Для [главной ленты](../feed.md) подключён внутренний GetPublicChannels:
пакет id/name/tag по владельцам, с именами из User.public.GetPublicNames.
Подключены [плейлисты B26–B28](../playlists.md): создание, список владельца,
выбор своих видео в Studio и просмотр по независимым правам.
Для R20 реализовано [сохранение доступных видео любого автора](../watch-save.md)
из просмотра и создание плейлиста с атомарным включением.
Подключена [страница канала B06](../channel-page.md): профиль по тегу,
публичные видео/плейлисты и cursor по 20.
Подключены [подписки B07](../subscriptions.md): состояние своей пары и
идемпотентная установка цели, без private-доступа или изменения дат.
FindChannels/FindPlaylists подключены к [общему поиску](../search.md): публичные
имя/@тег каналов и названия только public-плейлистов, пакетное чтение имён
через User.public, без чужих SQL-таблиц, чтения содержимого и персональных полей.
Даты изменения профиля пока равны созданию, поскольку редактирования профиля нет.

## Ответственность

Публичная страница автора, его видео и плейлисты, подписки.
Начальная модель — канал одного аккаунта, без командного владения и отдельных
аккаунтов брендов. Сведения об авторе приходят из `User.public`, доступные видео
и их карточки — из `Video.public`.

Пользователь подтвердил создание пустого канала одновременно с регистрацией;
поля и сценарий регистрации описаны в [User](user.md).
Начальное содержимое канала — без видео и плейлистов. Название берётся из
[отображаемого имени пользователя](user.md); имена разных каналов могут совпадать.

## Тег канала

Утверждено пользователем; [ADR-0003](../../decisions/0003-channel-identity.md).

- Тег — уникальный идентификатор канала, отображается с префиксом `@`.
- Часть после `@` содержит от 3 до 30 символов: латинские буквы, цифры,
  точку, подчёркивание `_` и дефис `-`. Префикс `@` в длину не входит.
- Регистр не различается: `@Name` и `@name` — один тег, зарегистрировать
  их для разных каналов нельзя. Уникальность действует на все каналы.
- Совпадение названий каналов допустимо; название не служит уникальным ключом.
- При недопустимом или занятом теге регистрация возвращает ошибку поля,
  а не создаёт другой тег автоматически.

## Базовые правила

- Гость может открыть канал, его публичные видео и плейлисты.
- Общий поиск поддерживает каналы и публичные плейлисты. Плейлисты `unlisted`
  и `private` через общий поиск не обнаруживаются; [правила поиска](../../project/search.md).
  Канал ищется по имени и `@тегу`, плейлист — по названию; совпадение по части
  текста без учёта регистра. Фильтры длительности и особенностей к ним не применяются.
- Список видео канала показывает только публичные опубликованные нескрытые
  видео; приватные не появляются там даже как способ обнаружения для приглашённого.
  Владелец видит состояние своей загрузки на экране загрузки.
- Плейлист содержит упорядоченные ссылки на видео. Права Video проверяются
  отдельно; недоступное видео не раскрывает метаданные. Разрешение на плейлист
  не выдаёт доступ к приватным видео внутри него: пользователь подтвердил
  независимость разрешений в Q14.
- В объём входят создание плейлистов пользователем, отображение на канале
  и управление включением видео в свои плейлисты в ЛК.
- Вошедший пользователь может подписаться на чужой канал и отменить подписку.
  Уникальность пары «подписчик, канал» обеспечивается постоянным хранилищем;
  повторное применение того же состояния не создаёт дубликат.
- Собственный канал не предлагает действие подписки. Подписка не открывает
  приватные видео и не создаёт уведомлений или отдельной ленты в этом ТЗ.

Подписка и её отмена соответствуют нужной части
[справки YouTube](https://support.google.com/youtube/answer/4489286?hl=en),
проверенной 2026-11-11. Предположение «один аккаунт — один канал» является
начальной моделью проекта, а не заявлением о полном устройстве YouTube.

## Создание и наполнение плейлистов

Дополнение пользователя от 2026-11-12; [ADR-0010](../../decisions/0010-playlist-creation.md).
Актуальная видимость плейлистов — [ADR-0011](../../decisions/0011-playlist-visibility.md),
заменяет прежнюю выдачу доступа к плейлисту по email.

- Пользователь создаёт плейлисты своего канала. Это рабочая функция,
  а не только заранее подготовленные тестовые данные.
- Для создания нужны обязательное название и необязательное описание.
  Название не может быть пустым или состоять только из пробелов.
  Подтверждены название 1–100 символов после удаления крайних пробелов
  и описание до 5000 символов с сохранением переносов, как у видео.
- Поддерживаются три режима видимости плейлиста; они не меняют видимость его видео:
  - `public` — публичный, доступен всем и показывается в публичном списке канала;
  - `unlisted` — доступ по ссылке, открыть может любой со ссылкой, включая гостя;
    в публичном списке канала не показывается;
  - `private` — ограниченный доступ, только владельцу после входа, в том числе по
    прямой ссылке. Другим пользователям не раскрываются содержимое и метаданные.
- Выдачи доступа к плейлисту по email и списка приглашённых у плейлиста нет.
  Владелец видит свои плейлисты всех трёх режимов в ЛК.
- В настройках своего видео в ЛК есть выпадающий список своих плейлистов.
  У каждого пункта независимая галочка; можно выбрать несколько, все
  или ни одного плейлиста.
- Одно видео может состоять в нескольких плейлистах. Установка галочки
  включает его в соответствующий плейлист, снятие — исключает из него,
  не удаляя само видео или другие связи.
- Пара «плейлист, видео» уникальна; повторное сохранение выбора не создаёт
  дубликаты. Studio проверяет владение видео и изменяемыми плейлистами.
  Отдельный API R20 проверяет обычное право просмотра видео и владение плейлистом.
- Новое включение видео добавляется в конец плейлиста; порядок соответствует
  времени включения. Ручная перестановка в проекте не предусмотрена.
  Повторное сохранение уже установленной галочки не меняет позицию; удаление
  и последующее новое включение добавляет видео в конец.
- Просмотр публичного плейлиста или доступ по ссылке не открывает приватные
  видео внутри него. Для чтения элемента нужны права на плейлист и на
  конкретное видео. Видимость видео и его разрешения не меняются.
- Место и устройство формы создания отложены до разработки UI (Q07).
  Бизнес-часть Q06 и вопрос независимости прав Q14 закрыты;
  [состояние вопросов](../../tasks/open-questions.md).

## Данные и проверки

Channel владеет профилем канала, плейлистами и подписками в PostgreSQL.
Реализован профиль `channel_profiles`, ID bigint и один владелец на канал;
плейлисты и порядок ссылок реализованы в миграции 0017;
подписки реализованы в миграции 0020; отмена удаляет активную пару.
`Channel.public.Register` создаёт аккаунт через адаптер к `User.public.CreateAccount`
и пустой канал в одной транзакции общей REQUEST-сессии. Ошибка тега откатывает
и аккаунт. Регистронезависимая уникальность тега обеспечена индексом PostgreSQL.
Цикла `User → Channel → User` нет; User не зависит от Channel.
Другие публичные методы добавляются при появлении реального потребителя.
Проверки: доступ к каналу гостем, фильтрация приватных/скрытых видео,
отсутствие утечек из плейлистов, конкурентные и повторные подписки,
границы длины/символов тега и его уникальность без учёта регистра.
Для R16 проверяются создание своего плейлиста, включение видео в несколько
или все свои плейлисты, снятие галочки, отсутствие дубликатов и запрет
изменять чужие видео через Studio или чужие плейлисты через подмену идентификаторов.
R20 позволяет сохранять доступное чужое видео только в собственные плейлисты.
Создание допускает пустое описание, требует название и сохраняет выбранную
видимость плейлиста отдельно от видимости содержащихся в нём видео.
Проверяются три режима видимости: public доступен гостю и находится на канале,
unlisted открывается гостю по ссылке без появления в публичном списке,
private по прямой ссылке доступен только владельцу. Во всех режимах сохраняется
проверка доступа к каждому видео. Отдельно проверяются добавление в конец
и сохранение порядка при повторной отправке неизменённого выбора.
