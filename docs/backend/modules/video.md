# Video

Статус: выдача приватного доступа по email без раскрытия наличия аккаунта
и порядок главной/поиска по дате добавления утверждены пользователем;
остальные правила R01, R02, R04, R05, R08, R10, R11 —
базовая спецификация.
Технический процесс — [конвейер](../video-pipeline.md).

## Ответственность и данные

Владелец, название, описание, превью, видимость, разрешённые зрители, состояние
публикации/обработки/скрытия, исходник, варианты HLS и лайки. Постоянное состояние
в PostgreSQL, файлы в RustFS. Идентификатор владельца не меняется по вводу клиента.

## Видимость и доступ

Только два режима: `public` и `private`.

| Сценарий | Публичное готовое видео | Приватное готовое видео |
| --- | --- | --- |
| Просмотр гостем | Да | Нет |
| Просмотр владельцем | Да | Да |
| Просмотр другим пользователем | Да | Только с разрешением владельца |
| Главная, поиск, публичный список канала | Да | Нет |
| Доступ по известному URL без разрешения | Да | Нет |
| Комментарии | Доступны | Недоступны |

Правила публичной выдачи и отключения комментариев у приватного видео взяты из
[справки YouTube](https://support.google.com/youtube/answer/157177?hl=en),
проверенной 2026-11-11. Применяется только часть про public/private.

## Разрешения по email

Утверждено пользователем 2026-11-12; [ADR-0009](../../decisions/0009-private-access-by-email.md).

- Владелец добавляет разрешённые адреса по **email**. Принимается любой корректный
  по формату адрес, независимо от наличия аккаунта в проекте.
- Разрешение адресовано email и может существовать до регистрации получателя.
  Добавление не требует существующего аккаунта или его внутреннего ID.
- В UI и API одинаковый результат для зарегистрированного и ещё не
  зарегистрированного адреса. Нельзя показывать «пользователь не найден», наличие
  аккаунта, его имя, тег, аватар или внутренний ID по введённому адресу.
- Список разрешений показывает введённые владельцем email без статуса регистрации.
  Публичный поиск аккаунтов по этому адресу для формы доступа не нужен.
- Email нормализуется по тем же правилам, что при входе. Повторное добавление
  того же адреса не создаёт дублирующее разрешение.
- Гостевой доступ этим правилом не вводится: для просмотра получатель входит
  в аккаунт. Для учебного проекта доверяем email, указанному при регистрации:
  совпадения нормализованного адреса аккаунта с разрешённым email достаточно
  для проверки получателя. Подтверждение владения почтой не требуется.
  Это согласованный ответ на Q13; остальные проверки готовности, видимости
  и модерации продолжают действовать.

## Применение доступа

- Подписка, лайк и возможность открыть плейлист не дают права приватного просмотра
  содержащегося в нём видео. Разрешение на приватное видео выдаётся отдельно;
  его добавление в плейлист не меняет видимость и список разрешённых email.
  Доступ по ссылке (`unlisted`) предусмотрен только для плейлистов;
  режимы самого видео по-прежнему `public` и `private`.
- Владелец управляет метаданными, видимостью и разрешениями при загрузке
  и в согласованных настройках видео в ЛК. Там же выбираются плейлисты;
  связями «плейлист, видео» владеет [Channel](channel.md).
- Недоступному зрителю не выдаются название, превью, списки качеств или ссылки
  приватного видео через API, поиск, плейлисты, кэш и медиараздачу.
- Проверка чтения учитывает одновременно разрешение, готовность и скрытие.
  Модерационное скрытие запрещает обычное воспроизведение, в том числе владельцу.
  Просмотр для рассмотрения жалобы — отдельное привилегированное действие.
- Переход в `private` и отзыв разрешения закрывают последующие запросы к данным
  и HLS. Уже полученные байты отозвать невозможно; детали медиапроверки — в конвейере.

## Главная и поиск

В выдачу попадают только публичные опубликованные нескрытые видео с готовым
качеством. Главная показывает превью и основные данные карточки.
Утверждено пользователем 2026-11-12; [ADR-0012](../../decisions/0012-feed-and-search-order.md):

- Главная на начальном этапе упорядочена по дате добавления, новые сначала,
  без алгоритма персональных рекомендаций.
- Дата добавления видео — момент успешного завершения загрузки исходника.
  Последующая публикация и готовность качеств не меняют её. Q15 закрыт.
- Поиск видео работает по части названия без учёта регистра; описание
  и содержимое видео не участвуют в совпадении.
- Общий поиск теперь включает также каналы и плейлисты, фильтры по типу,
  длительности, дате загрузки и особенностям, сортировки по созданию/изменению.
  Канонические правила — [поиск](../../project/search.md); бизнес-часть согласована.

Пагинация отложена до технической части [Q08](../../tasks/open-questions.md).
Фильтр доступа применяется до пагинации, подсчёта результатов и отдачи из кэша.
Выбор сортировки не открывает доступ к скрытым или приватным видео.

## Лайки

Вошедший зритель с доступом может поставить один лайк видео и отменить его.
Уникальность пары «пользователь, видео» сохраняется при конкурирующих запросах;
повтор команды установить/снять лайк не меняет результат повторно.
Клиент отправляет целевое состояние, а не ненадёжную серверную команду toggle.
Счётчик и собственное состояние возвращает сервер.
Ориентир отмены выбора — [справка YouTube](https://support.google.com/youtube/answer/6083270?hl=en),
проверена 2026-11-11. Остальные функции этой страницы не входят в проект.

## Публичные контракты и проверки

Планируемый `Video.public`: получить доступную карточку, проверить просмотр и
комментирование, выдать доступные видео автора, применить модерационное скрытие.
Сценарий скрытия требует подтверждённой роли, причина и инициатор сохраняются.
Проверки: матрица видимости, утечки через выдачу/превью/HLS, отзыв доступа,
конкурентные лайки и все варианты состояний конвейера.
Для разрешений проверяются сохранение email до регистрации адресата, одинаковый
публичный результат при наличии/отсутствии аккаунта и отсутствие раскрытия
его данных. Вошедший пользователь с разрешённым email получает доступ без
подтверждения почты; другой email и гость доступа не получают.
Для каталога проверяются порядок по дате добавления на главной и в поиске,
поиск по части названия без учёта регистра, сохранение фильтра прав при смене
сортировки, неизменность даты добавления при поздней публикации и обработке.
Проверяется также, что дата изменения обновляется при правках владельца,
но не при просмотрах, лайках или фоновой обработке. Признаки HD/4K/HDR появляются
только после готовности доступных зрителю версий; подходящий исходник не заменяет
готовый результат. Сочетание 4K + HDR требует готового варианта 2160p HDR.
