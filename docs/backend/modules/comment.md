# Comment

Статус: имя автора, лимит текста, сортировки и правила лайков утверждены пользователем;
остальные правила R02 — базовая спецификация.
Бэкенд B30/B31 реализован; результаты приёмки — в
[контракте комментариев](../comments.md). UI остаётся в F16/F17.

## Ответственность и правила

Комментарии к видео: автор, текст, время публикации и идентификатор видео.
Постоянные данные находятся в PostgreSQL; идентичность автора — из `User.public`,
разрешение комментировать и читать — из `Video.public`.
У комментария показывается имя автора, указанное при регистрации, по
[правилам отображаемого имени](user.md). Оно может совпадать с именами других
авторов; связь комментария с автором определяется идентификатором аккаунта.

- Смотреть комментарии публичного доступного видео может и гость.
- Публиковать может вошедший пользователь с доступом к видео.
- Пустой или состоящий только из пробелов текст не принимается; текст
  отображается как пользовательские данные, а не исполняемый HTML.
- Максимальная длина комментария — **2000 символов**, включительно.
  Более длинный текст отклоняется с понятной ошибкой и не обрезается молча.
- У приватного видео комментарии недоступны, включая владельца и приглашённых:
  [правило YouTube](https://support.google.com/youtube/answer/157177?hl=en),
  проверено 2026-11-11. Старые комментарии при смене видимости не удаляются,
  но их чтение и публикация блокируются до возвращения публичного доступа.
- Модерационное скрытие видео закрывает обычный доступ и к его комментариям.
- Ответы, другие реакции кроме лайков, закрепление, редактирование, удаление и отдельная модерация
  комментариев не входят в текущее ТЗ.

## Сортировка и лайки

Утверждено пользователем 2026-11-12; [ADR-0015](../../decisions/0015-comment-order-and-likes.md).

- По умолчанию комментарии показываются по времени публикации, новые сначала.
- Дополнительно доступна сортировка по числу лайков, от большего к меньшему.
  При одинаковом числе лайков более новые комментарии располагаются выше.
- Для сортировки используется реальное серверное число лайков комментария.
  Модуль Comment владеет этими данными; лайки видео остаются в Video.
- Вошедший пользователь с доступом к видео может поставить один лайк любому
  доступному комментарию, включая свой, и затем снять его. Гость лайк не ставит.
- Для пары «пользователь, комментарий» возможен только один лайк. Повтор команды
  установить или снять лайк не изменяет счётчик повторно; конкурентные запросы
  не создают дубликатов.
- Если комментарий или его видео недоступны пользователю, постановка/снятие
  лайка запрещены. Проверку выполняет сервер, а не только интерфейс.
- Q18 закрыт; [состояние вопросов](../../tasks/open-questions.md).
- Любой порядок сохраняет правила доступа к видео и комментариям. Изменение
  счётчика лайков не меняет дату изменения самого видео.

Пагинация — cursor по 20, согласовано для всех списков в
[ADR-0059](../../decisions/0059-list-cursors-and-channel-order.md).
HTTP-контракт и границы реализации — [комментарии](../comments.md).
Проверки: гость не пишет, идентификатор автора не подделывается, приватность
не обходится прямым API-запросом, содержимое безопасно отображается во фронтенде.
Проверяются граница 2000 символов, отклонение превышения и два порядка
всего доступного списка комментариев, а не только текущей страницы.
Для лайков проверяются вход и доступ, уникальность, снятие, повторные и
конкурентные запросы. Для популярного порядка — убывание счётчика и более
новый комментарий первым при равенстве числа лайков.
Обратная зависимость Video от Comment не нужна.
