# Личные выдачи R19

Статус: `done`, серверная часть. [Согласованные правила и HTTP-контракт](../frontend/library-backend-request.md).
Реализованы список подписанных каналов, лента их публичных видео, понравившиеся
и история по принятому прогрессу. Собственные плейлисты используют готовый API.

Миграция 0027 добавляет video_likes.created_at. Существующим лайкам назначается
время миграции; при равной дате порядок определяет video_id DESC. Историческая
дата не восстанавливается. Новые пары получают серверное время;
повтор true сохраняет дату, снятие и новый лайк меняют её. По R21 одна пара
хранит like/dislike; выдача liked фильтрует только like до LIMIT, а возврат
с dislike к like задаёт новую дату — [контракт реакций](video-dislikes.md).
Индексы покрывают порядок лайков и прогресса по аккаунту/дате/video_id.

Channel владеет подписками: список каналов и ID подписанных владельцев
возвращаются через public. Video не читает таблицы Channel. Лента подписок
отбирает кандидатов по этим ID в своём SQL до LIMIT; при отсутствии подписок
возвращается пустая страница без сканирования общей видеоленты.
Все три видео-выдачи применяют обычную пакетную проверку просмотра, включая
готовность и private-разрешения, до выбора границы страницы. Авторы и прогресс
получаются пакетно, позиции — один раз для итоговой страницы.

Все методы проверяют вход перед параметрами/cursor; cursor привязан к аккаунту
и виду выдачи. Чтения не меняют записи, метаданные, даты и существующие права.
Новых библиотек, медиаобработки и фоновых заданий не требуется.

## Код и проверка

Channel.public экспортирует GetSubscribedChannels и GetSubscribedOwners:
[сценарии](../../backend/src/channel/application/subscription_lists.py),
[хранилище подписок](../../backend/src/channel/infrastructure/subscriptions.py).
GetSubscribedOwners участвует в транзакции Video и возвращает только ID владельцев
активных подписок текущего аккаунта, без имён или персональных полей.

Video.public экспортирует GetLibraryVideos и InvalidLibraryCursor:
[сценарий](../../backend/src/video/application/library.py),
[составные границы](../../backend/src/video/domain/library.py),
[SQL](../../backend/src/video/infrastructure/library.py),
[HTTP видео](../../backend/src/app/http/library.py),
[HTTP каналов](../../backend/src/app/http/channels.py).
[Миграция 0027](../../backend/migrations/versions/0027_library_order.py) применена в dev.

В Docker прошли **37 профильных проверок**: 23 проверки границ/cursor и
14 проверок HTTP/БД/миграции. Код:
[cursor видео](../../backend/src/video/tests/test_library.py),
[cursor каналов](../../backend/src/channel/tests/test_subscription_lists.py),
[HTTP](../../backend/tests/test_library_http.py),
[старые лайки и миграция](../../backend/tests/test_library_migration.py).

Проверены 401 и пустые ответы, OpenAPI, scope аккаунта/назначения, int64 > 2^53,
точные даты и равные границы, страницы 20/20/1, 43 недоступных записи перед
41 доступной, пакетные имена/позиции, unknown/query SQL-ввод, отмена подписки,
идемпотентный лайк и снятие/новый лайк, перемотка назад с подъёмом в истории,
private/разрешение/отзыв/admin без обхода/hidden/draft/неготовность, сохранение
недоступных исходных пар, отсутствие изменений от GET и отказ зависимостей
без частичных/ложно пустых успешных ответов. Существующие лайки при миграции
сохраняются, получают общую техническую дату; новые пары — фактическое время.

Ruff, форматирование и Basedpyright затронутых файлов прошли. Через Nginx dev
подтверждены все четыре маршрута и DTO в OpenAPI, 401 гостя и 200 с сессией.
Общие проверки приложения, медиа-конвейер и фронтенд не запускались.
