# Формирование master-плейлиста HLS

Реализован адаптер Video; техническая квалификация прошла.
Последующим этапом подключена [сборка по результатам заданий и API готовности](readiness.md).
[Защищённая раздача](media-delivery.md) подключена, плеер остаётся до фронтенда.
Правила упаковки —
[ADR-0047](../decisions/0047-hls-packaging.md), видеобитрейт —
[ADR-0048](../decisions/0048-uncapped-video-crf.md).

FFmpeg HLS muxer остаётся упаковщиком fMP4. Готовый master формирует сервер
по фактическим данным готовых дорожек, вместо использования неполного master
от FFmpeg. Это ранее запланированная часть ADR-0047; новых библиотек нет.
Данные не берутся из имени исходника или клиентского запроса:

- AV1 `CODECS` по AOM: профиль, уровень, tier, разрядность, субдискретизация
  из AV1CodecConfigurationRecord (`av1C`), цветовые поля готовой дорожки.
  Поля цвета указываются полностью, включая PQ, без подстановки SDR по умолчанию.
- AAC `mp4a.40.2` только после проверки AudioSpecificConfig: AAC-LC, 48 кГц,
  моно/стерео. Аудиопрофиль физически переиспользуется и включается в `CODECS`.
- `RESOLUTION`, `FRAME-RATE`, `VIDEO-RANGE` по выходной дорожке.
  Три десятичных знака FPS в HLS не меняют дробную частоту самих кадров.
- `BANDWIDTH`/`AVERAGE-BANDWIDTH` по размерам и EXTINF готовых медиасегментов,
  с учётом аудио. Пик по окнам 0,5–1,5 target duration (RFC 8216);
  для ролика короче окна используется его средний битрейт.
- Ссылки в этом адаптере — только относительные серверные пути внутри
  медиакомплекта. Ни сетевых запросов, ни чтения произвольных файлов нет.
  Привязка к защищённым маршрутам выполняется отдельным адаптером B22.

По [ADR-0049](../decisions/0049-embedded-text-subtitles.md) добавлены группы
готовых текстовых субтитров. Общая группа используется для совместимых шкал;
различающиеся шкалы имеют отдельные группы с одинаковым составом имён/языков.
Генератор сохраняет и прежний вход общего subtitles; смешивать его с
per-variant subtitles нельзя. Отбор готовых пакетов — [готовность](readiness.md).
`TYPE=SUBTITLES` ссылается на отдельные WebVTT-плейлисты, `LANGUAGE`
сохраняется, подписи/URI проверяются. В битрейтах учитывается самый тяжёлый
выбираемый язык, а не сумма всех языков. Отдельный текстовый WebVTT не является
MP4 sample entry `wvtt` и не добавляется как такой кодек в `CODECS`.
Интерфейс выбора/автовыбора субтитров остаётся до UI; генератор не выбирает
язык по умолчанию. При отсутствии дорожек пустая группа не создаётся.
Подготовка и текущая проверка — [субтитры](subtitles.md).

Пустые дорожки, некорректная конфигурация кодека, неизвестные обязательные
поля, противоречивые ссылки или попытка внедрить строку в плейлист должны
заканчиваться ошибкой до выдачи master. Неполный результат не допускается.
Адаптер не подтверждает готовность файлов в RustFS и права доступа:
кодировщик проверяет и сохраняет пакет перед ready, сборщик проверяет дескриптор;
проверки зрительских прав и доставка выполняются в [B22](media-delivery.md).

## Первоначальная реализация и проверка

Ниже результаты отдельного адаптера до подключения к данным заданий;
новая интеграция и её проверки — [B18](readiness.md).

Код: [hls.py](../../backend/src/video/infrastructure/hls.py);
модульные тесты: [test_hls.py](../../backend/src/video/tests/test_hls.py);
реальный FFmpeg: [check_hls.py](../../docker/python/check_hls.py).

В Docker прошли 52 теста генератора; вместе с тестами метаданных Video —
90 тестов. Проверены эталонная строка CODECS из AOM, 8/10 бит и tier,
отказ повреждённых/неполных конфигураций и неизвестных цветовых параметров,
пустые и противоречивые дорожки, беззвучное видео, переиспользование аудио,
окна пикового битрейта с коротким последним сегментом, дробные частоты,
TARGETDURATION, внедрение строк/кавычек, внешние URI и обход пути.

Пересобраны dev/prod. Квалификация в обоих образах от app, без сети/GPU,
с 2 CPU и 1 ГиБ RAM прошла: 18 независимых fMP4-сегментов, AV1 8/10 бит,
24/30000/1001 FPS, два малых размера, AAC-LC моно/стерео и общий аудиоплейлист.
CODECS проверены по конфигурации, level и pix_fmt выходных дорожек.
Полные master созданы нашим адаптером, видео/аудио декодированы FFmpeg
с `-xerror` и разрешённым только локальным протоколом `file`.
Позднее добавлены WebVTT по ADR-0049; FFmpeg HLS demuxer пропускает такие
дорожки, сами непустые VTT проверяются отдельно. Результаты текущей
квалификации и ограничения — [субтитры](subtitles.md).

PQ в этой пробе синтетический: она проверяет сигнализацию в упаковке,
а не тональное преобразование или бизнес-порог HDR 1080p+. Реальные HDR-пробы —
[ADR-0046](../decisions/0046-cpu-hdr-conversion.md). Размеры/длительности здесь
не являются бенчмарком реальных разрешений. Браузер и все варианты переключений
между качествами пока не проверены; защищённая выдача и recovery — впереди.

Ruff/Formatter (124 файла), Basedpyright и оба Tach прошли. Полный
`docker/run check` не запускался. Дополнительный запуск всей папки Video
в контейнере без Compose Secrets дал 95 успешных тестов и 39 ошибок подготовки
интеграционных fixtures (`POSTGRES_PASSWORD_FILE` отсутствовал); интеграционные
сценарии этим запуском не проверены. Последующий целевой запуск указанных
модульных тестов завершился 90/90 без ошибок. БД, очереди, сессии и
HTTP-контракты в этом изменении не затронуты, их сквозная приёмка не заявляется.

## Источники

Дополнительно 2026-11-14 проверен [RFC 8216 §4.3.4.1.1](https://www.rfc-editor.org/rfc/rfc8216#section-4.3.4.1.1):
группы одного TYPE имеют одинаковый состав и атрибуты членов, кроме URI/CHANNELS.
Соответствующая доработка AAC/WebVTT входит в [B18](readiness.md).

Проверены 2026-11-13:

- [AOM AV1 ISOBMFF, §2.3 и §5](https://aomediacodec.github.io/av1-isobmff/): av1C и CODECS.
- [RFC 8216, §4.1 и §4.3.4.2](https://www.rfc-editor.org/rfc/rfc8216): битрейты и master.
- [Apple HLS authoring](https://developer.apple.com/streaming/hls-authoring-specification-for-apple-devices.html): VIDEO-RANGE и FRAME-RATE.
- [FFmpeg HLS muxer, текущая ветка](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/libavformat/hlsenc.c): write_codec_attr пока не содержит AV1; одно обновление не устраняет пропуск.
