# План качеств и кодирование

Реализовано 2026-11-14: постоянный план и реальные отдельные задания AV1/AAC
по ADR-0039–0053. B14/B15 остаются `in_progress` до полной сквозной приёмки.

План строится после доверенной проверки исходника. Выбираются основные дорожки
по [ADR-0052](../decisions/0052-primary-media-tracks.md). Лестница учитывает
поворот, SAR, пропорции и запрет upscale. Для вертикального видео прямоугольник
лестницы поворачивается. Размеры для 4:2:0 округляются вниз до чётных значений;
DAR сохраняется через выходной SAR, без обрезки или растяжения. Для однопиксельной
стороны сохраняется 1 пиксель; libaom-AV1 работает и для 1×1.
Ниже 360p планируется фактическое разрешение. HDR создаёт всю допустимую SDR
лестницу и HDR10 от 1080p; профиль/FPS/CRF/битрейт — из принятых ADR.
Для стороны меньше 64 — libaom-av1/cpu-used=4 по
[ADR-0053](../decisions/0053-small-frame-av1.md); для остальных — SVT-AV1/preset 6.

План постоянный и идемпотентный. Каждая видеоверсия и каждый нужный AAC-профиль
имеют отдельное задание. Совпадающая дорожка с совместимым профилем имеет
одну общую работу, включая незавершённую. Первые работы — минимальное SDR
и его аудио; последующие не пересоздают уже готовое.

Звук учитывает смещение относительно выбранного видео. При повторной кодировке
другой исходник не может подменить временную привязку общей аудиоверсии.
Точность времён сохраняется рациональными числами, без float в ключах профилей.
Отчёт инспектора версии 3 содержит время показа и длительность выбранной дорожки,
включая Skip Samples/discard padding. Версии 1/2 автоматически проверяются заново;
формат слепка compressed-v1 при этом не меняется.

Меньший исходный FPS сохраняется точно. Если он выше потолка варианта,
выбирается частота не выше потолка на общей сетке сегментов. Старшая версия
задаёт ближайшую к 6 с границу по целому числу кадров; остальные получают целое
число кадров за этот интервал. Например, 59,94 → 29,97/59,94 и сегменты 6,006 с.
Уменьшение частоты не меняет скорость; VFR преобразуется в CFR по этой сетке.

Worker скачивает закрытый исходник, читает только его FD и запускает FFmpeg
без shell/GPU под ADR-0051. Видео — AV1/fMP4 HLS, AAC-LC — отдельный HLS.
Неполные результаты не становятся ready; отдельные префиксы попыток защищают
от запоздалой записи старого worker. Готовность фиксируется после проверки
локального комплекта и загрузки всех его объектов в закрытый RustFS.
Повторы/журнал/recovery сохраняют ADR-0035. Оригинал пока не удаляется.

## Данные и готовность

Миграция [0009](../../backend/migrations/versions/0009_media_encoding.py) добавляет
video_media_plans, video_encoded_tracks, video_plan_tracks и журнал незавершённых
префиксов video_encoding_attempts. [0010](../../backend/migrations/versions/0010_encoding_deadlines.py)
сохраняет срок конкретной попытки: изменение конфигурации другого worker
не сокращает разрешённое время её жизни. Старые записи без доказанного срока
не разрешают автоматическое удаление. Источник, план и задания передают управление
в транзакциях PostgreSQL. Идентичность результата включает слепок дорожки и
версионированный профиль; lookup/upsert защищён упорядоченными advisory locks.
В очереди только числовые upload_id/encoded_id, без ссылок и пользовательских тегов.

ready относится к закрытой отдельной дорожке: проверяются весь комплект,
декодируемость, AV1/AAC configuration, размеры/разрядность/цвет и фактические FPS
по числу декодированных кадров и длительности. Проба первого сегмента/заголовка
не заменяет эту проверку. Для одиночного кадра неверный r_frame_rate FFprobe
не используется вместо проверенной частоты. Реальные битрейты считаются по сегментам.
Для короткого VOD исправляется нулевой TARGETDURATION FFmpeg, минимум 1 с.
Файлы хешируются и потоково загружаются в закрытый RustFS до фиксации ready.

Поколение очереди проверяется под FOR SHARE вместе с токеном попытки; late finish
не заменяет чужой результат. [Подтверждение очереди](background-jobs.md)
отдельно проверяет поколение: старый worker не может завершить новую попытку.
Неоконченная загрузка по обычной ошибке очищается,
отклонённый поздний результат удаляет только свой префикс. Для аварийного прерывания
префикс остаётся в БД: обслуживание удаляет его после максимального срока попытки
плюс 60 с, только если он не активен и не является зафиксированным результатом.
Удаление и проверка ссылки идут под блокировкой; I/O обслуживания ограничено 5 с,
незавершённая очистка повторяется. Успешная фиксация удаляет запись незавершённого
префикса в той же транзакции; R17-история ошибок при этом сохраняется.
Окончательная ошибка всех вариантов отражается в processing=failed без изменения
названия, видимости, публикации или дат владельца.

## Границы этапа

Первоначальный этап не добавлял HTTP-раздачу/публикацию, превью и субтитры.
Последующими этапами подключены превью, субтитры и
[расчёт готовности с внутренним master](readiness.md). Настройки владельца
показывают ready/partial/failed по фактическим результатам AV1/AAC;
публичная выдача B22 ещё не реализована.
Сейчас проверены повороты, кратные 90°; другой угол даёт безопасный отказ
invalid_media_plan. Поддержка произвольной матрицы/угла и полноценная приёмка
всех HDR-профилей остаются до завершения B10/B14/B15. Проверки синтетические,
они не заменяют просмотра на реальных экранах или браузерной приёмки.

Последующим этапом подключены [превью и API владельца](thumbnails.md).
Общий механизм заданий/префиксов используется и для них; AV1/AAC-профили
и признаки готовности видеовариантов этим не меняются.

Приёмка: отсутствие upscale, поворот/SAR/нестандартные пропорции, дробный FPS,
8/10 бит, SDR/HDR и HDR→SDR, AAC/моно/стерео/отсутствие звука, смещение звука,
одна работа при конкуренции/повторе, crash/recovery/fencing, частичная запись,
реальные FFmpeg/PostgreSQL/RustFS в Docker, приватность и сохранность оригинала.
