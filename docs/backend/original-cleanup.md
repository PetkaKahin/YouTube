# Завершение обработки и удаление оригинала

Реализована очистка оригиналов в B19 по [ADR-0040](../decisions/0040-temporary-originals.md)
и [ADR-0049](../decisions/0049-embedded-text-subtitles.md). Политика не меняется:
любой незавершённый или неуспешный зависимый результат сохраняет оригинал для
повтора; это относится и к unsupported_subtitle. Ранний просмотр недостаточен.

Кандидат требует проверенного слепка v3, полного плана, всех AV1/AAC, набора
превью и полного набора связей встроенных субтитров со всеми видеошкалами.
WebVTT допускает успешный empty. Проверяются результаты и успешное завершение
их постоянных заданий, включая работы других публикаций, использующие этот
исходник. Свой загруженный рисунок превью обрабатывается отдельно: его входные
байты не зависят от видеооригинала. Приватность и публикация не влияют на очистку.

В upload сохраняются начало очистки, последняя попытка и подтверждение удаления.
Начало фиксируется отдельным commit до внешнего DELETE. Оно запрещает новое
чтение оригинала/создание зависимой работы; готовый общий результат по-прежнему
можно переиспользовать. Допуск работы и решение об очистке сериализуются короткой
блокировкой PostgreSQL. Сетевой вызов не держит транзакцию/блокировку.
Миграция 0014 добавляет три времени и ограничения; частичный индекс выбирает
ещё не удалённые оригиналы, индекс source_upload_id находит общие зависимости.
Допуск использует shared advisory lock, очистка — try-exclusive в отдельном
пространстве ключей; строка блокируется FOR NO KEY UPDATE. Ключ upload не меняется,
FK-ссылки не блокируются на всё время допуска. Готовые результаты можно
переиспользовать и после очистки; subtitle_clock читает готовый AV1, поэтому
ему не нужен удалённый исходник.

Удаление идемпотентно по точному неизменяемому серверному ключу incoming/UUID.
После сбоя RustFS, потери ответа, rollback подтверждения или рестарта остаётся
постоянное намерение; обслуживание повторяет его. До commit намерения файл
не удаляется. Очередной сбой одного объекта не останавливает другие кандидаты.
Используется существующий цикл обслуживания 15 секунд и размер SQL-пакета 100;
новых TTL, пользовательских ограничений и библиотек нет.
Этот цикл ставит обычное задание video.cleanup_originals в maintenance с
lock/queueing_lock; повторы используют прежние 3 запуска и задержки 30/120 секунд.
После исчерпания попыток новое обслуживание вновь подхватывает намерение.
Если один DELETE отказал, проверяются остальные кандидаты, затем попытка
завершается ошибкой для существующего постоянного журнала. История не очищается
после успеха. Публичного и ручного API очистки нет.

Слепки, инспекция, ссылки публикаций, готовые общие пакеты, даты владельца и
история ошибок не удаляются. Подтверждение/обновление уже принятой загрузки
после очистки остаётся идемпотентным и не проверяет удалённый оригинал по HEAD.
Отсутствие файла без намерения очистки по-прежнему является ошибкой хранилища.
Новых HTTP-маршрутов нет; публичный просмотр и ручной повтор остаются B20/B22/T12.

Приёмка: реальное удаление после полной обработки, отсутствие очистки при
ошибках/ожидании/выполнении, empty, разные аккаунты с общими работами, скрытое
видео, повторное подтверждение загрузки, отказ RustFS, разрыв между двумя
commit, гонки допуска/очистки, безопасный ключ и сохранность готовых файлов.
