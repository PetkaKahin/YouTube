# Подписка на канал

Реализованы сценарии и API B07 по [правилам Channel](modules/channel.md) и R03.
Подписка относится к паре вошедшего аккаунта и чужого канала; повтор
целевого состояния не создаёт дубликат. Собственный канал не является целью.
Подписка не даёт private-доступа, не создаёт уведомления или новую ленту.

## Контракт

GET `/api/v1/channels/{tag}/subscription` возвращает текущее состояние
подтверждённого пользователя: subscribed и can_subscribe. Для своего канала
оба false. Для чужого can_subscribe=true независимо от текущей подписки.
Гость получает 401; публичный профиль/списки канала остаются доступны через B06.

PUT того же пути принимает subscribed (строгий bool) и возвращает состояние
принятой операции. Это установка цели, а не переключатель. Повтор true/false
идемпотентен. Для своего канала обе команды дают 422 self_subscription.
Подписчик определяется по HTTP-сессии и User.public, цель — по существующему
тегу через FindChannel. Подмена subscriber_id/owner_id/channel_id во входе
не меняет отправителя или цель. Tag поддерживает регистр/@ как B06.

Требуется CSRF для PUT. Ошибки: 401 без действующего аккаунта, общий 404 для
некорректного/отсутствующего тега, общий 422 для неверного состояния, 500 без
внутренних подробностей при сбое. Все ответы no-store/Vary Cookie.
Подписки других людей и число подписчиков в API не добавляются.
По R19 подключены личный список каналов и лента их публичных видео —
[контракт и проверка](library.md). Порядок списка каналов — по созданию канала,
новые первыми; ленты — по добавлению видео. Повторы PUT и отмена сохраняют
прежние правила состояния пары и не меняют даты канала/видео.
Пагинация не нужна для единичного состояния; общее правило cursor по 20 остаётся.

## Реализация и приёмка

Сначала схема 0020: channel_subscriptions с PK(subscriber_id,channel_id),
FK на аккаунт и профиль. Отсутствие строки означает false; отмена удаляет
активную подписку. Дополнительных дат, секретов, библиотек и фоновых задач нет.
Из Channel нельзя читать таблицы User/Video напрямую: аккаунт проверяется
через User.public, остальные чтения/записи относятся к собственным таблицам.

GET/PUT открывают транзакцию сценария. Insert с точным ON CONFLICT для пары
и delete по паре атомарны; параллельные повторы не создают дубликат или строку
false. Перекрывающиеся разные команды могут завершиться в любом порядке;
результат каждого PUT описывает принятую им цель, актуальный GET повторно читает БД.
Чтения/подписки не меняют даты профиля, видео или плейлистов и не используют Valkey
как источник постоянного состояния. Роль сотрудника не разрешает подписку на себя
или управление чужой парой.

Приёмка: гость/владелец/посторонний/user/moderator/admin, свой/чужой/пустой/отсутствующий
канал, регистр/@ и одинаковые имена, подмена отправителя/цели, CSRF и строгий bool,
повторы/параллельные true/false и смешанные действия, rollback, FK/уникальность,
свежие чтения после отмены, сохранение состояния без Valkey, отсутствие изменения дат,
SQL/HTML/path-ввод, ошибки без данных/секретов и приватное видео после подписки/отмены.
Подтвердить профильные тесты и связанные HTTP/права/DI в Docker, dev/prod через Nginx.
Регрессия в Docker: **180 passed**. Включены все тесты Channel и HTTP
подписок/канала/плейлистов/поиска, включая поиск плейлистов, а также DI приложения.
Медиакодеки, параметры обработки и схема разрешений Video в этом этапе не менялись.

Код: [домен](../../backend/src/channel/domain/subscriptions.py),
[сценарии](../../backend/src/channel/application/subscriptions.py),
[PostgreSQL/User.public](../../backend/src/channel/infrastructure/subscriptions.py),
[HTTP](../../backend/src/app/http/channels.py).
Проверки: [сценарии и БД](../../backend/src/channel/tests/test_subscriptions.py),
[HTTP](../../backend/tests/test_subscriptions_http.py).

Проверены отличающиеся ID аккаунта/канала, self для всех ролей, регистр/@,
одинаковые имена, строгий bool, неизвестный аккаунт/тег, отсутствие записи
после отмены. По 8 параллельных повторов и 16 смешанных команд сохраняют
уникальность, чужую пару и соответствие свежего GET данным PostgreSQL.
Проверены FK/PK и откат после выполненных insert/delete, неизменность дат
профиля/видео/плейлиста и работа сценариев при принудительном отказе Valkey.

HTTP проверяет подмену подписчика/канала, CSRF и ошибки без ложного состояния.
Подписка не открывает private-видео/HLS; приглашение действует после отмены
подписки, отзыв приглашения закрывает просмотр даже при активной подписке.
Публичный список видео не расширяется. Одно ожидание теста OpenAPI исправлено:
общий контракт уже добавляет CSRFToken к защищённому PUT.

Dev/prod-квалификации через Nginx прошли: собственный канал запрещён,
гость получает 401, подписка сохраняется после повторного входа. Подписка
не открывает приватные байты; приглашение продолжает действовать
после отмены подписки, а отзыв закрывает доступ при повторной подписке.
API не читает объекты RustFS. Отдельный production-прогон при отказе Valkey
подтвердил состояние подписки и независимость email-разрешений; pytest в образе нет.

Ruff/Formatter (248 файлов), Basedpyright, оба Tach, Alembic upgrade/check
(0020), uv audit (85 пакетов без известных проблем), Compose dev/prod config,
Nginx config и HTTP smoke прошли. Dev/prod собраны с UV_OFFLINE=1 из кэша
закреплённых пакетов после известного внешнего TLS-сбоя PyPI; постоянные
Dockerfile/lock не менялись. Оба worker перезапущены. Финальный аудит:
