# Серверная часть админ-панели фоновых заданий

Реализована серверная часть T12 по [ADR-0062](../decisions/0062-job-administration.md).
[Интерфейс T12](../frontend/job-administration.md) подключён отдельно.
Технические таблицы журнала и намерений
принадлежат common; app соединяет их с User.public и Video.public.
Video сам восстанавливает собственные состояния и доверенные аргументы.

## Контракт API

Все маршруты требуют действующую сессию и актуальную роль admin; изменяющие
запросы также требуют CSRF. Роль читается под блокировкой PostgreSQL,
включая каждую фоновую подачу порции. При снятии роли остаток намерения отменяется.
Диагностика и ответы имеют no-store/Vary Cookie. Нет доступа у moderator/user/гостя.

| Маршрут | Поведение |
| --- | --- |
| GET `/api/v1/admin/job-errors?cursor=...` | Постоянная история, occurred_at DESC/id DESC, по 20, без фильтров. Ошибки после успеха и удаления native-записи сохраняются |
| POST `/api/v1/admin/jobs/{job_id}/retry` | Один ID; 202 с сохранённым намерением |
| POST `/api/v1/admin/job-retries` | `{"mode":"selected","job_ids":[1,2]}` либо `{"mode":"all"}`; 202. Дубликаты ID внутри списка схлопываются |
| GET `/api/v1/admin/job-retries/{id}?cursor=...` | Состояние намерения, actor_id, queued/skipped/unavailable, результаты по 20 с next_cursor |

ID — положительный bigint. Пустой selected, неверные типы/ID, лишние поля
команды и испорченные курсоры дают 422. Недоступное намерение — 404,
нет сессии — 401, недостаточно роли — 403, отказ хранилища — 503 без диагностики.
Переданные имена задач/аргументы/приоритеты не являются входом исполнения.
История содержит безопасные поля журнала, без kwargs, сообщений исключений,
ключей медиа, путей, URL и локальных переменных.

`pending` означает оставшиеся цели; `submitted` — цели рассмотрены и постановки
зафиксированы, а не успешное выполнение всех джоб; `cancelled` — остаток отменён
после утраты полномочий. Каждый queued-результат содержит replacement_job_id.
Пересечение с уже поставленным повтором даёт skipped/already_requested.
Устаревшая/успешная/неизвестная/недоступная работа не исполняется; причина
отражается как unavailable. Изменение ошибок после границы намерения не включается
в старый запрос «все». Его обработка не держит HTTP или неограниченную транзакцию.

## Постановка и конфигурация

Миграция 0024 добавляет намерения, результаты/аудит и индекс истории.
`JOB_RETRY_BATCH_SIZE=20` — несекретная настройка `.env`, передаётся Compose
в API/maintenance, положительное целое.
Изменение `.env` применяется после пересоздания API/maintenance через Compose.
В HTTP сохраняется только намерение; существующий цикл обслуживания постепенно
добавляет зарегистрированные задания.
Порция ограничена настройкой, при заполненной todo/doing очереди ждёт места;
обычные загрузки и параллелизм worker остаются по прежним правилам.
Общий advisory lock и уникальность старого job_id среди queued-результатов
защищают от параллельных dispatcher и пересекающихся выбранные/все.
Намерения, граница истории, прогресс и аудит переживают потерю Valkey/рестарт.

При повторе создаётся новый native ID с нулевым бюджетом использованных попыток.
Canonical job_id заменяется в той же транзакции. Старый worker не может завершить
новую работу; прошлые ошибки/префиксы попыток сохраняются. Готовые результаты
не очищаются. Сохраняется исходный приоритет; если native-запись удалена,
приоритет AV1/AAC/кадров восстанавливается по сохранённой проверке исходника
и планировщику, а не приблизительно по названию качества.
Восстановление источника/плана/AV1/AAC/WebVTT/превью выполняет
Video; housekeeping запускается только из фиксированного реестра.
При удалённой native-записи Video может восстановить только свою текущую
неуспешную работу, если сохранился необходимый источник. Произвольная старая
ошибка не даёт права запустить функцию или изменить готовый результат.
