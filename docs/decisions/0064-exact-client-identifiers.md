# ADR-0064: точные идентификаторы в клиенте API

Статус: принято пользователем 2026-11-16, Q47 закрыт по выбору решения.

## Решение

Серверный контракт `integer/int64` из ADR-0029 сохраняется. На фронтенде числовые
идентификаторы представлены точными десятичными строками типа `Identifier`.
Для JSON используется `lossless-json` 4.3.3 (MIT), а не округление через `number`.

Сгенерированный Hey API SDK остаётся неизменяемым. Адаптер `shared/api/sdk.ts`
получает успешный JSON как текст и разбирает его до преобразования в обычные
числа. Публичные DTO выводятся из сгенерированных типов через `ExactIdentifiers`;
имена `id`, `*_id`, `ids`, `*_ids` определяют числовые идентификаторы.
UUID и обычный пользовательский текст сохраняются строками.

При отправке JSON числовые ID-строки сериализуются точными JSON-числами,
как требует сервер. Диапазон положительного bigint проверяется без округления.
Обычные числовые поля остаются числами; неподдерживаемое числовое значение
отклоняется вместо тихой потери точности. JSON-адаптер не предназначен для
бинарной передачи файла или HLS.

## Последствия

Страницы и сущности импортируют клиент/DTO через `shared/api`, не обходят
адаптер прямым импортом SDK и не преобразуют ID в `Number`/`parseInt`.
Новые операции подключаются через ту же границу; генерация не правится вручную.

Проверки включают соседние ID около 2^53, максимум int64, вложенные объекты,
списки ID, обратную сериализацию, ошибочные значения и безопасный вывод текста.
Источник библиотеки — [lossless-json](https://github.com/josdejong/lossless-json).
