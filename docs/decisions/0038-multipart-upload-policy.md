# ADR-0038: параметры прямой multipart-загрузки

Статус: принято пользователем 2026-11-13; часть Q05 о загрузке закрыта.

## Решение

Браузер запрашивает начало загрузки и получает идентификатор, размер частей,
подписанные URL и срок их действия. Части исходного файла — по 16 МиБ,
последняя содержит остаток. Рекомендуемый параллелизм клиента — до 4 частей.
Подписанные URL для PUT частей действуют 15 минут; владелец может обновить
их после повторной проверки сессии и прав. Ключи S3 браузеру не передаются.
Это ссылки передачи, независимые от ссылок просмотра публикаций.

Незавершённая загрузка истекает после 24 часов без активности; временные
части удаляются, метаданные публикации сохраняются. Согласованные ранее
лимиты 5 ГБ и 60 минут не пересматриваются. В API 5 ГБ — 5 000 000 000 байт.
Реальный размер проверяется по хранилищу; длительность — на следующем этапе ffprobe.

## Реализация и границы

Постоянное намерение создаётся в PostgreSQL до обращения к RustFS. Случайный
ключ временного исходника принадлежит загрузке публикации, а не общему контенту.
После доверенной проверки слепка будущий конвейер свяжет несколько публикаций
с общей физической копией. Владелец публикации не становится владельцем
общего медиаобъекта.

Вход частей — отдельный PUT-маршрут Nginx → RustFS с фиксированным upstream/Host;
FastAPI не принимает байты. Подписываются номер части, uploadId и Content-Length.
Перед завершением сервер сам получает перечень частей и проверяет номера/размеры.
Повтор после сбоя Complete или commit восстанавливается по HEAD закрытого объекта.
added_at берётся из подтверждённого LastModified и не меняется повторно.

Очистка сериализуется с завершением через блокировки PostgreSQL. Служебный
worker Procrastinate выполняет её отдельно от будущего тяжёлого медиаконвейера;
ошибки сохраняются в техническом журнале. Совместимость S3-вызовов и подписей
проверяется на установленном RustFS.
