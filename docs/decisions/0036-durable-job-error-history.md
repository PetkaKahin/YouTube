# ADR-0036: постоянная история ошибок и резервный файловый буфер

Статус: принято пользователем 2026-11-13; часть Q36 о хранении закрыта.

## Решение

История ошибок всех попыток фоновых заданий хранится в PostgreSQL без
автоматической очистки. При отказе БД очищенные от секретов события остаются
в отдельном постоянном Docker-томе и переносятся в PostgreSQL после восстановления.
Рестарт приложения не должен терять уже записанные в буфер события.

## Причина и последствия

Постоянная диагностика нужна для будущего повтора упавших джоб из админ-панели.
Вывод в Docker logs и последнее состояние очереди не заменяют историю.
Резервный буфер покрывает также отказ БД, хотя приложение вероятнее завершится
раньше неё. Буфер не исполняет задачи и не заменяет Procrastinate.

Перенос должен быть идемпотентным; очистка очереди не удаляет историю.
Неподтверждённые и повреждённые события не удаляются автоматически. Потеря
самого тома/диска этим решением не покрывается; отказ записи нельзя скрывать.
Бюджет попыток после ручного запуска остаётся решением T12.
