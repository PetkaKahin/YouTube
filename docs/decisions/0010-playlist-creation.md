# ADR-0010: создание плейлистов и выбор для видео

Статус: принято пользователем. Дата: 2026-11-12.
Часть о видимости и доступе по email заменена [ADR-0011](0011-playlist-visibility.md).
Расширяет первоначальный объём R03 требованием R16; закрывает бизнес-часть Q06 и Q14.

## Контекст

В исходном ТЗ был показ плейлистов на канале, а способ наполнения не был
определён. При разборе Q06 пользователь явно добавил создание плейлистов
и их выбор в настройках видео в личном кабинете.

## Решение

Пользователь создаёт плейлисты. В ЛК в настройках видео находится выпадающий
список плейлистов с независимыми галочками; можно выбрать любое их число,
включая все. Одно видео может входить в несколько плейлистов.
При дальнейшем разборе пользователь согласовал обязательное название
и необязательное описание. Первоначальный выбор двух режимов видимости
с доступом по email отменён: актуальные public/unlisted/private без списка
приглашённых описаны в [ADR-0011](0011-playlist-visibility.md).
Новое видео добавляется в конец плейлиста; ручная перестановка в проекте
не предусмотрена. Порядок выбран пользователем для этого проекта.
Доступ к плейлисту не открывает приватные видео внутри него: разрешения
на видео выдаются отдельно, их видимость и список разрешённых email не меняются.
Канонические правила — в [Channel](../backend/modules/channel.md),
экран — в [спецификации фронтенда](../frontend/screens.md).

## Последствия

Прежнее ограничение только показом плейлистов заменено явным дополнением
пользователя. В объём входит ЛК с указанными настройками видео.
Связями с плейлистами владеет Channel; права на видео по-прежнему определяет Video.
Галочки сохраняют включение без дублирования и не удаляют сам файл при снятии.

Бизнес-часть Q06 и Q14 закрыты. Детали UI, включая место открытия формы,
пользователь перенёс на этап разработки интерфейса (Q07).
Удаление/переименование плейлистов и остальные разделы ЛК пока не согласованы.
[Открытые вопросы](../tasks/open-questions.md). Реализация ещё не начата.
