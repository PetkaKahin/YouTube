# ADR-0018: настройки приложения через Docker

Статус: принято пользователем 2026-11-12; часть о секретах заменена
[ADR-0019](0019-compose-secrets.md). Уточняет расположение env из
[ADR-0017](0017-docker-environment.md).

## Решение

Корневой `.env.example` с несекретными значениями хранится в репозитории,
локальный `.env` игнорируется Git и исключается из контекстов сборки.
Настройки контейнеров и версии образов остаются в `docker/`.
Compose читает локальные значения и передаёт каждому сервису явно указанные
переменные окружения. Приложение получает их из окружения процесса без чтения
env-файлов или установки dotenv. Node получает только необходимые ему настройки.

`docker/run init` создаёт `.env` из шаблона, добавляет новые отсутствующие ключи
и генерирует пустые секреты внутри Docker, сохраняя уже заданные значения.
Ни env-файл, ни пароли не добавляются в образ приложения.

## Последствия

Один шаблон перечисляет пользовательские настройки, а Compose определяет,
какие из них доступны каждому сервису. Изменения применяются пересозданием
контейнеров. Ignore-правила поддерживаются и в корне, и в отдельных
Dockerfile-specific файлах: последние заменяют корневой `.dockerignore`.
Команды и проверенное состояние — в [Docker](../infrastructure/docker.md).
