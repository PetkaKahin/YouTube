# ADR-0046: преобразование HDR без обязательного GPU

Статус: принято пользователем 2026-11-13; техническая основа реализована
и проверена на Linux/amd64. Позднее преобразование подключено к отдельным
заданиям: [текущее состояние](../backend/encoding.md).
Закрывает выбор механизма преобразования из Q03, дополняет
[ADR-0045](0045-hdr-and-sdr-versions.md).

## Решение

- Серверная обработка должна работать в Docker без видеокарты, GPU-драйверов
  хоста и передачи видеоустройств контейнеру. AV1 кодируется на CPU через SVT-AV1.
- Нормализация HDR и HDR→SDR используют фильтр FFmpeg `libplacebo`.
  Тональное преобразование — BT.2390 со штатными настройками установленной версии.
- В общий слой Python Dockerfile добавлен `mesa-vulkan-drivers`.
  `VK_DRIVER_FILES=/usr/share/vulkan/icd.d/lvp_icd.json` явно выбирает
  программный Vulkan Mesa/Lavapipe. Это вычисления на CPU, а не требование GPU.
  `dev` и `prod` наследуют один механизм от `base`.
- Вызов FFmpeg явно создаёт устройство `-init_hw_device vulkan=cpu:0`
  и передаёт его фильтру через `-filter_hw_device cpu`. Одного выбора ICD
  недостаточно: автоматический поиск устройства `libplacebo` отбрасывает
  программное устройство; это обнаружено при квалификации.
- Путь ICD одинаков в пакетах Debian trixie для amd64 и arm64. Наличие
  пакетов на обеих архитектурах не заменяет запуск на обеих архитектурах.
  Работоспособность проверяется на доступном Docker-хосте и в пределах
  поддерживаемой архитектуры/достаточных CPU, RAM и диска; гарантия любого
  физического железа без проверок не заявляется.

## Границы этапа

Этап технический: Docker и проверка медиазависимостей. БД, бизнес-логика,
API и подключение обработки к очереди не меняются. B10/B13–B19 не закрываются.
Наличие фильтра и успешная проба не доказывают поддержку любого профиля
Dolby Vision, сохранение всех HDR-метаданных или визуальное качество.
Согласованные профили цвета/качества остаются по ADR-0043–0045.

До изменения образа проба одного кадра завершилась
`VK_ERROR_INCOMPATIBLE_DRIVER`: в образе не было Vulkan ICD.
Ресурсные пределы production worker остаются открытыми в Q03.

## Результаты квалификации

Собраны `base` и отдельные проверочные образы `dev`/`prod` из общего Dockerfile.
Установлены FFmpeg `7.1.5-0+deb13u1`, libplacebo `7.349.0-3`, Mesa Vulkan
`25.0.7-2+deb13u1`, Vulkan loader `1.4.309.0-1`.

[Проверка медиазависимостей](../../docker/python/check_media.py) добавлена
в `docker/run check` и отдельно прошла в обоих проверочных образах.
Контейнеры работают от app (UID 1000), без передачи GPU-устройств,
с `--network none`, `--cap-drop ALL`, `no-new-privileges`, 2 CPU и 1 ГиБ памяти.
Проверены:

- Создание именно программного устройства Lavapipe/llvmpipe.
- Отказ без создания результата при недоступном явно выбранном ICD,
  без автоматического выбора другой видеокарты.
- Четыре синтетических случая PQ/HLG → BT.709/PQ через BT.2390, последующее
  кодирование AV1 и декодирование двух кадров. Размер 64×64, 10 бит 4:2:0,
  цветовые поля проверены через ffprobe. При смене представления проверено
  изменение пикселей до сжатия, а не только тегов.

Короткая синтетическая проверка заняла 6,58 с в dev и 6,29 с в prod;
максимальный RSS отдельного дочернего процесса — 200,1/198,3 МиБ.
Это не бенчмарк 4K и не лимиты будущего worker. Настройки параллелизма пробы
`LP_NUM_THREADS=2`/SVT `lp=2` относятся только к проверке. Позднее уточнено:
в SVT 2.3.0 `lp` задаёт уровень, а не точное число потоков —
[ресурсные замеры](../backend/media-resources.md).

Дополнительно в prod на CPU проверены два кадра каждого публичного образца
FFmpeg FATE с уменьшением до 64×64 для технической квалификации:

| Образец | Размер | SHA-256 |
| --- | --- | --- |
| [dv84.mov](https://fate-suite.ffmpeg.org/hevc/dv84.mov), Dolby Vision 8.4 | 3 621 742 байта | `aaa9289a9755eaebd9962204f24a6acf8a19ff104657a3a79b6b1fa672993721` |
| [hdr10_plus_h265_sample.hevc](https://fate-suite.ffmpeg.org/hevc/hdr10_plus_h265_sample.hevc), HDR10+ | 77 718 байт | `663bd5179571133660a1e8ac260aa1f5bf8ce61d33dedb828a1cd7188771abcc` |

Входные динамические метаданные обнаружены декодером; оба образца
преобразованы в AV1 PQ/BT.2020 и AV1 BT.709 с проверенными цветовыми полями.
В результатах нет Dolby Vision/HDR10+ и DOVI container record; статические
HDR10-метаданные второго образца сохранились в PQ-результате и отсутствуют
в SDR. Образцы скачивались в удаляемый контейнер, в репозиторий не добавлены;
обычная проверка не зависит от сети или этих внешних файлов.

Эти пробы не проверяют бизнес-порог HDR 1080p+, всю длительность/разрешение,
визуальное качество или все профили Dolby Vision; это остаётся до реализации
медиаконвейера. На arm64 подтверждён состав пакета, runtime не запускался.
Ruff/Formatter, Basedpyright, оба Tach и `uv audit --locked` прошли;
аудит не нашёл известных уязвимостей в 85 пакетах. Полный pytest/HTTP smoke
не запускался: код приложения и бизнес-сценарии этим этапом не изменены.

По применимости правил тестирования: проверены непривилегированный запуск,
работа без сети/GPU, ограниченная проба и отказ зависимости. Новых входных
HTTP-контрактов, операций с БД/сессиями/хранилищами или пользовательского ввода
нет; их проверки этим техническим этапом не подменяются.
