# ADR-0032: отдельные ссылки публикаций и слепки дорожек

Статус: требования пользователя приняты 2026-11-13; уточняет ADR-0031.
Q33/Q34 закрыты; сжатые дорожки и учёт технических параметров выбраны в
[ADR-0033](0033-compressed-content-fingerprints.md).
Слепки сжатых дорожек и общие записи реализованы частично 2026-11-14 —
[проверка дорожек](../backend/track-fingerprints.md). Выдача медиассылок ещё впереди.

## Принятые требования

- У каждой логической публикации/источника собственная медиассылка, даже когда
  физический контент общий. Разрешение проверяется относительно этой публикации
  для каждого защищённого медиазапроса. Ссылка общего физического объекта или его
  хеш не заменяют проверку прав и не становятся универсальным доступом к копиям.
- Совпадение определяется побайтовым содержимым дорожек без описательных
  метаданных контейнера. Доверенные слепки исходных видеодорожек, аудиодорожек
  и превью сохраняются на серверной стороне до конвертации в целевые форматы.
- При подтверждённом совпадении переиспользуются имеющиеся совместимые данные;
  дублирующий исходник удаляется без повторной конвертации. Для ещё не готовой
  общей обработки не создаётся второй независимый комплект одинаковых заданий;
  необходимые недостающие результаты остаются фоновой работой.
- Это точное сравнение содержимого, а не поиск визуально похожих/украденных
  роликов. Клиентский хеш не является доверенным доказательством совпадения.

Глобальный пул, независимые права публикаций и хранение до освобождения всех
пользовательских ссылок сохраняются по ADR-0031.

## Метаданные и безопасность совпадения

Описательные теги вроде автора, заголовка или времени создания файла можно
исключать из слепка. Однако временная шкала, взаимное смещение дорожек,
параметры декодирования, поворот и цветовые/HDR-характеристики способны влиять
на воспроизведение. Они не объявляются мусором. Заявленная длительность не
заменяет проверку реальной длительности по правилам конвейера.
Совпадение только видеодорожки не позволяет отбросить отличающуюся аудиодорожку
или субтитры; состав логического видео сохраняется при переиспользовании частей.

## Разобранные варианты Q34

При разборе сравнивались основы точного слепка:

1. Сжатые данные исходной дорожки после извлечения из контейнера — без
   декодирования; плюс значимые параметры и нормализованный тайминг.
2. Декодированные кадры/аудиосэмплы — без повторного кодирования; также с учётом
   значимых параметров и тайминга. Формат точного представления ещё не выбран.

FFmpeg позволяет считать отдельные хеши потоков. Его hash/streamhash игнорируют
timestamps; при настройках по умолчанию данные декодируются в raw video/audio.
Поэтому готовая команда без продуманного слепка недостаточна для решения Q34.
Пользователь выбрал первый вариант; правила и результат следующей пробы — ADR-0033.
Источник: [FFmpeg: streamhash](https://ffmpeg.org/ffmpeg-formats.html#streamhash),
проверен 2026-11-13.

## Техническая проба

В Docker на установленной сборке FFmpeg создан односекундный синтетический
MPEG-4 в MP4. При stream copy смена title/artist изменила файл, но сохранила
хеш видеодорожки. Изменение тайминга через itsscale сохранило тот же хеш,
но ffprobe показал длительность 1,8 секунды вместо 1. Это подтверждает необходимость
учёта временной шкалы; выбор первого или второго способа пробой не принимается.
