# ADR-0051: начальные пределы медиаворкера

Статус: принято пользователем 2026-11-14; контроль процесса проверен в dev/prod.
Закрывает численные пределы Q03
и дополняет [ADR-0050](0050-worker-resource-configuration.md).

| Параметр | Значение по умолчанию |
| --- | --- |
| Docker CPU | 2 CPU; пулы по эффективным quota/affinity/cpuset |
| RAM worker | 8 ГиБ, без дополнительного swap |
| Временный рабочий каталог | Остановка при превышении 32 ГиБ |
| Резерв свободного места на разделе | Не менее 2 ГиБ |
| Нет продвижения позиции/кадров/байтов | 30 минут |
| Одна попытка | Не более 7 суток |

Значения изменяются несекретной конфигурацией под сервер. Измеренные
начальные уровни SVT: 1 при CPU-бюджете менее 2, 2 от двух доступных CPU;
пулы FFmpeg/Mesa — целая часть бюджета, минимум 1. Это не точное число
потоков внутри SVT; квота CPU обеспечивается Docker.

Дисковый порог проверяется перед запуском, во время работы раз в секунду
и после завершения: это программная проверка с возможным превышением между
опросами, а не жёсткая файловая quota. Рабочие файлы на дисковом томе, не tmpfs.

При распознанном превышении останавливается группа текущего процесса:
SIGTERM, 5 секунд ожидания, затем SIGKILL. Причина сохраняется в постоянном
журнале при подключении заданий. Неполный результат не готов; оригинал и
уже готовые варианты сохраняются. Повтор с тем же заведомо недостаточным
бюджетом автоматически не запускается. Временные I/O-сбои и потеря worker
по-прежнему следуют ADR-0035, повторы и heartbeat не меняются.

## Граница реализации

Инфраструктурный контроль subprocess и изолированная проверка
с Compose-ограничениями реализованы. БД, домен/сценарии и HTTP не меняются; тяжёлая очередь,
постоянная запись причины конкретного задания и публикация медиа пока не подключены.
Источник правил и результаты — [ресурсы медиа](../backend/media-resources.md).
