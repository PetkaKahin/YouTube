# ADR-0005: валидация регистрации

Статус: принято пользователем. Дата: 2026-11-11.
Закрывает Q01 после [ADR-0002](0002-registration.md),
[ADR-0003](0003-channel-identity.md) и [ADR-0004](0004-sessions-and-roles.md).

## Контекст

Для учебного проекта нужна простая валидация регистрации.
Пользователь уточнил пределы имени и пароля и исключил проверку существования почты.

## Решение

Имя — 2–50 символов. Email проходит обычную проверку формата, без проверки
существования ящика. Пароль — 6–128 символов без жёстких требований к составу;
повтор должен совпадать. Канонические правила — в [User](../backend/modules/user.md).

## Последствия

Регистрация не зависит от DNS/SMTP и не включает письмо подтверждения.
Занятость email проверяется среди аккаунтов проекта, чтобы обеспечить вход.
Минимальная длина пароля выбрана пользователем для учебного проекта.
Фронтенд и бэкенд используют одинаковые правила; окончательная проверка на сервере.

Q01 закрыт; [оставшиеся вопросы](../tasks/open-questions.md).
Позднее при согласовании разрешений по email появился отдельный Q13 о проверке
владения адресом для приватного просмотра; [ADR-0009](0009-private-access-by-email.md).
В ответе на Q13 пользователь подтвердил доверие email из регистрации и для
приватного просмотра; подтверждение почты не требуется. Q13 закрыт в ADR-0009.
Реализация ещё не начата.
