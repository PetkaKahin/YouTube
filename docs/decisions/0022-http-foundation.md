# ADR-0022: HTTP-основа бэкенда

Статус: принято пользователем 2026-11-12; реализация в [T02](../tasks/T02-backend-foundation.md).

## Решение

- Прикладные маршруты версионируются: внешний `/api/v1/...`.
  Nginx снимает `/api`; FastAPI сохраняет `root_path=/api`.
- Swagger UI доступен через `/api/docs`, внешний `/docs` ведёт туда.
  OpenAPI остаётся `/api/openapi.json`, вне версии прикладных маршрутов.
- Ошибки используют RFC 9457, `application/problem+json`. Расширения:
  машинный `code`, `request_id`, список ошибок полей `errors`.
- Входные JSON-схемы проверяют типы строго, без автопреобразования.
  Неизвестные поля игнорируются и не передаются сценарию. Вложенные схемы
  наследуют то же правило. Path/query приходят строками по протоколу HTTP;
  их разбор описывается соответствующим контрактом отдельно.
- Ошибки и журналы не включают тело запроса, пароли, cookie, CSRF-токены,
  содержимое secret-файлов или внутренние тексты исключений.
- Cookie: SameSite=Lax, сессионная — HttpOnly; обе — Secure в prod,
  локальный dev по HTTP — без Secure. CSRF-токен передаётся в X-CSRFToken,
  его cookie читается фронтендом. Пользователь подтвердил параметры (Q24).

## Последствия

Общие схемы и обработчики переиспользуются всеми будущими модулями.
Игнорирование поля роли не даёт права назначить её: сценарий регистрации
сам определит роль `user`. Аутентификация и бизнес-права реализуются отдельно,
выбранная библиотека или наличие middleware не доказывают их готовность.
