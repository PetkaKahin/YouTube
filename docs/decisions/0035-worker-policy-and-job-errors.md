# ADR-0035: параметры worker и история ошибок фоновых заданий

Статус: принято пользователем 2026-11-13. Q02 закрыт.
Требования согласованы; production worker, журнал ошибок и админ-панель пока не реализованы.

## Параметры первой реализации

| Параметр | Согласованное значение |
| --- | --- |
| Тяжёлые задачи | 1 одновременно на worker; лёгкое обслуживание/recovery отдельно от занятого тяжёлого слота |
| Временные ошибки | 3 запуска всего: первый запуск и 2 повтора |
| Задержки повторов | 30 секунд, затем 2 минуты |
| Heartbeat | Каждые 10 секунд |
| Признак потерянного worker | Нет heartbeat 60 секунд |
| Проверка восстановления | Каждые 15 секунд |

Согласовано для учебного проекта. Это не ограничения CPU/RAM/диска/времени FFmpeg:
ресурсные ограничения и медиапрофили остаются в Q03.
При настройке Procrastinate учитывается проверенная семантика 3.11.0:
max_attempts=2 соответствует трём запускам всего, а не двум.

## Ошибки и будущая админ-панель

Пользователь требует фиксировать ошибки всех фоновых заданий, чтобы впоследствии
одним действием из админ-панели повторно запускать упавшие джобы.
Историю нужно закладывать при реализации worker, до появления панели.
Полные требования к хранению и безопасному повтору —
[фоновые задания и диагностика](../backend/background-jobs.md).

Административный экран и ручной перезапуск — отдельное согласованное дополнение
R17, отложенное в [T12](../tasks/T12-job-administration.md). Конкретные формы,
выбор набора заданий и другие детали UI обсуждаются при реализации панели.
