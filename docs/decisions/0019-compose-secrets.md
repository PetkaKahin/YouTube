# ADR-0019: все чувствительные значения через Compose Secrets

Статус: принято пользователем 2026-11-12. Заменяет передачу секретов через
environment и их генерацию в `.env` из [ADR-0018](0018-application-environment.md).
Размещение `.env.example` и несекретные настройки остаются прежними.

## Решение

Пароли, токены, ключи и прочие секреты предоставляются через Compose Secrets
как файлы `/run/secrets/`. В обычном environment находятся адреса, названия
и пути `*_FILE`, без значений секретов. Каждый сервис получает только нужные файлы.
Node/Nginx секреты не предоставляются.

`docker/run init` создаёт отсутствующие файлы в игнорируемом `docker/secrets/`,
сохраняет существующие значения, переносит старые пароли/ключи из `.env`
и удаляет соответствующие env-записи после сохранения файлов.
Конфликтующие значения требуют явного разрешения; автоматически пароль не меняется.
Файлы и значения не включаются в образы, Git, аргументы команд проекта или логи.

## Последствия

PostgreSQL и RustFS используют штатные `*_FILE`; Valkey получает ACL с хешем
в tmpfs, а healthcheck — пароль через stdin. Python читает файлы напрямую,
проверяет их до старта API и исключает значения из repr объекта настроек.
Локальный Compose монтирует файлы хоста и сам не шифрует их на диске;
права каталога/файлов и порядок обновления описаны в [Docker](../infrastructure/docker.md).
Dev/prod и аудит секретов выполнены 2026-11-12; фактический результат —
в [T01](../tasks/T01-docker.md).
