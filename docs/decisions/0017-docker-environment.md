# ADR-0017: Docker-окружение

Статус: решения пользователя приняты 2026-11-12; dev/prod собраны и проверены.
Результат и исправления запуска — [T01](../tasks/T01-docker.md).

## Решение

- Compose-файлы находятся в корне; Dockerfile, конфигурации, скрипты и окружение —
  в `docker/`, с каталогами `python`, `node`, `nginx`, `valkey`, `rustfs`.
- Python, Node и Nginx имеют ровно `base`, `dev`, `prod`;
  `dev` и `prod` напрямую наследуются от `base`.
- Используем LTS/поддерживаемые стабильные ветки и закреплённые версии.
  Пакетный менеджер фронтенда — npm.
- Nginx раздаёт собранную SPA и проксирует API. Node собирает статику;
  Compose передаёт результат в сборку Nginx через `additional_contexts`.
- Инициализация секретов и lock-файлов, проверки, сборки и запуск выполняются
  в Docker; PostgreSQL и RustFS сохраняют данные в именованных томах.

## Причины и последствия

Это фиксирует ответы пользователя по окружению и сохраняет наследование из
[ADR-0001](0001-foundation.md) без переноса инструментов на хост.
Готовые образы PostgreSQL/Valkey/RustFS не требуют собственных Dockerfile.
Nginx получает статику без установки Node в HTTP-образ.
Для зависимых сборок нужны BuildKit и актуальный Compose.
LTS не является названием релизов всех компонентов; конкретная политика и
версии приведены в [Docker](../infrastructure/docker.md).

Worker, ORM/миграции, защищённая медиараздача и установка на чистую Ubuntu
сохраняют свои открытые решения и не входят в минимальный bootstrap.
Отсутствие доступа к daemon не заменяется запуском npm/uv на хосте.
