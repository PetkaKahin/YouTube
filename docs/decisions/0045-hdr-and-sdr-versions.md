# ADR-0045: HDR и SDR для HDR-исходников

Статус: принцип, лестницы, профиль качества и выходные цветовые представления
приняты пользователем 2026-11-13; механизм выбран в
[ADR-0046](0046-cpu-hdr-conversion.md).
Медиаконвейер ещё не реализован.

## Решение

- Для поддержанного HDR-исходника сохраняем HDR в 10-битных вариантах AV1
  и дополнительно готовим SDR-варианты в AV1 с тональным преобразованием
  для просмотра на обычных экранах.
- Для обычного SDR-исходника готовим только SDR; искусственный HDR не создаём.
- SDR готовим во всей допустимой исходником лестнице. HDR — только для
  1080p, 1440p и 2160p, когда исходник позволяет их без увеличения разрешения.
  Следствие: у HDR-исходника ниже 1080p будут только SDR-варианты, без HDR
  в выдаче или плеере. Порог применяется к качеству с учётом ориентации
  по правилам лестницы, а не только к буквальной высоте кадра.
- Для SDR действует профиль ADR-0043. Для HDR 1080p+ приняты тот же preset 6,
  один проход, `tune=0` и соответствующий этой группе CRF 28.
  Качество HDR ещё требуется проверить на примерах.
- Пользователь выбрал обычный HDR для готового результата; другие HDR-форматы
  должны преобразовываться в него. Требование не сводится к использованию
  только совместимой базы HDR10/HLG: отсутствие базы само по себе не является
  согласованным основанием отказа. Нужна корректная обработка цвета и метаданных,
  а не их удаление или смена тегов без преобразования изображения.
- Выходной обычный HDR — **HDR10**: PQ/SMPTE ST 2084, BT.2020, 10 бит,
  4:2:0 со значимыми статическими HDR-метаданными.
- SDR-версия HDR-исходника — BT.709, 10 бит, 4:2:0 после тонального
  преобразования. Для исходно SDR-видео сохраняются правила ADR-0044.
- Оба представления остаются в выбранном видеокодеке AV1. Дополнительная
  SDR-версия для HDR-исходника требует вычислений и хранения; пользователь
  согласовал эту стоимость ради просмотра на разных экранах.
- Публикации и права остаются общими для представлений одного видео.
  Переключение HDR/SDR не открывает приватный или скрытый контент.

## Следствия для надёжности

Готовность HDR и SDR проверяется по завершённым артефактам каждого варианта.
Ошибка одного не удаляет уже готовые результаты другого; правила раннего
просмотра и частичных ошибок сохраняются. Признак HDR возникает только
после готовности доступной зрителю HDR-версии. Готовое SDR того же разрешения
не заменяет HDR для фильтров, включая сочетание 4K + HDR.

Оригинал нужен для обоих наборов работ и их повторов. Его очистка происходит
только после завершения всех зависимых работ по
[ADR-0040](0040-temporary-originals.md), а не сразу после готовности одного
из представлений.

## Механизм и оставшаяся реализация

Выбраны FFmpeg/libplacebo, программный Vulkan Mesa/Lavapipe на CPU и
BT.2390 со штатными настройками установленной версии — ADR-0046.
Динамические HDR-метаданные не обязаны оставаться динамическими в обычном
HDR-результате, но необходимые сведения должны учитываться при корректном
преобразовании. Значимые исходные метаданные для слепка дедупликации
сохраняются по ADR-0033. Технические пробы и их границы — в ADR-0046;
бизнес-конвейер и его приёмка ещё впереди.
