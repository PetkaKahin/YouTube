# ADR-0034: SHA-256 и Procrastinate

Статус: принято пользователем 2026-11-13. Q35 закрыт;
библиотека и алгоритм выбраны. Параметры Q02 позднее согласованы в ADR-0035.

## Решение

- Итоговый digest версионированного слепка — SHA-256. Он вычисляется на серверной
  стороне по сжатому содержимому и значимым техническим параметрам по ADR-0033.
  Дополнительная библиотека для самого SHA-256 не требуется.
- Фоновая очередь — Procrastinate с PostgreSQL и Psycopg 3. Собственный движок
  очереди не пишется. Valkey не участвует в сохранности заданий.
- Выбор библиотеки не заменяет проверку её интеграции: нужны реальные транзакции,
  повторы, конкуренция, сохранность после рестарта и восстановление после гибели worker.

## Текущий этап

Сначала устанавливается закреплённый релиз и проверяется совместимость с Python
3.14/SQLAlchemy/Psycopg на изолированной БД в Docker. Изменение постоянной схемы
приложения и production worker на этом этапе не выполняются; библиотечная схема
создаётся только в тестовой БД. Бизнес-логика, HTTP и конвейер видео ещё не реализуются.
Это техническая проверка выбранной зависимости, а не готовность B13/B19.

Параметры Q02 согласованы в [ADR-0035](0035-worker-policy-and-job-errors.md).
Остаются Q03: медиапрофили и ресурсы; Q05: параметры прямой загрузки и защищённая раздача.

## Проверка выбранной зависимости

Установлен Procrastinate 3.11.0, обновлён uv.lock. Dev/prod собраны;
импорт версии проверен и в prod без dev-зависимостей. На реальном PostgreSQL
прошли семь интеграционных проверок, включая совместный commit/rollback
с SQLAlchemy и восстановление после SIGKILL. Полный make test: 316 passed.
