# ADR-0020: библиотеки данных, сессий и политик

Статус: принято пользователем 2026-11-12. Установка и базовая интеграция
выполнены в [T02](../tasks/T02-backend-foundation.md); бизнес-сценариев пока нет.

## Решение

Последующее уточнение: [ADR-0028](0028-session-concurrency.md) сохраняет starsessions,
но заменяет штатный RedisStore нашим расширением SessionStore вне пакета для Q25.
Исходное решение ниже сохраняет контекст первоначальной установки библиотек.

Основа следующего этапа: SQLAlchemy ORM + Psycopg 3, Alembic, pwdlib[argon2],
pydantic-settings, email-validator без DNS-проверок и boto3 для RustFS.

Для механизмов защиты используются готовые библиотеки:

- starsessions[redis] с RedisStore — серверные сессии в Valkey;
- redis-py — клиент Valkey для сессий и кэша без собственного адаптера;
- starlette-csrf — CSRF middleware;
- PyCasbin (пакет casbin) — движок политик ролей и атрибутов ресурсов.

## Причины и последствия

Пользователь потребовал готовые инструменты для управления сессиями и исполнения
политик вместо собственных механизмов. Сохраняются существующие бизнес-правила:
30 дней без активности, продление сессии, роли, владение и приватный доступ.
Casbin исполняет описанные нами бизнес-политики; проверка не ограничивается
HTTP-маршрутами. ORM и библиотеки безопасности не становятся зависимостями домена.

Версии закрепляются при установке после проверки в Docker на Python 3.14 и
текущем FastAPI/Starlette. Нужны тесты rolling TTL/cookie, регенерации ID, выхода,
потери Valkey, конкурентных запросов, CSRF и отзыва прав без устаревшего кэша.
Ключи конфигурации передаются через Compose Secrets. Выбор не подтверждает
runtime-совместимость или уже реализованную защиту.

Подробности, источники и состояние — [библиотеки бэкенда](../backend/libraries.md).
Q10 и Q20 закрыты по выбору инструментов. Библиотека очереди PostgreSQL остаётся Q02;
JWT и дополнительное шифрование не добавляются без отдельного сценария.
