# ADR-0043: профиль качества SDR-видео

Статус: принято пользователем 2026-11-13; часть Q03 о качестве SDR согласована.
Кодирование подключено и проверено на синтетических примерах;
визуальная приёмка на реальных экранах остаётся впереди —
[текущее состояние](../backend/encoding.md).
Дополняет [ADR-0039](0039-av1-encoding.md).
Частота кадров и формат SDR позднее согласованы в
[ADR-0044](0044-frame-rate-and-sdr-depth.md).

## Решение

- Обычное SDR-видео кодируем в AV1 через SVT-AV1 с согласованным preset 6.
- Режим — однопроходный CRF, настройка на визуальное качество `tune=0`.
  CRF задаёт ориентир качества, а не фиксированный битрейт или размер файла.
- Начальные параметры по выходному качеству:

| Качество видео | CRF |
| --- | --- |
| 360p и ниже | 34 |
| 480p | 32 |
| 720p | 30 |
| 1080p, 1440p, 2160p | 28 |

Числа выбраны для проекта и приняты пользователем, это не опубликованный
профиль YouTube. Они не гарантируют незаметных потерь для любого исходника.
При реализации проверить движение, мелкий текст, тёмные сцены, градиенты
и исходники ниже 360p. Последние должны сохранять разборчивость без увеличения
разрешения. Менять согласованные значения по результатам проверки без
согласования нельзя.

## Оставшиеся решения и проверка

HDR позднее согласован в [ADR-0045](0045-hdr-and-sdr-versions.md)
и [ADR-0046](0046-cpu-hdr-conversion.md), упаковка HLS — в
[ADR-0047](0047-hls-packaging.md). Отсутствие дополнительного потолка
видеобитрейта принято в [ADR-0048](0048-uncapped-video-crf.md).
Установка CRF не заменяет ограничения CPU/RAM/диска/времени worker.

В Docker ранее проверена справка текущего FFmpeg `libsvtav1`: доступны
`-preset`, `-crf` (0–63), `-svtav1-params`, форматы `yuv420p` и `yuv420p10le`.
Это наличие интерфейса кодировщика, а не проверка готового медиаконвейера.
