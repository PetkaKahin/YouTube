# ADR-0026: бизнес-тесты находятся внутри модулей

Статус: принято пользователем и настроено в T02, 2026-11-13.

## Решение

- Тесты сценариев, домена и адаптеров модуля находятся в
  `backend/src/<module>/tests/`, вместе с локальными фикстурами.
  При переносе модуля переносится и его тестовый пакет.
- `backend/tests/` содержит проверки приложения и общей инфраструктуры:
  HTTP, конфигурация, DI, секреты, архитектура, сквозные проверки.
  Существующие общие проверки туда и относятся; бизнес-сценариев пока нет.
- pytest обнаруживает тесты и в `tests`, и в `src`.
- Tach рассматривает `<module>.tests` как часть владельца модуля: ему доступны
  собственные `domain/application/infrastructure/public`, общие технические
  средства и разрешённые чужие `public`. Доступ к чужим внутренним пакетам
  и импорт тестового пакета из production-слоёв запрещены.
- Только внешние зависимости тестовых файлов исключаются из `check-external`:
  они используют dev-инструменты. Контроль их внутренних импортов сохраняется.
- Тесты исключаются из production wheel. Тестовые каталоги не нужны для сборки
  wheel; dev получает их через bind mount репозитория.

Новые бизнес-сценарии и их фиктивные тесты этой настройкой не создаются.
В Docker проверены обнаружение тестов, границы импортов, содержимое wheel
из исходников с тестовыми пакетами и отсутствие тестов в BuildKit-контексте Python.

Источник упаковки: [Hatch file selection](https://hatch.pypa.io/latest/config/build/#patterns),
проверен 2026-11-13.
