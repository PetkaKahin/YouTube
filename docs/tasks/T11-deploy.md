# T11 — установка одной командой и сброс dev

Статус: `done` — установщик и dev refresh реализованы и проверены в Docker.
Требование [R13](../project/requirements.md),
согласованные параметры — [Q09](open-questions.md#q09-установка-на-чистой-ubuntu).

## Согласованный объём

После распаковки архива на Ubuntu 24.04 LTS или 26.04 LTS достаточно
`bash install.sh`. Нужны сеть для apt/образов/зависимостей и root либо sudo.
Python, Node и обработчики видео устанавливаются внутри Docker.
Установщик поднимает dev по HTTP с настройками `.env`, как на локальной машине;
TLS, домен и внешний Nginx остаются настройкой разработчиков.

Перед работой задаётся `Использовать сидеры для заполнения тестовыми данными? (Y/n)`.
Пустой ответ означает да, EOF не считается ответом. После подготовки Docker
создаются недостающие `.env`/Compose Secrets, собираются образы, запускаются
хранилища, применяются миграции, затем стартуют API, worker, frontend и Nginx.
Сидирование выполняется только при положительном ответе. Повтор сохраняет
конфигурацию, secrets и данные. Существующий рабочий Docker используется повторно.

## Refresh

`make refresh` предназначен только для dev и удаляет его БД целиком.
Удаляются также временные сессии Valkey, буфер ошибок и рабочий том media_scratch
со старым seed-манифестом. RustFS с готовыми медиа, исходники проекта, `.env`,
secrets и зависимости frontend сохраняются. После миграций создаётся полный
[демонабор](demo-seed.md), включая администратора и активность.
Работающие контейнеры с конфигурацией prod блокируют сброс до удаления данных.
Глобальные Docker prune и удаление чужих томов не используются.

## Этапы и проверка

Изменяются инфраструктурные скрипты, Makefile и эксплуатационная документация.
Схема БД, бизнес-правила, HTTP API и UI не меняются.
Код: [install.sh](../../install.sh), [docker/run](../../docker/run),
[Makefile](../../Makefile). Профильная проверка сценариев —
[check_deploy.py](../../docker/python/check_deploy.py).

В Docker прошли 13 профильных сценариев: обе Ubuntu, ответы Enter/n/ошибочный/EOF,
сохранение конфигурации при повторе, Docker без группы и с остановленным daemon,
конфликтующие пакеты, старая Compose, отказ сборки, порядок миграций/worker,
изолированное удаление томов, отказ для prod и чужих томов, Make и синтаксис Bash.
ShellCheck, Ruff, форматирование и относительные ссылки затронутых документов прошли.

В отдельном настоящем Compose-проекте `make refresh` удалил старую контрольную
таблицу и создал 5 аккаунтов, 12 видео, 20 позиций просмотра и 15 плейлистов;
readiness через Nginx вернула ready. Рабочая dev-база в этом прогоне не использовалась.

Установщик выполнен из копий архива без `.git`, `.env` и secrets в контейнерах
Ubuntu 24.04 и 26.04. Установка apt-пакетов Docker/Compose/Buildx была реальной;
24.04 с ответом n запустила приложение с пустыми бизнес-таблицами, 26.04 с Enter
создала 5 аккаунтов и 12 видео с активностью. В обоих случаях HTTP readiness прошла.
В этих проверках использовался Docker daemon хоста и заглушка systemctl:
запуск daemon через systemd на отдельной чистой VM не проверялся.
Временные Compose-проекты, их тома и копии архива удалены.
Остальные тесты приложения, повторная обработка медиа и общий `make check` не запускались.

## PostgreSQL для IDE и начальная схема

По [ADR-0069](../decisions/0069-development-database-and-initial-schema.md) добавлены
POSTGRES_PORT и подключение IDE. По последующему [ADR-0070](../decisions/0070-secret-files-only.md)
пароль хранится только в `docker/secrets/postgres_password`, копия в `.env` отменена.
Dev публикует БД на loopback, prod — без порта. `install.sh` после установки
выводит адрес БД, указывает на параметры `.env` и отдельный файл пароля.

После изменения инфраструктуры прошли пять профильных сценариев: новая генерация
пароля, сохранение прежнего, кавычки/литеральные символы/конфликт и повтор подготовки,
установщик для обеих Ubuntu и повтор без сидов. ShellCheck, Ruff и форматирование
затронутых файлов прошли. Начальная схема — [отдельный профиль](../backend/database-schema.md).

Реальный `install.sh` выполнен с сидами в отдельном контейнере Ubuntu 26.04 из
копии архива без `.env`/secrets. Использован установленный Docker CLI и daemon
хоста; повторная установка Docker и запуск systemd в этом прогоне не проверялись.
Подтверждены HTTP readiness, 5 аккаунтов/12 видео, ревизия initial_030 и TCP-вход
через опубликованный порт с действующим паролем. Временный проект и тома удалены.
Рабочая dev-БД пересоздана через `make refresh` по явному разрешению пользователя.
После отмены копии пароля прошли пять профильных сценариев подготовки/установщика,
включая удаление старой записи из `.env` без смены secret. `make init` очистил
локальный `.env`; TCP-вход с паролем из `docker/secrets/postgres_password` прошёл.
Схема и данные БД на этом шаге не менялись.
