## Как вести задачи

Приёмка включает правильное поведение и применимые проверки безопасности:
утечки, инъекции, доступ, лимиты, конкуренцию и сбои по
[общим правилам тестирования](../testing.md). Без необходимых проверок задача
не считается готовой; пройденный позитивный сценарий этого не заменяет.
Объём проверок отдельной задачи и итогового прогона определяется
проектными скиллами [backend](../../skills/backend/SKILL.md#проверки),
[frontend](../../skills/frontend/SKILL.md#проверки) и [docs](../../skills/docs/SKILL.md#проверки).

У крупной задачи при начале работы появляется отдельный документ с нужным
контекстом, затронутыми модулями, шагами и критериями проверки; заранее пустые
карточки не создаются. Перед зависимой реализацией закрываются её вопросы.
По завершении записываются результат, реальные пути и фактическая проверка.
При обнаружении решения обновляются вопрос, профильный документ и ADR, если
оно меняет устойчивую архитектуру. Не добавлять в план функции сверх ТЗ.
