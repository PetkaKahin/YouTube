# Демонстрационные аккаунты, каналы и готовые видео

Статус: `done` — готовые пакеты заменили исходные MP4.

## Работающий контракт

`make seed` создаёт пять аккаунтов с каналами: администратора и четырёх обычных
авторов с 12 публичными природными роликами. У администратора пустой канал.
`make seed SEED_MODE=prod` использует работающий prod. Учебные логины
и пароль — в [README](../../README.md#тестовые-и-демонстрационные-данные).

В [backend/seed-media](../../backend/seed-media/README.md) хранятся уже готовые
AV1/AAC HLS, WebP-превью и проверенные технические метаданные. Исходные MP4
заменены этим набором. Доступны 360p, 480p и 720p; длительность 1–4 минуты.
Внешняя сеть, FFmpeg, инспектор и планировщик при обычном сидировании не нужны.

Сначала проверяются манифест и SHA-256 каждого файла, затем готовые пакеты
копируются в закрытый RustFS. После полной передачи одной транзакцией
создаются публикация, проверенный состав, план и готовые дорожки. Исходник
отмечен удалённым, как после обычной очистки завершённого видео.
Успех команды означает готовность всех сохранённых качеств и превью.

## Активность аккаунтов

После импорта всех роликов `make seed` добавляет активность пяти
подтверждённым тестовым аккаунтам, включая администратора. В свежем наборе каждый получает
четыре частичных просмотра с разными позициями, пять лайков, две или три
подписки на чужих авторов, три непустых плейлиста public/unlisted/private
с роликами разных каналов и три комментария. Часть роликов останется непросмотренной.

Используется существующий HTTP API с сессиями и CSRF; новые таблицы,
бизнес-сценарии, маршруты и обработка медиа не требуются. Повторные команды
лайков, подписок и включения в плейлист идемпотентны. Плейлисты узнаются
по постоянной метке в описании внутри своего канала, комментарии — по тексту
и имени подтверждённого демоавтора в обсуждении конкретного видео, с обходом
cursor-страниц по 20. Это также позволяет продолжить после потери ответа POST.
Существующая позиция просмотра и поставленный вручную дизлайк сохраняются.
Пользовательские комментарии и добавленные вручную элементы плейлистов не удаляются.
Для активности выбираются только публичные готовые seed-видео:
изменённые права и скрытие не отменяются.
Экспорт `--export-ready` активность не создаёт.

Координатор — [seed.py](../../backend/src/app/seed.py),
активность через API — [seed_activity.py](../../backend/src/app/seed_activity.py).

## Импорт и повторный запуск

Регистрация и вход используют существующий API; импорт выполняется доверенным
CLI через Video.public. Новых HTTP-маршрутов, библиотек и миграций нет.
Тестовый `admin.demo@example.com` после проверки ID аккаунта/канала
по seed-манифесту получает admin через User.public.SetRole. Повтор восстанавливает
admin только этому подтверждённому аккаунту. Совпавший email/тег без манифеста
или с чужими ID не приводит к назначению роли. Обычная регистрация по-прежнему
всегда создаёт user; администратор назначается только доверенной CLI-командой.
Существующие обязательные job_id относятся к завершённым записям операции
`video.import_prepared`: они сразу succeeded, не вызывают worker и не расходуют
попытки перекодирования. Ни todo, ни doing при импорте не создаются.

Импортированные файлы имеют адреса
`prepared/{profile_key}/{artifact_digest}/`. Дескриптор связан с профилем
и полным файловым манифестом; он переносится между БД с разными числовыми ID.
Путь разрешает только известные имена HLS/WebP. Произвольные пути, URL,
symlink, несовпадающие хеши и неполные результаты отклоняются.
Обычные ссылки HLS и превью сохраняют прежние проверки доступа.

При сбое БД метаданные откатываются. Уже переданные файлы остаются в конечном
адресуемом по содержимому наборе, без новых случайных префиксов на каждом
повторе; повтор проверяет их размер/хеш в metadata RustFS и дописывает остаток.
До полной передачи готовая публикация не фиксируется. Готовый общий результат
с другим дескриптором не перезаписывается.

Прогресс аккаунтов/публикаций хранится в Docker-томе media_scratch,
`/var/lib/youtube/media/demo-seed`, отдельно по имени БД. Повтор сохраняет ID,
проверяет владение и восстанавливает файлы из локального набора. Конфликт
email/тега без записи о владении останавливает команду без смены пароля/роли.
Файловая блокировка исключает два запуска с одним манифестом; импорт дополнительно
сериализуется в БД и повторно находит свою публикацию по постоянному маркеру.
Существующие названия/видимость публикаций и роли четырёх авторов не сбрасываются.

## Обновление набора

После однократной обычной обработки своих новых исходников:

```bash
./docker/run dev exec -T -e PYTHONPATH=/app/src media-worker python -m app.seed --export-ready
```

Команда использует ID текущего seed-манифеста, сохраняет полные готовые пакеты,
проверяет их и обновляет manifest.json. Только после полного экспорта удаляет
исходные MP4 из каталога набора. Версия 1 пакета поддерживает используемые
природные ролики с генерируемыми превью; встроенные субтитры и пользовательская
картинка при экспорте отклоняются явно. Обычный `make seed` экспорт не запускает.

Код: [CLI](../../backend/src/app/seed.py),
[сценарии Video](../../backend/src/video/application/prepared_media.py),
[хранилище](../../backend/src/video/infrastructure/prepared_media.py),
[проверка пакета](../../backend/src/video/infrastructure/prepared_bundle.py).

## Проверки

Профильный набор — 30 passed; затем отдельно прошёл дополненный сценарий
импорта с обычным фоновым восстановлением. Проверены свежая изолированная БД,
реальный RustFS, rollback после передачи файлов, повтор без повторного PUT,
переиспользование дорожек другим автором, ready/HD/превью, обычные HLS и Range,
private и отсутствие запуска кодировщиков или исполняемых заданий.
В [HTTP-тесте импорта](../../backend/tests/test_prepared_seed_import.py) запуск
медиапроцессов перехватывается через `asyncio.create_subprocess_exec`,
без обращения к внутренней инфраструктуре Video из общего теста.
Проверены hash/size, пути, symlink, форма ключей и точные bigint.
Ruff, форматирование и Basedpyright затронутых файлов прошли.
`make seed` сохранил текущие 12 ID без кодирования. Production-образ собран;
запуск встроенного набора с запретом внешних адресов и дочерних процессов
прошёл для всех 12 роликов, сохранив аккаунты и ID. Dev-образ media-worker
обновлён с готовыми файлами.
Общие проверки приложения не запускались.

Дополнение с администратором: **22 профильные проверки** сидера прошли в Docker,
включая свежую БД, повтор без дублей, восстановление admin при сохранении
изменённой роли автора, реальный вход и доступ к админскому API, отказ повышать
роль при конфликте/чужом манифесте. Медиа-конвейер повторно не проверялся.
Ruff, форматирование и Basedpyright затронутого кода прошли.

вход администратора и доступ к `/api/v1/admin/job-errors` подтверждены.
