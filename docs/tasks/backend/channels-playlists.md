Общие требования и зависимости — [реестр](README.md).

## B06. Показывать канал автора

**Описание.** Посетитель открывает канал, его публичные видео и плейлисты.

**Требования.** Канал создаётся в B01, имя пользователя является названием,
тег определяет уникальный канал; одинаковые имена разных авторов допустимы.
Видео канала — только публичные опубликованные нескрытые с готовым качеством.
Публичная часть плейлистов показывает только public. Приватные видео не добавляются
в публичный список приглашённого зрителя. Пустой канал остаётся доступным.

**Приёмка.** Гость открывает пустой и наполненный канал. Видео без готового качества,
черновик, private и hidden не раскрываются. Private/unlisted плейлисты отсутствуют
в публичной части; автор видит их отдельно в своём списке B26.
Редактирование профиля, оформление/баннеры и несколько каналов на аккаунт не добавляются.

## B07. Подписываться на чужой канал и отменять подписку

**Описание.** Пользователь сохраняет или снимает подписку на автора.

**Требования.** Действие доступно вошедшему пользователю для чужого канала.
У пары «подписчик, канал» одно состояние; повтор установки/снятия не дублирует
подписку. Собственный канал не является целью подписки.
Подписка не предоставляет приватный доступ и не создаёт уведомления/новую ленту.

**Приёмка.** Проверены подписка, отмена, гость, собственный канал, повторные
и одновременные запросы. Подмена подписчика не изменяет чужие подписки.
После подписки чужое private по-прежнему требует отдельного разрешения.

## B26. Создавать плейлисты и получать свой список

**Описание.** Автор создаёт плейлисты канала и получает их для управления своим видео.

**Требования.** Обязательное непустое название, необязательное описание,
режим public/unlisted/private. Public доступен всем и виден на канале/в поиске;
unlisted доступен любому, включая гостя, по ссылке, без обнаружения на канале/в поиске;
private — только вошедшему владельцу, включая прямую ссылку.
Свой список содержит все три режима. Приглашений по email у плейлистов нет.

**Приёмка.** Название из пробелов отклоняется; пустое описание принимается.
Плейлист принадлежит текущему автору и имеет выбранную видимость. Посторонний
не видит содержимое/метаданные private даже по известной ссылке.
Создание плейлиста не меняет настройки видимости видео.

## B27. Включать своё видео в любое число своих плейлистов

**Описание.** Автор сохраняет набор плейлистов для своего видео в его настройках.

**Требования.** Можно выбрать несколько, все либо ни одного своего плейлиста.
Включение добавляет новое видео в конец, исключение удаляет только связь,
сохраняя видео и остальные включения. Пара «плейлист, видео» уникальна.
Повтор сохранения не меняет позицию; удаление и новое включение добавляет в конец.
Ручной перестановки нет. Нельзя менять чужое видео или чужие плейлисты.

**Приёмка.** Проверены несколько/все/ноль выбранных плейлистов, независимость связей,
повтор и одновременное сохранение, сохранение порядка и новое включение после удаления.
Подмена владельца/плейлиста отклоняется. Даты изменения отражают реальные правки
состава, а неизменённое повторное сохранение не поднимает объекты в сортировке.

## B28. Читать плейлист без наследования прав на видео

**Описание.** Посетитель открывает разрешённый плейлист и его доступные видео.

**Требования.** Доступ к плейлисту определяется B26; к каждому элементу — B20/B21.
Порядок доступных элементов соответствует включению в плейлист. Чужое приватное
или скрытое видео не раскрывает метаданные/превью/ссылки через разрешённый плейлист.
Открытие public/unlisted плейлиста не выдаёт приватных разрешений на его видео.

**Приёмка.** Проверены все режимы плейлиста для гостя/владельца/постороннего,
смесь public/private/hidden видео и отдельное разрешение на видео. Владелец
private-плейлиста также не обходит собственные права на содержимое.
Отзыв доступа к видео действует при следующем чтении/просмотре из плейлиста.
