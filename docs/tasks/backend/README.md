# Бизнес-задачи бэкенда

Статус: **B01–B04/B08–B09 — done; B05/B12 — in_progress; остальные — todo**.
B08: черновики реализованы и проверены. B12: готовы метаданные/видимость
и чтение настроек владельцем; email/плейлисты и сквозной медиадоступ впереди.

## Общие требования к приёмке

Для всех B-задач обязательны применимые
[правила тестирования безопасности, утечек, инъекций и лимитов](../../testing.md).
Они дополняют критерии ниже и не обозначают уже выполненные проверки.

- Проверять права на сервере для каждой операции. Автор, владелец и роль определяются
  по подтверждённой сессии и серверным данным; подмена входных идентификаторов
  не разрешает чужое действие. Модератор не получает неограниченный обычный просмотр.
- Отсутствие доступа не раскрывает метаданные приватного объекта или ссылки
  на медиа через списки, счётчики результатов, превью, плейлисты и кэш.
- Повторные и одновременные запросы не нарушают явно заданные уникальности:
  email/тег, подписка, лайк, разрешение, элемент плейлиста, жалоба.
- Постоянные бизнес-данные и принятая фоновая работа сохраняются после рестарта
  и потери Valkey. Утрата сессии требует нового входа и не открывает приватные данные.
- Пароли/токены/ключи и персональные данные, не предназначенные получателю,
  не попадают в ответы и журналы. Пользовательский текст не исполняется как код.
- Сохранение без фактической правки не меняет порядок по дате изменения;
  лайки, подписки и фоновая обработка не считаются правками владельца.
- Для каждой задачи проверить успешный сценарий, отказ по правам, ошибки входных
  данных и перечисленные в ней повторы/сбои. Конкретный механизм проверки здесь не задаётся.

## Границы и оставшиеся решения

Не добавляются функции вне ТЗ: восстановление/подтверждение почты, OAuth,
редактирование аккаунта, удаление видео и комментариев, ответы на комментарии,
дизлайки, уведомления, лента подписок, рекомендации, апелляции, блокировки аккаунтов.
У видео только public/private; unlisted существует только у плейлистов.
Согласованные требования к UI остаются в профильных документах, здесь новых нет.

Бизнес-правил достаточно для описания этих задач. [Открытые вопросы](../open-questions.md)
не заменяются предположениями: Q02 уже согласован в ADR-0035.
Хранение Q36 согласовано; бюджет после ручного повтора остаётся до T12.
Q03 — медиапрофили и форматы (B10/B14–B18), Q05 — защищённая доставка
(B22), Q08 — пагинация и ограничения выборок (B06/B24/B25/B30/B33).
Они закрываются перед зависимой технической реализацией. Значения, не заданные
в ТЗ, здесь не придумываются; название/описание согласованы в ADR-0037,
параметры повторов — в ADR-0035.
