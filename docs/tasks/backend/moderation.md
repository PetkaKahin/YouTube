## B32. Отправлять и обновлять жалобу

**Описание.** Вошедший зритель сообщает о проблеме с доступным ему видео.

**Требования.** Причина выбирается из согласованного списка: спам/мошенничество,
оскорбления/травля, насилие, сексуальный контент, авторские права, другое.
Для пары «пользователь, видео» одна жалоба. Повтор обновляет причину/время в той
же записи; рассмотренная жалоба снова ожидает рассмотрения, ожидающая остаётся
одним обращением. Повтор не меняет скрытие видео и не создаёт санкцию автоматически.
Автор видео и обычные зрители не получают сведения об отправителе.

**Приёмка.** Проверены первая/повторная отправка, неизвестная причина,
повтор после решения, одновременные запросы, гость и недоступное видео.
Разные пользователи могут иметь отдельные жалобы; один не создаёт дубликатов.
Рост числа обращений не скрывает видео сам по себе и не раскрывает отправителей.

## B33. Предоставлять очередь и контекст модерации

**Описание.** Модератор/администратор получает ожидающие обращения и данные для рассмотрения.

**Требования.** Очередь и служебные сведения доступны только уполномоченным ролям.
Сохраняются инициатор, причина, состояние, решение и исполнитель; обычные
пользовательские ответы не раскрывают служебные данные. Повтор рассмотренной
жалобы возвращает то же обращение в ожидание; не возникает второй записи.

**Приёмка.** User/гость не читают очередь или отдельную служебную жалобу подменой ID.
После снятия полномочий старая сессия не сохраняет доступ. Повтор из B32 снова
виден как требующий решения; чужое старое решение не выдаётся за результат
рассмотрения обновлённого обращения.

## B34. Рассматривать жалобу и фиксировать решение

**Описание.** Сотрудник завершает рассмотрение отклонением жалобы либо скрытием видео с причиной.

**Требования.** Полномочия проверяются в момент действия; сохраняются решение,
исполнитель и основание. Скрытие исполняется согласованно с B35: сбой не должен
оставлять жалобу ложно завершённой при неприменённом решении. Повтор исполнения
не дублирует результат. Обновлённая после решения жалоба требует нового рассмотрения.

**Приёмка.** Проверены оба решения, отказ обычному пользователю, повтор,
одновременное рассмотрение/обновление жалобы и сбой при применении скрытия.
Отклонённая жалоба сама по себе не меняет видимость видео и не снимает уже
действующее скрытие. Апелляции и автоматические санкции не вводятся.

## B35. Скрывать видео на всех обычных путях доступа

**Описание.** Решение модерации прекращает обычную доступность видео.

**Требования.** Только moderator/admin с сохранением причины/инициатора.
Видео исключается из главной, поиска, канала и доступного состава плейлистов;
закрываются обычные прямые данные/превью/HLS/субтитры и комментарии.
Правило действует для владельца и ранее приглашённых. Переключение видимости,
правка метаданных, устаревший кэш и завершение обработки не отменяют скрытие.

**Приёмка.** Проверены все перечисленные пути, прямой сегмент, действующая
старая ссылка и скрытие одновременно с обработкой. Повтор скрытия не дублирует
результат; обычный автор не возвращает доступ собственным действием.
Удаление файлов/аккаунта и действие восстановления скрытого видео не добавляются.

## B36. Открывать служебный просмотр только для рассмотрения жалобы

**Описание.** Уполномоченный сотрудник получает доступ к материалу обращения,
когда это необходимо для модерации, включая приватное видео.

**Требования.** Отдельный серверный сценарий, связанный с рассмотрением жалобы,
с фиксацией исполнителя и основания. Роль сама по себе не открывает приватный
каталог и не разрешает произвольное видео в обычном плеере.
Исключение не выдаёт постоянного разрешения зрителю и не меняет приватность/скрытие.

**Приёмка.** Обычный пользователь не использует служебный просмотр; сотрудник
не получает исключение без основания рассмотрения. Проверены приватный материал,
попытка обойти обычный отказ через роль и снятые полномочия. Служебный доступ
зафиксирован, но не публикует данные или медиассылки в обычных выдачах.
