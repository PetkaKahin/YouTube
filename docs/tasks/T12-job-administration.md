# T12: ошибки и повтор фоновых заданий в админ-панели

Статус: `todo`, отложено пользователем до разработки админ-панели.
Явное дополнение R17 к ТЗ от 2026-11-13. Предпосылки: аккаунты/роль admin,
worker и журнал ошибок из T04, техническая основа фронтенда T09.

## Результат

Администратор видит сохранённые ошибки фоновых заданий и может одним действием
повторно запустить упавшие джобы. История должна собираться заранее при реализации
worker, чтобы панель могла работать с уже накопленными сбоями.

Правила хранятся в [диагностике фоновых заданий](../backend/background-jobs.md),
параметры worker — в [ADR-0035](../decisions/0035-worker-policy-and-job-errors.md).

## Границы

На текущем этапе ни панель, ни HTTP-маршруты перезапуска не реализованы.
Конкретные формы, состав списка/фильтров, выбор набора джоб, подтверждения
и пагинация согласуются перед зависимой реализацией. Настройки ролей через UI,
управление произвольными функциями и прочие разделы админки не добавляются.
Хранение Q36 согласовано в ADR-0036; остаётся бюджет автоматических попыток
после ручного запуска. Детали UI — в Q07.

## Приёмка будущей реализации

- Сохранённые ошибки видны после рестартов и повторов, в том числе если задание
  позднее завершилось успешно; диагностика не раскрывает секреты.
- Admin получает доступ, гость/user/moderator отклоняются сервером, включая прямые запросы.
- Повтор упавшей работы запускается из панели, ошибка запроса не выдаётся за успех.
  Двойное и конкурентное нажатие не создаёт независимые дубли.
- Прошлые ошибки и готовые медиа сохраняются; приватность, скрытие и технические
  лимиты не обходятся через повтор. Действие администратора прослеживается.

Эта карточка фиксирует запрошенную функцию, а не закрывает её реализацию.
