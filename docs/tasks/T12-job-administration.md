# T12: ошибки и повтор фоновых заданий в админ-панели

Статус T12: `done`; серверная часть и интерфейс реализованы.
Панель, маршруты и браузерные проверки — [фронтенд T12](../frontend/job-administration.md).
Явное дополнение R17 к ТЗ от 2026-11-13. Предпосылки: аккаунты/роль admin,
worker и журнал ошибок из T04. T09 требуется только для интерфейса.

## Результат

Администратор видит сохранённые ошибки фоновых заданий и может одним действием
повторно запустить упавшие джобы. История должна собираться заранее при реализации
worker, чтобы панель могла работать с уже накопленными сбоями.

Правила хранятся в [диагностике фоновых заданий](../backend/background-jobs.md),
параметры worker — в [ADR-0035](../decisions/0035-worker-policy-and-job-errors.md).

## Границы

Реализованы HTTP-маршруты истории и повторов —
[контракт](../backend/job-administration.md). Интерфейс подключён: таблица,
галочки по заданиям, три режима повтора, подтверждение и результат.
Компоновка согласована пользователем. Пагинация — cursor по 20;
история новыми сверху, без фильтров. Настройки ролей через UI,
управление произвольными функциями и прочие разделы админки не добавляются.
Q36 закрыт: хранение принято в ADR-0036; ручной повтор заново ставит работу
в очередь с обычным циклом — до трёх запусков для временных ошибок, паузы
30 секунд и 2 минуты по ADR-0035. История ошибок сохраняется.
Согласованы все режимы ручного повтора: одна джоба, выбранный список и все
упавшие. Запросы могут пересекаться: например, выбранные, затем через секунду
все. Такие запросы не создают независимые дубли одной незавершённой работы.
Параметр порций задаётся через `.env` под железо, начальное значение — 20;
это число джоб в одной порции. Предложенные фиксированные пороги
100 заданий и интервал 15 секунд не приняты.
История ошибок — новые сверху, без фильтров. Q46 закрыт.
Контракт и техническое решение — [ADR-0062](../decisions/0062-job-administration.md).
Детали UI — в Q07.

## Приёмка

- Сохранённые ошибки видны после рестартов и повторов, в том числе если задание
  позднее завершилось успешно; диагностика не раскрывает секреты.
- Admin получает доступ, гость/user/moderator отклоняются сервером, включая прямые запросы.
- Повтор упавшей работы запускается из панели, ошибка запроса не выдаётся за успех.
  Двойное и конкурентное нажатие не создаёт независимые дубли.
- Прошлые ошибки и готовые медиа сохраняются; приватность, скрытие и технические
  лимиты не обходятся через повтор. Действие администратора прослеживается.

## Результат серверной части

Миграция 0024 добавляет постоянные намерения, аудит результатов и индекс истории.
Все три режима, пересечения запросов, свежая роль admin, отмена остатка после
снятия роли, полный новый цикл попыток и безопасное восстановление Video подключены.
`JOB_RETRY_BATCH_SIZE=20` добавлен в `.env.example`, текущий `.env`, Compose/Settings.
Новых библиотек и секретов нет; UI и произвольные команды не добавлялись.

Финальный профильный набор — **37 passed**. Он включает отдельный новый процесс
для продолжения намерения, исчерпание старого бюджета и новый цикл из трёх запусков,
атомарный rollback, работающий реальный inspector/encoder, native pruning,
порции/занятую очередь, защиту от дублей и диагностику без kwargs/секретов.
Ранее выполненный полный pytest дал **1578 passed**; он предшествовал финальной
правке приоритетов и повторно не запускался. Для отдельной задачи используются
только профильные проверки по обновлённому скиллу backend.

Production-образы собраны штатным Dockerfile. `docker/check_delivery prod`
прошёл после финальной сборки: реальные Nginx/API/RustFS, admin/CSRF,
выбранные → все, новый native ID/сохранённый приоритет, общий готовый пакет
после удаления оригинала, hidden и история. Отдельный production media-worker
прошёл тот же повтор при принудительном отказе Valkey. Временные БД, объекты
и сессии квалификации удалены; dev-аудит секретов не повторялся по просьбе пользователя.

Миграция 0024 применена, Alembic check прошёл. Финальные Basedpyright и
Tach/check-external прошли. Дальнейшие изменения документации не требуют
повтора проверок реализации по обновлённым проектным скиллам.
Dev-сервисы API, media-worker и upload-maintenance пересозданы с изменениями T12.
Относительные файловые ссылки в затронутых документах проверены.
