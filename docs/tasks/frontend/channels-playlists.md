# Канал, подписка и плейлисты

F18–F21 — `done` по функциональным профилям. Источники: [Channel](../../backend/modules/channel.md),
[экраны](../../frontend/screens.md), [соответствие YouTube](../../frontend/youtube-parity.md).
Зависимости и общая приёмка — [реестр](README.md).

Первая реализация: профиль, две вкладки с публичными списками и раскрытие
состава плейлиста на канале. Подписка переиспользуется с просмотра. Прямой
`/playlist?list=<id>` подключён по обновлённому контракту Q49.
F21 завершён по функциональному профилю — [Studio](../../frontend/studio.md).
Код, референсы, проверки и ограничения — [покрытие](../../frontend/channel-playlists.md).

## F18. Показывать канал автора

**Описание.** Посетитель открывает канал и его публичное содержимое.

**Требования.** Композиция, навигация по видео/плейлистам, карточки и пустое состояние
следуют F01. Имя отображается названием канала, тег идентифицирует автора.
Публичная часть не показывает private-видео даже приглашённому, hidden/черновики/
неготовое исключаются. В списке плейлистов только public; личное управление — F21/F26.
Переходы ведут к нужным видео и содержимому плейлиста.

**Приёмка.** Проверены пустой канал после регистрации, наполненный канал,
гость/владелец, совпадающие имена и разные теги. Нет закрытого содержимого
или лишних разделов оформления/студии. На телефоне все предусмотренные действия достижимы.

В Chromium и Firefox прошли по 49 проверок. Исправлены запросы до подтверждения
сессии, сохранение отключённых списков между вкладками и зависимость запроса
от изменившегося тега/профиля. Проверены cursor, ошибки, пустые/наполненные
каналы, новая регистрация, роли, одинаковые имена и Back после отзыва публичности.
Переходы к видео/составу и клавиатура телефона сохранены;
[результаты и ограничения](../../frontend/channel-page.md). Бэкенд не менялся.

## F19. Подписываться и отменять подписку

**Описание.** Вошедший посетитель меняет состояние подписки на чужого автора.

Серверный [контракт B07](../../backend/subscriptions.md) реализован.
F19 завершён по [функциональному профилю](../../frontend/subscriptions.md):
в Chromium и Firefox прошли по 38 проверок канала и просмотра. Исправлены гонка
GET/PUT, старая действующая кнопка после отказа чтения, потеря фокуса и обработка
поздних ответов. После перехода новая точка интерфейса ждёт свежий GET.
Проверены быстрые клики, ошибки/повтор, гостевой возврат, self, смена личности,
одинаковые имена и независимость private-приглашения. Бэкенд не менялся;
визуальная приёмка остаётся у пользователя.

**Требования.** Кнопка и переходы между состояниями соответствуют F01,
фактическое состояние подтверждает B07. Собственный канал не предлагает подписку,
гость направляется ко входу. Ошибка не сохраняет ложную подписку.
Уведомления/колокольчик и отдельная лента подписок не входят в ТЗ.

**Приёмка.** Проверены установка/отмена, быстрые нажатия, ошибка и переход
между каналами до ответа. Состояние согласовано в доступных местах интерфейса,
подписка не открывает private-видео и не меняет его карточки на публичные.

## F20. Читать состав плейлиста и переходить к видео

**Описание.** Посетитель открывает разрешённый плейлист и выбранное видео.

**Требования.** Состав отображается на канале с переходом к существующему просмотру
по согласованному референсу; дополнительный экран вне согласованного состава
не вводится. Порядок — включение видео, новые в конец. Public доступен всем,
unlisted открывается по ссылке гостю без обнаружения на канале/в поиске,
private — только владельцу. Права на каждое видео отдельные.

**Приёмка.** Проверены три режима, прямые ссылки, пустой список и смесь
доступных/недоступных видео. Закрытые названия/превью/медиа не раскрываются
через разрешённый плейлист. Переход не обходит B20/B21; ручной перестановки нет.

В Chromium и Firefox прошли по 55 проверок F20. Состав и resolver используют
контекст своего query key, новый экземпляр ждёт свежий ответ, отмену/удаление
при уходе выполняет Query. Ошибка сессии прямой ссылки отделена от гостя;
отказ состава очищает данные и заголовок без запроса отключённого каталога.
Проверены cursor, три режима, пустые списки, повторное включение, ошибки/повторы,
поздние ответы, независимый отзыв доступа и переходы на телефоне;
[результаты и ограничения](../../frontend/playlist-contents.md). Бэкенд не менялся.
Затронутый F18 повторно прошёл по 49 проверок в Chromium и Firefox.

## F21. Создавать плейлист и видеть свои плейлисты

**Описание.** Вошедший автор создаёт плейлист для своего канала.

**Требования.** Обязательное название, необязательное описание, public/unlisted/private.
Форма, её место открытия и поведение согласуются в F01/Q07 в визуальном языке YouTube.
Личный список выбран по предоставленному референсу Studio:
«Контент на канале» → «Плейлисты», таблица —
[ADR-0066](../../decisions/0066-studio-playlist-interface.md).
Меню «Создать» → «Создать плейлист» открывает модалку; исходный доступ — public,
по дополнительным снимкам пользователя. F21 подключён к API и проверен
функционально; визуальную приёмку выполняет пользователь по ADR-0068.
Свой список включает все три режима; отсутствие плейлистов — отдельное пустое состояние.
Нет выбора приглашённых по email. Успех создания показывается только после B26.

**Приёмка.** Проверены пустое/пробельное название, пустое описание, режимы,
отправка/ошибка/повтор. Новый плейлист доступен автору для выбора F28 и имеет
подтверждённую видимость. Несохранённая форма не выдаётся за созданный объект,
создание не меняет приватность видео.

В Chromium и Firefox прошли по 56 проверок. Исправлены скрытая ошибка фонового
списка, синхронная блокировка submit, привязка ответов к ревизии формы,
позднее close и снятие ошибки при изменении поля. Query удаляет неактивный
список без отложенного удаления нового экземпляра; URL открытия формы проверяет
маршрут/область после ожидания. Проверены реальные границы/права/ошибки, cursor,
смена личности и компактное создание из выбора видео без изменения настроек.
[Результаты и ограничения](../../frontend/studio.md). Бэкенд не менялся.
