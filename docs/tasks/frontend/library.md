# R19: личные разделы и sidebar

Статус: `done` по функциональному профилю, согласовано пользователем 2026-11-18.
Источники: [ТЗ R19](../../project/requirements.md), [контракт API](../../frontend/library-backend-request.md),
[референсы](../../frontend/references.md#личные-разделы-r19--2026-11-18).

## Результат

Подключены `/feed/subscriptions`, `/feed/history`, `/feed/liked`, `/feed/playlists`
в обычной оболочке. «Подписки» используют ту же сетку, что главная, и имеют
отдельное раскрытие списка каналов в sidebar. История упорядочена по последнему
просмотру, понравившиеся — по времени текущего лайка, плейлисты — собственные.
В рамках R19 создание/редактирование контента размещено в Studio; дополнение
[R20](watch-enhancements.md) отдельно добавляет быстрое создание из закладки watch.

SDK сгенерирован из готового OpenAPI. Списки принадлежат Query и используют
серверные cursor по 20, точные int64 и проверку сессии. После лайка/подписки/
прогресса затронутые выдачи обновляются; позднее подтверждение команды после
ухода со страницы также обновляет уже открытый личный список прежнего зрителя.
При смене аккаунта/401/отказе прав прежние данные не остаются в интерфейсе.

## Приёмка

Chromium и Firefox прошли по **47 проверок** R19: гостевой вход с возвратом,
пустые/ошибочные ответы, продолжение/повтор, реальные страницы 20/20/1 и 20/20/5,
семь/двадцать/двадцать два канала, переходы и активный пункт, безопасный текст,
прогресс и хронология, поздние команды/чтения, private/отзыв/401, фокус и телефон.
Это также приёмка правил F33 на новых выдачах.

Регрессия обоих браузеров: F09 — по 20, F15 — по 36, F19 — по 38,
R18 progress — по 33 проверки. Генерация SDK, сборка/типы, ESLint/Prettier,
синтаксис профиля, ссылки документов и git diff --check прошли в Docker.
Внешний вид проверяет пользователь; снимки/визуальное сравнение не выполнялись.
Бэкенд приложения, контракт и библиотеки не менялись.
[Код, повтор и ограничения](../../frontend/library.md).

Не добавлены очистка/удаление истории, уведомления, Shorts, перемешивание,
новые виды плейлистов и недостоверные счётчики. Обложек в DTO плейлистов нет —
используются общие нейтральные карточки без запросов состава каждого элемента.
Safari/WebKit и физический телефон не квалифицированы; полный make check
остаётся до завершения общего плана F01–F04.
