# Жалобы и служебная модерация

Все задачи — `todo`. Источники: [Moderation](../../backend/modules/moderation.md),
[экраны](../../frontend/screens.md), [границы соответствия](../../frontend/youtube-parity.md).
Зависимости и общая приёмка — [реестр](README.md).

## F29. Отправлять жалобу на доступное видео

**Описание.** Вошедший зритель выбирает причину жалобы из действия на экране просмотра.

**Требования.** Открытие, выбор, подтверждение и закрытие формы соответствуют F01.
Причины — спам/мошенничество, оскорбления/травля, насилие, сексуальный контент,
авторские права, другое. Успех означает принятую жалобу, не скрытое видео.
Повтор обновляет ту же запись, рассмотренная снова попадает в ожидание.
Гостю нужен вход, недоступное видео не раскрывается через форму.

**Приёмка.** Проверены причины, отсутствие выбора, отправка/ошибка/повтор,
гость и закрытие формы с восстановлением фокуса. Сообщение соответствует B32,
автор/другие зрители не видят отправителя жалобы. Массовое число жалоб
не изображается как автоматическая санкция.

## F30. Показывать служебную очередь жалоб

**Описание.** Модератор/администратор видит обращения, требующие рассмотрения.

**Требования.** Экран доступен по серверным полномочиям, включая прямой URL.
Композиция согласуется как проектная адаптация стиля YouTube; не заявляется
копирование неизвестного внутреннего интерфейса. Очередь, пустое состояние,
загрузка и ошибка отражают B33. Отправитель/служебные данные не показываются
в обычных пользовательских экранах. UI назначения ролей отсутствует.

**Приёмка.** User/гость не получают очередь даже кратко перед отказом.
После снятия роли доступ прекращается. Повторно отправленная рассмотренная
жалоба снова видна как ожидающая, без второго обращения. Порядок/пагинация
не придумываются до Q08 и контракта; переход открывает правильное обращение.

## F31. Открывать контекст жалобы и служебный просмотр

**Описание.** Сотрудник получает материал для решения по выбранной жалобе.

**Требования.** Контекст загружается через служебный сценарий B36 с основанием
рассмотрения; обычный плеер не обходит права по одной роли.
Интерфейс различает служебное и обычное открытие, не создаёт постоянного
приватного разрешения и не публикует ссылки/данные в обычные списки.
Воспроизведение использует предусмотренные F13 возможности.

**Приёмка.** Проверены приватный материал по жалобе, несуществующее основание,
отказ/снятие роли, переключение между обращениями и ошибки потока.
Данные предыдущего обращения не показываются в новом. Служебная возможность
не превращается в каталог произвольных чужих приватных видео.

## F32. Принять решение по жалобе

**Описание.** Сотрудник отклоняет жалобу либо скрывает видео с причиной.

**Требования.** Форма, подтверждение, ожидание и результат согласуются F01;
сервер B34/B35 подтверждает окончательное состояние.
Ошибка применения скрытия не выдаётся за завершённое решение.
Повтор и обновление жалобы учитывают актуальное состояние, без ложного
показа старого решения как результата нового обращения.

**Приёмка.** Проверены оба решения, причина скрытия, повтор нажатия, отказ
сервера, снятие роли и обновлённая жалоба. Очередь/контекст показывают реальный
результат; скрытое видео недоступно в обычных сценариях после соответствующего
серверного обновления. Апелляции, восстановление скрытого видео, страйки,
блокировки аккаунтов и отдельная модерация комментариев не добавляются.
