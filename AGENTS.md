# YouTube — инструкции для Codex

Учебная копия YouTube. Выполняй только объём [ТЗ](docs/project/requirements.md).
Текущее состояние и навигация: [docs/README.md](docs/README.md).

## Сначала вопросы

Сначала проверь документы и уже полученные ответы; не спрашивай повторно.
Если по текущей задаче остались неразрешённые вопросы, задай их пользователю
и сразу останови всю работу над текущей задачей до получения ответа.
После вопроса не продолжай даже независимые части задачи, не редактируй файлы
и не запускай проверки. Передай ход пользователю. Таймаут, молчание и собственное
предположение не заменяют ответ; если нужны уточнения, снова спроси и остановись.
Открытые решения: [docs/tasks/open-questions.md](docs/tasks/open-questions.md).
Само наличие записей в списке не блокирует другие задачи; заданный пользователю
вопрос по текущей задаче останавливает её целиком до ответа.
Если ответ порождает новые вопросы, фиксируй их в этом списке и также разбирай
с пользователем. Обсуждай вопросы небольшими связанными порциями, а не все сразу.
Бизнес-правила текущего разбора согласованы; Docker и техническая основа бэкенда
подготовлены. Реализованы аккаунты, регистрация с пустым каналом и HTTP-сессии;
текущее покрытие бизнес-сценариев — в реестре задач бэкенда.
Остальные библиотеки и параметры выбираются перед зависимой реализацией.
Расположение элементов, формы, референсы и другие детали UI обсуждаются
в ходе разработки интерфейса. Уже согласованные требования к UI сохраняются.

## Проектные скиллы

Перед соответствующей работой прочитай указанный `SKILL.md` и следуй ему:

| Область | Скилл |
| --- | --- |
| Бэкенд, API, видео, хранилища, фоновые задачи | [backend](skills/backend/SKILL.md) |
| Фронтенд, FSD, экраны, клиент API | [frontend](skills/frontend/SKILL.md) |
| Документация, решения, архитектурные записи, задачи | [docs](skills/docs/SKILL.md) |

При изменении нескольких областей загружай соответствующие скиллы по мере работы.
Не читай все документы заранее: используй индексы и ссылки нужного модуля.

Скиллы хранятся в `skills/`, поскольку `.agents/` в текущей среде доступна только
для чтения. Этот файл обеспечивает их применение в репозитории. Это не установка
в стандартный каталог автоматического обнаружения `.agents/skills/`.

## Постоянные ограничения

- Для всех списков соблюдай [единое решение о пагинации](docs/decisions/0059-list-cursors-and-channel-order.md);
  не спрашивай повторно о cursor и размере порции.
- Объём и порядок проверок соблюдай по проектным скиллам:
  [backend](skills/backend/SKILL.md#проверки),
  [frontend](skills/frontend/SKILL.md#проверки), [docs](skills/docs/SKILL.md#проверки).
- Длительный прогон тестов запускай один раз и ожидай его завершения.
  Не проверяй многократно статус или хвост лога и не отправляй сообщения
  о процентах выполнения. Промежуточная диагностика нужна только при конкретном
  признаке сбоя или зависания, а не по таймеру.
- В отчётах и документации фиксируй результат проверок без времени прогона.
  Длительность указывай только по отдельному запросу или при разборе производительности.

- Бэкенд: модульный монолит, clean architecture внутри модулей, взаимодействие через `public`.
  Техническое исключение: явный реестр DI импортирует только классы провайдеров
  из infrastructure модулей — [ADR-0027](docs/decisions/0027-explicit-module-providers.md).
- Фронтенд: Vue 3 + TypeScript, FSD, ПК и мобильный веб, пока только тёмная тема.
- Разработка, проверки, сборка и запуск приложения — через Docker. `dev` и `prod` наследуются от `base`.
- PostgreSQL хранит постоянные данные; RustFS — медиа; Valkey — кэш и сессии.
- Секреты конфигурации (пароли сервисов, API-токены, ключи) передавай только
  через Compose Secrets и файлы `/run/secrets/`; environment и `.env` содержат
  несекретные значения и пути `*_FILE`.
- Функции, отсутствующие в ТЗ, требуют отдельного запроса пользователя.
- Обновляй затронутые документы вместе с реализацией; отличай план от работающего поведения.
- Помимо правильного поведения проверяй безопасность, утечки, инъекции,
  лимиты и сбои по [правилам тестирования](docs/testing.md).
- Каждый коммит, включая amend, требует явного согласия пользователя;
  [порядок согласования](docs/README.md#согласование-коммитов).
